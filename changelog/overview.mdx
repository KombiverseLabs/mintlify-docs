## SpeechKit Meeting Mode and network privacy scopes, StackKits Smart Home and Media

SpeechKit rolled from [v0.65.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.65.0) to [v0.68.24](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.24): a full Meeting Mode with reviews in six languages, a privacy setting that draws a hard network boundary, and in-meeting screenshots that never leave the device. StackKits shipped [v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) through [v0.24.27](https://github.com/kombifyio/stackKits/releases/tag/v0.24.27): Smart Home and Media use cases, a browser-based planner at stackkit.cc/planner, and module-local compute profiles.

### New features

- **Meeting Mode is a first-class mode.** [SpeechKit v0.67.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.67.0) puts Meeting Mode beside Dictation, Assist, and Voice Agent, with its own settings for capture, review generation, languages, and retention. A compact transparent overlay shows capture health and controls during the call, rolling summaries run without blocking capture, and finishing a meeting produces a durable Meeting Review, a five-sentence Executive Brief, and action items in English, German, Spanish, Chinese, Hindi, and Arabic. GitHub Copilot is an optional review-generation provider behind a separate, revocable transcript-processing grant; the local path needs no cloud credentials. See [SpeechKit modes](/speechkit/modes).
- **Pick a network boundary and SpeechKit enforces it.** [v0.67.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.67.0) adds a Network Scope setting: all networks, local network only, or this device only. The backend enforces the boundary for speech providers, model downloads, updates, telemetry, server connections, and integrations. Switching to a stricter scope suspends incompatible settings instead of deleting them, and Settings explains what is disabled and why. See [SpeechKit overview](/speechkit/overview).
- **Screenshots inside a meeting, kept on your machine.** [v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) captures a chosen window or the monitor under the cursor with a configurable `Ctrl+Alt+S` shortcut. Snapshots appear as markers in the transcript timeline, are cited in generated Meeting Reviews, and the compact meeting pill briefly unfolds a preview so you know the right window was captured. No image ever leaves the device.
- **Find and export any meeting.** The [v0.68 patch releases](https://github.com/kombifyio/SpeechKit/releases) group the meeting list by when a meeting happened, add search across titles, transcripts, notes, and write-ups, render notes as formatted Markdown, and add Copy Markdown and Save .md for the complete write-up.
- **Smart Home use case in StackKits.** [StackKits v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) adds a Home Assistant workload on Basement, Cloud, and Modern kits. Generate writes the reverse-proxy baseline and a native MCP client fragment, and setup creates the Homelab owner account. See [Use cases](/guides/stackkits/use-cases/overview).
- **Media use case with Jellyfin.** [v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) adds a Jellyfin workload on the `standard` and `high` compute tiers. The media library stays owner-custodied and is deliberately not a StackKits backup source. See [Jellyfin](/stackkits/apps/jellyfin).
- **Plan a homelab in the browser.** [v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) launches the StackKits planner at stackkit.cc/planner: read-only, schema-first tools over the public catalog that hand off a `init → validate → resolve → generate → plan` sequence to the CLI. Apply remains an explicit step on your machine. See [MCP connector](/stackkits/reference/mcp-connector).
- **Sign in to kombify Cloud from the app.** [SpeechKit v0.67.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.67.0) adds a Connect button that opens the kombify sign-in page in your browser, shows a code to confirm, and points the device at the hosted service. Your password never enters the app, and the session lives in the operating system's credential store.

### Updates

- **Meetings finish on their own.** [SpeechKit v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) stops a recording shortly after the calling app releases the microphone, and a notification says when the Meeting Review is ready or why it failed. Hand-started recordings are never auto-stopped.
- **Module-local compute profiles in StackKits.** [v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) through [v0.24.27](https://github.com/kombifyio/stackKits/releases/tag/v0.24.27) move compute, storage, and accelerator profiles onto each module with per-workload alternatives. Required host facts must be observed in inventory before Apply, not inferred from declared hardware. See [Choosing a kit](/guides/stackkits/choosing-a-kit).
- **The low tier gets real lite variants.** [v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) makes a Basement `low` generate emit standalone Compose variants: core without Coolify and Immich without machine learning. Media is omitted on `low` until a lite substitute exists, and fails closed at init instead of deploying something undersized.
- **Integrations show their maturity.** [SpeechKit v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) marks each integration in Settings as Ready, Partial, Planned, or Unavailable, with per-mode tags. What this build cannot run is greyed out instead of failing when enabled.
- **A leaner SpeechKit SDK.** [v0.65.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.65.0) removes the provider names deprecated in v0.64.0, so a Deepgram-only app compiles 49 external packages instead of 286. [v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) splits the root package into contracts and implementations with a mechanical import rewrite. [v0.66.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.66.0) publishes all five Android modules as Apache-2.0 artifacts on JitPack, resolvable anonymously. See [SpeechKit framework](/speechkit/framework).
- **The overlay settings are a designer.** The [v0.68 patch releases](https://github.com/kombifyio/SpeechKit/releases) redraw General settings as compact cards and preview the overlay live: style, position, and the quick buttons on the hover strip update in the preview at once.

### Bug fixes

- **Nothing fails quietly anymore.** [SpeechKit v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) reports dropped Voice Agent speech, overlay placement failures, silent screenshot errors, and stalled meeting summaries in the activity log with a reason instead of leaving you guessing.
- **Meeting audio stays out of dictation.** [v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) runs meeting transcription on its own pipeline. Call audio no longer flashes the dictation overlay, fills the dictation history, or becomes the "last transcription" that the copy and insert shortcuts reuse.
- **Long meetings produce write-ups.** The [v0.68 patch releases](https://github.com/kombifyio/SpeechKit/releases) size summary batches for the bundled local model, split overlong transcript pieces at sentence boundaries, resume write-ups interrupted by a restart, and retry a temporarily unreachable local model instead of failing the review for good.
- **Local dictation starts on non-ASCII install paths.** [v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) fixes the bundled whisper-server failing on a fresh install when the model path contains an umlaut. If local speech-to-text still cannot start, the activity log names the cause and says whether dictation is offline or falling back to a named cloud provider.
- **Multi-language reviews run one after another.** [v0.68.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.68.0) stops parallel review runs from starving the local model and missing their deadlines together, and progress follows the language actually running instead of a queued job stuck at 0%.
- **The dashboard opens at a size that fits.** The [v0.68 patch releases](https://github.com/kombifyio/SpeechKit/releases) stop the window from opening taller than a scaled laptop screen, keep the minimum size within a 13-inch display, and preserve a size you choose.
- **The Connect button tells the truth.** [v0.67.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.67.0) fixes the hosted connection claiming to be ready without ever obtaining a credential, and the Android app now says when a Companion pairing fails because the two installed apps do not match, instead of showing a general failure.
- **StackKits release archives carry their own docs.** [v0.24.2](https://github.com/kombifyio/stackKits/releases/tag/v0.24.2) includes the public backup and application-readiness documentation in release archives and keeps the guided Basement and Cloud recipes explicit through the compatibility adapter.

</Update>

## SpeechKit meeting notes and LAN discovery, StackKits public addresses and compute tiers

SpeechKit rolled from [v0.59.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.59.0) to [v0.64.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.64.0): meeting notes that start from what you wrote down, LAN discovery so devices find your homelab server without typing an address, and tap-to-interrupt on every client. StackKits shipped [v0.21.10](https://github.com/kombifyio/stackKits/releases/tag/v0.21.10) through [v0.22.0](https://github.com/kombifyio/stackKits/releases/tag/v0.22.0): managed public service addresses with automatic TLS on Cloud Kit, and compute tiers that match a kit to the hardware you actually have.

### New features

- **Meeting notes that start from your own notes.** [SpeechKit v0.59.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.59.0) adds a meeting notepad: your notes lead, the transcript fills in the rest, and the write-up cites the words it came from. Microphone and system audio stay on separate tracks, so speaker labels come for free and the audio is never kept. SpeechKit notices when a calling app takes the microphone and offers to take notes; nothing is recorded until you accept. The write-up lands in the dashboard as soon as the meeting ends. See [SpeechKit modes](/speechkit/modes).
- **Find your SpeechKit server on the home network.** [v0.60.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.60.0) lets a homelab server announce itself over mDNS/DNS-SD, so the desktop app, the Android app, and `speechkitctl discover` find it without typing an address. Discovery is opt-in and off by default, so a hosted instance stays silent, and the announcement only says where to knock: devices still sign in after they connect. See [SpeechKit overview](/speechkit/overview).
- **Managed public addresses with automatic TLS on Cloud Kit.** [StackKits v0.21.20](https://github.com/kombifyio/stackKits/releases/tag/v0.21.20) through [v0.21.24](https://github.com/kombifyio/stackKits/releases/tag/v0.21.24) give Cloud Kit services managed public kombify.me addresses: a secret-free address plan, routes rendered from your validated subdomain prefix, and certificates issued with ACME HTTP-01 so the Cloudflare gateway can validate origin TLS while service traffic stays HTTPS. See [Cloud Kit](/stackkits/kits/cloud-kit).
- **Compute tiers match the kit to your hardware.** [StackKits v0.22.0](https://github.com/kombifyio/stackKits/releases/tag/v0.22.0) adds `low`, `standard`, and `high` compute tiers per kit. Apply attests local CPU, RAM, and disk before resolving, and blocks with a clear reason instead of deploying onto an undersized host. See [Choosing a kit](/guides/stackkits/choosing-a-kit) and [Review, plan, and apply](/guides/stackkits/review-plan-and-apply).
- **Interrupt the assistant from any client.** [SpeechKit v0.62.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.62.0) brings tap-to-stop for a spoken answer to the web and Android clients, not only the desktop app. Transcripts on web and Android carry speaker labels when speaker recognition is on, and each client shows which speech backend is serving the session. See [SpeechKit modes](/speechkit/modes).
- **Voice-note transcription and summaries on Android.** [v0.60.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.60.0) transcribes voice notes and summarizes WhatsApp and Telegram voice messages from the SpeechKit app.
- **Add secrets custody to an existing homelab.** [StackKits v0.21.11](https://github.com/kombifyio/stackKits/releases/tag/v0.21.11) adds an explicit, idempotent `stackkit secrets materialize` command so a standalone homelab can establish owner-bound custody after selecting a new workload, without re-running its initial StackSpec. See [Day 2 operations](/stackkits/reference/day-2-operations).

### Updates

- **Words and Replacements are manageable.** [SpeechKit v0.62.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.62.0) makes custom Words and Replacements searchable, paged, and deletable in Settings. Several spoken forms can rewrite to one term, and aliases apply in Dictation, Assist, and Voice Agent.
- **Pick your dictation engine in one control.** [v0.62.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.62.0) switches Deepgram Nova-3 and AssemblyAI Universal 3.5 in one Dictation setting, and AssemblyAI's LLM Gateway is a native backend using the same API key as speech-to-text.
- **The overlay is the control strip.** [v0.59.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.59.0) lets you choose which actions sit on the Windows overlay, rotate the speech language, and start a meeting from it. See [SpeechKit framework](/speechkit/framework).
- **One Go package per speech provider.** [v0.64.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.64.0) splits every speech and realtime voice provider into its own SDK package, so an app that talks to one backend stops compiling the rest. Old names still work through v0.64 with a migration table and are removed in v0.65.0. The model catalog is now single-sourced, and entries carry a `modality` field.
- **Owner-approved removal targets one node.** [StackKits v0.21.11](https://github.com/kombifyio/stackKits/releases/tag/v0.21.11) through [v0.21.13](https://github.com/kombifyio/stackKits/releases/tag/v0.21.13) let owner-approved workload removal select one exact node placement from a verified multi-node Apply result, with absence evidence still correlated to the same Apply.
- **Richer access manifest.** [v0.21.16](https://github.com/kombifyio/stackKits/releases/tag/v0.21.16) extends the native access manifest to v3 with application grouping, display names, lifecycle impact, and secret-free internal addresses for running services.

### Bug fixes

- **Cloud hardening can no longer lock you out.** [StackKits v0.21.10](https://github.com/kombifyio/stackKits/releases/tag/v0.21.10) preserves a non-root key-authenticated account before Cloud host-security disables root login, and [v0.21.17](https://github.com/kombifyio/stackKits/releases/tag/v0.21.17) makes the hardened sshd policy win over provider and cloud-init defaults, so root key login stays disabled.
- **Re-running Apply on ports 80 and 443 is safe.** [v0.21.18](https://github.com/kombifyio/stackKits/releases/tag/v0.21.18) lets an idempotent Apply reuse ports 80 and 443 only when Docker proves they belong to the current workspace's Cloud core. Foreign or stale listeners still block.
- **Workloads without a placement block just work.** [v0.21.11](https://github.com/kombifyio/stackKits/releases/tag/v0.21.11) applies the governed placement defaults when a StackSpec author selects a workload without a `placement` block. See [Configure a stack spec](/guides/stackkits/configure-stack-spec).
- **A failed Apply tells you what to do next.** [v0.22.0](https://github.com/kombifyio/stackKits/releases/tag/v0.22.0) ends a failed Product Apply with retry, `status`, and `logs` guidance plus the Run-ID, and the installers resume an existing workspace instead of dying.
- **A refused voice session explains itself.** [SpeechKit v0.62.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.62.0) makes a refused Voice Agent session name the one thing to change, and every error carries the id support needs to find the request.
- **Spoken numbers come out as digits.** [v0.61.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.61.0) writes spoken numbers as digits and strips German filler words like äh and ähm, including when the language is set to all languages.
- **The assistant stops interrupting itself.** [v0.61.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.61.0) rejects the agent's own voice as barge-in, stops a hung provider close from leaving a session stuck ending, and plays the reply at the correct 24 kHz rate.
- **Windows shows the real version after an update.** [v0.61.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.61.0) makes Install and restart display the published version instead of the previous one.
- **Full-capture Dictation respects your engine choice.** [v0.62.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.62.0) uses the selected speech engine instead of always trying Deepgram first.
- **The keyboard behaves on Android.** [v0.60.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.60.0) puts SpeechKit on the Gboard suggestion strip and restores the provider buttons on the keyboard, and [v0.61.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.61.0) keeps a tester connection working until you explicitly switch to a hosted connection.

## Techstack open-source Alpha, SpeechKit on the Android keyboard, StackKits Cloud core

Techstack is now public: an unsigned Windows Alpha and an open-source client you can install on your own machine to operate a local server without a hosted kombify account. SpeechKit ships its own Android keyboard so dictation and the Voice Agent are one tap above the keys, with a choice of on-device, SpeechKit server, Deepgram, AssemblyAI, or GPT. StackKits [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) rounds out ten first-class use cases and lands the provider-neutral Cloud core runtime, followed by a series of Cloud Apply and Verify fixes through [v0.21.9](https://github.com/kombifyio/stackKits/releases/tag/v0.21.9).

### New features

- **Techstack Windows Alpha, open source.** The Techstack open-core client is now published under AGPL-3.0 at [kombifyio/TechStack](https://github.com/kombifyio/TechStack), and the unsigned Windows Alpha is available for local-server feedback. Techstack is the optional orchestration and operator experience on top of StackKits, and this Alpha supports the account-free local path. See [Techstack overview](/techstack/overview), [availability](/techstack/availability), and [Install Techstack Alpha on Windows](/techstack/install-windows).
- **Dictation and Voice Agent, one tap above the keys.** [SpeechKit v0.58.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.58.0) adds a row above the Android keyboard to dictate on device or through your SpeechKit server, or talk to Deepgram, AssemblyAI, or GPT. Actions that need a server say so instead of failing when pressed. See [SpeechKit modes](/speechkit/modes).
- **SpeechKit ships its own Android keyboard.** [v0.57.1](https://github.com/kombifyio/SpeechKit/releases/tag/v0.57.1) replaces the borrowed IME with a SpeechKit-branded keyboard (a HeliBoard fork). Tap the voice key and the dictation panel opens inside the keyboard, where you were typing, without an app switch or a lost cursor. The complete corresponding source is published alongside the release.
- **Ten first-class use cases in StackKits.** [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) completes the CUE authorities for all ten use cases, including Vault, Media, and draft AI/Dev/Remote, plus post-1.0 draft Mail and Game. - **Provider-neutral Cloud core runtime.** [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) implements the provider-neutral Cloud core runtime with a guarded local Product Apply, live Verify observation, and the exact access-manifest v2 projection for `base`, `auth`, `id`, and `coolify`. Provider and credential custody stay in Techstack. See [Cloud Kit](/stackkits/kits/cloud-kit).
- **Configure a SpeechKit mode before you turn it on.** [v0.57.1](https://github.com/kombifyio/SpeechKit/releases/tag/v0.57.1) keeps Transcribe, Assist, and Voice Agent settings open and editable while the mode is switched off, and no longer throws you out of the page when you toggle a mode off. See [SpeechKit framework](/speechkit/framework).

### Updates

- **Desktop shell branded "SpeechKit UI".** [v0.57.1](https://github.com/kombifyio/SpeechKit/releases/tag/v0.57.1) gives the desktop window the SpeechKit mark and title so it no longer identifies itself as a generic shell.
- **`foundation` replaces the `base` schema package.** [StackKits v0.18.22](https://github.com/kombifyio/stackKits/releases/tag/v0.18.22) renames the shared CUE schema package from `base` to `foundation` and requires `foundation/stackkit.cue` in published archives. [v0.21.5](https://github.com/kombifyio/stackKits/releases/tag/v0.21.5) executes all-local Cloud Kit owners through their exact local router. See [Review, plan, and apply](/guides/stackkits/review-plan-and-apply).
- **Verify and Status reject stale Cloud service projections.** [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) rejects stale, foreign, or mutated Cloud service projections during Verify and Status readback.
- **No more duplicate SpeechKit launcher icons on Android.** [v0.58.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.58.0) stops the keyboard fork from adding a second launcher that opened the keyboard's settings instead of the app.

## StackKits v0.15.0 – v0.18.1: guided installer, service-controllable rollouts, and a provider-neutral Cloud core

StackKits rolled from v0.14.28 to [v0.18.1](https://github.com/kombifyio/stackKits/releases/tag/v0.18.1) this week. A new guided installer takes an unprepared machine to a running homelab in three modes. Cloud Kit gained a provider-neutral Cloud core, public TLS route ownership, and opt-in offsite backup. `apply`, `status`, `verify`, and `logs` are fully machine-readable on every outcome, and a new `stackkit service` command controls individual services between full applies.

## SpeechKit v0.53.0 – v0.57.0: one voice assistant everywhere, Android Voice Agent, hosted web assistant

SpeechKit shipped [v0.57.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.57.0). The Android app now holds a real spoken conversation and reaches the assistant straight from the SpeechKit keyboard. Every SpeechKit server exposes a ready-to-use `/assistant` web page. The same animated assistant renders identically on Android, in the Windows overlay, and on the web, driven by a single shared library. Deepgram Flux v2 is now selectable across realtime, speech-to-text, and text-to-speech.

### New features

- **Guided installer to a running homelab.** [StackKits v0.17.0](https://github.com/kombifyio/stackKits/releases/tag/v0.17.0) ships a full guided installation with three modes and a `v2 init` flow that accepts `--use-case`, `--platform`, and `--enable`. The installer bootstraps Docker and storage roots directly, works safely under `sudo`, and prints truthful native credentials. See [Quickstart](/stackkits/quickstart) and [Choosing a kit](/guides/stackkits/choosing-a-kit).
- **Provider-neutral Cloud core with public TLS routes.** [StackKits v0.15.0](https://github.com/kombifyio/stackKits/releases/tag/v0.15.0) resolves a required `cloud-core` workload for `base`, `auth`, `id`, and `coolify`, renders one digest-pinned Compose project, and executes it through a closed local runtime owner on an externally supplied host. [v0.18.0](https://github.com/kombifyio/stackKits/releases/tag/v0.18.0) makes Cloud Kit own and materialize public TLS routes end to end. Cloud runtime custody stores only service-scoped PocketID, TinyAuth, and Coolify material. Provider credentials, server credentials, leases, and inventory stay outside StackKits. See [Cloud Kit](/stackkits/kits/cloud-kit).
- **`stackkit service` command for post-rollout control.** [v0.16.0](https://github.com/kombifyio/stackKits/releases/tag/v0.16.0) adds `stackkit service start|stop|restart <service-key>` and `stackkit service logs <service-key>` for StackKits-managed Cloud core services. Mutations require `--owner-approve`, and `--json` returns a versioned action result. Use it to bounce or inspect one service between full applies.
