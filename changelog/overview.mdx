## BaseKit graduates to public beta

The v0.4 line landed on the unpinned official installer this week, taking BaseKit from pinned-prerelease testing to the public `latest` channel. Six releases shipped between Sunday and Wednesday: [v0.4.0-beta.1](https://github.com/kombifyio/StackKits/releases/tag/v0.4.0-beta.1), [v0.4.0](https://github.com/kombifyio/StackKits/releases/tag/v0.4.0), [v0.4.0-beta.2](https://github.com/kombifyio/StackKits/releases/tag/v0.4.0-beta.2), [v0.4.1](https://github.com/kombifyio/StackKits/releases/tag/v0.4.1), [v0.4.2](https://github.com/kombifyio/StackKits/releases/tag/v0.4.2), and [v0.4.3](https://github.com/kombifyio/StackKits/releases/tag/v0.4.3).

### New

- **BaseKit public beta on `latest`.** Unpinned installers at `https://base.stackkit.cc` now resolve to the v0.4 BaseKit public beta. You no longer need `STACKKIT_RELEASE_VERSION` to try the new BaseKit line on a fresh server. See [Choosing a kit](https://docs.kombify.io/guides/stackkits/choosing-a-kit) and [Install-only vs managed cloud](https://docs.kombify.io/guides/stackkits/install-only-vs-managed-cloud).
- **Custom-domain Coolify on ephemeral servers.** Custom-domain rollouts (SK-S3) now provision a fresh provider-leased Ubuntu server through the lease API, install BaseKit over SSH, capture evidence, and clean up DNS records and the server lease automatically. See [Deploy with the CLI or TechStack](https://docs.kombify.io/guides/stackkits/deploy-with-cli-or-techstack).
- **Agent-ready public surface.** Public docs, OpenMCP metadata, installer endpoints, and schemas now describe one BaseKit install path and one user-facing `stackkit` MCP connection, so coding agents have a single, stable entry point.

### Improved

- **Bounded install phases.** Custom-domain Coolify installs now run as explicit Start, Wait, Verify, and Cleanup phases with credential and provider preflight, so a stuck step fails fast with diagnostics instead of hanging the run.
- **Cleaner public surface.** The public repository is now restricted to the BaseKit beta contract plus CLI, runtime, website, public docs, and the module catalog. Unreleased kits and internal scaffolding no longer ship in release archives.

### Fixed

- **Custom-domain Base Hub URLs.** Run-scoped custom-domain Base Hub URLs (for example, `https://base.e2e-cd-<run>.kombify.pro`) are now accepted when they stay inside the expected DNS zone, so SK-S3 evidence imports succeed instead of being rejected as malformed.
- **Stable scenario contract.** Stable SK-S2 (kombify.me on Komodo) and SK-S3 (custom-domain Coolify) now claim only the supported bootstrapped BaseKit path, and the production verifier requires bootstrapped tfvars, Base Hub access summaries, public service URLs, and platform evidence from the official installer.
- **Skipped-scenario diagnostics.** Production workflows now emit explicit blocked/skipped diagnostics when a scenario can't run, instead of failing later during artifact upload.

</Update>

## BaseKit public beta release channel

StackKits now has a clearer public release split:

- **Stable latest:** [v0.4.4](https://github.com/kombifyio/StackKits/releases/tag/v0.4.4) remains the unpinned official installer target.
- **Pinned beta:** [v0.4.5-beta.1](https://github.com/kombifyio/StackKits/releases/tag/v0.4.5-beta.1) is the current BaseKit beta prerelease and must be installed with `STACKKIT_RELEASE_VERSION=v0.4.5-beta.1`.
- **Beta scope:** BaseKit only. Modern Homelab and High Availability remain preview docs until their own released-content matrices graduate.

### Improved

- **Released-content evidence.** The beta evidence records SK-S1 local Coolify, SK-S2 kombify.me Komodo, SK-S3 custom-domain Coolify, SK-S5 negative guard, browser evidence, host security baseline, archive validation, SBOMs, and attestations.
- **Ephemeral server E2E contract.** Cloud scenario evidence provisions fresh managed servers through the approved lease flow, runs StackKits over SSH as the transport, captures release artifacts, and cleans up DNS/server state after the run.
- **Installer semantics.** Prereleases stay pinned by environment variable; unpinned `https://base.stackkit.cc` remains stable latest.

### Known limits

- Dokploy remains draft/non-beta. Coolify is the BaseKit default and Komodo is the supported beta alternative.
- The Reddit/public beta announcement remains gated on green public mirror CI and docs freshness, not just on a published prerelease existing.

</Update>

## StackKits v0.3.4

One release this week, focused on a native MCP surface, TechStack-managed install readiness, and public release hygiene.

### New

- **Native MCP surface.** StackKits now exposes a single user-facing `stackkit` MCP connection, with `stackkit-mcp` as the local adapter and `stackkit-server /mcp` as the protected durable endpoint after install. Agents and IDEs can connect to one stable name across local, SSH, and remote setups.
- **TechStack-managed install readiness.** Release archives include the MCP and server pieces needed for kombify-TechStack managed installs, with bounded MCP rollout and Fresh Ubuntu phase gates so you can see exactly when each phase completes. See [Install-only vs managed cloud](https://docs.kombify.io/guides/stackkits/install-only-vs-managed-cloud) and [Deploy with the CLI or TechStack](https://docs.kombify.io/guides/stackkits/deploy-with-cli-or-techstack).
- **Agent discovery on stackkit.cc.** The site now ships OpenMCP metadata, updated `llms.txt`, and installation guidance for local, SSH, and protected durable MCP paths, so coding agents can discover and connect to a StackKit on their own.

### Fixed

- **Public release hygiene.** Public release builds no longer depend on private internal modules, and the Docker image build no longer leaks private module-auth configuration into the released image.
- **Bounded release gates.** Build timing, website checks, MCP smoke tests, and timeout-budget checks are now bounded by the 15-minute command policy, so a stuck step fails fast instead of hanging the release.

</Update>

<Update label="2026-06-05" description="Week of June 2 – June 5">

## StackKits v0.3.1 and v0.3.2

Two patch releases shipped this week, focused on Coolify routing, auth, installer reliability, and security.

### New

- **Canonical live scenarios.** Releases are now validated against three reference setups: local Coolify (SK-S1), kombify.me on Komodo (SK-S2), and custom-domain Coolify (SK-S3). Installer runs are split into bounded Start, Wait, and Verify phases so you can see exactly where a deploy is. See [Choosing a kit](https://docs.kombify.io/guides/stackkits/choosing-a-kit).
- **Coolify managed routing.** BaseKit on Coolify now bootstraps, reconciles, and exposes StackKit services through the managed proxy at predictable hostnames like `base.<domain>`, `id.<domain>`, `photos.<domain>`, and `kuma.<domain>`. See [Deploy with the CLI or TechStack](https://docs.kombify.io/guides/stackkits/deploy-with-cli-or-techstack).

### Improved

- **PocketID + TinyAuth on BaseKit.** Provider registration and runtime checks were restored, so protected services again show PocketID login (with TinyAuth as the password-only fallback) instead of skipping straight to TinyAuth. See [PocketID](https://docs.kombify.io/guides/stackkits/services/pocketid) and [TinyAuth](https://docs.kombify.io/guides/stackkits/services/tinyauth).
- **Cloudflare DNS-01 for custom domains.** Custom-domain Coolify rollouts now correctly pass Cloudflare Global API Key credentials to Traefik when `CLOUDFLARE_EMAIL` is set, while scoped API tokens continue to work as before. See [Traefik](https://docs.kombify.io/guides/stackkits/services/traefik).
- **Installer readiness.** Live installer jobs hand off VM state before verification and wait for routed services and certificates in bounded phases, instead of relying on one long-running job.
- **Security updates.** Go crypto and networking dependencies (`golang.org/x/crypto`, `golang.org/x/net`, and related modules) were updated and lint, static, and security checks restored to a clean state.

### Fixed

- **Coolify proxy recovery.** Fallback and reconciliation now correctly restore file-provider routing, dynamic config mounts, proxy TLS, service routes, host-gateway access, and dynamic-config sync.
- **Coolify endpoint contract.** BaseKit keeps the persisted Coolify endpoint node-local at `http://127.0.0.1:8000`, while bootstrap and readiness probes can use a separate endpoint reachable from remote Docker targets.
- **Restore-drill metrics.** Host CPU metrics now preserve legitimate zero values instead of dropping them as missing data.
- **Release archive validation.** Smoke checks now validate the current Coolify platform contract from packaged contents instead of obsolete token API markers.

</Update>
