## StackKits v0.10.0: unified Operations registry, read-only MCP, Alpine Foundation

Two feature releases and a hotfix landed on top of last week's v0.8.0 standalone lifecycle. [v0.9.0](https://github.com/kombifyio/StackKits/releases/tag/v0.9.0) brings Modern Homelab and the optional TechStack orchestration layer over v0.8's account-free Basement baseline. [v0.9.1](https://github.com/kombifyio/StackKits/releases/tag/v0.9.1) is a storage-defaults hotfix. [v0.10.0](https://github.com/kombifyio/StackKits/releases/tag/v0.10.0) unifies the CLI and MCP surfaces behind one Operations registry, hardens the Foundation baseline for Alpine, and adds `stackkit host attach-conformance`.

### New

- **Unified standalone Operations registry.** A canonical registry now owns `Init`, `Validate`, `Resolve`, `Generate`, `Plan`, `Apply`, `Verify`, `Status`, `Logs`, `Backup`, `Restore`, `Upgrade`, and `Drift` — their identities, command paths, mutation metadata, and approval policy. The public CLI and the native MCP connector bind the same registry, so `Backup`, `Restore`, `Upgrade`, `Drift`, native `Status` / `Logs`, `Validate`, and `Verify` now have full MCP parity through the exact same-build sibling CLI. Use MCP when you want an agent-driven Day-2 workflow that resolves to the same operations you get from the CLI.
- **Read-only MCP by default.** The native MCP connector refuses mutating operations unless the caller explicitly opts into writes, presents the exact registered operation identity, and clears explicit local Owner approval before the CLI is invoked. The StackKits State Console renders these registered contracts, requests governed approval, and never invokes `Apply` directly.
- **Alpine Foundation host hardening.** Architecture v2 Foundation host hardening now supports Alpine on OpenRC alongside apt-based hosts, with a canonical daily stable-repository upgrade job, an active `crond`, and the same governed `sysctl` evidence used on Ubuntu and Debian. Alpine host installation waits for the OpenRC-managed Docker daemon through a bounded 30-second readiness loop before grading Docker and Compose v2, and Alpine VM installation now includes `curl` (used by the governed host-routed HTTP verification phase).
- **`stackkit host attach-conformance`.** Atomically attaches an exact `ExternalHostBinding` and matching `HostConformanceReceipt` to one Inventory node before canonical plan generation. Workspace escapes, malformed JSON, unknown nodes, and post-generation attachment all fail closed. Use it when you provisioned a host outside StackKits and need to bind its conformance receipt to the plan before generate.

    ```bash
    stackkit host attach-conformance \
      --node <node-id> \
      --binding path/to/external-host-binding.json \
      --receipt path/to/host-conformance-receipt.json
    ```
- **Modern Homelab as an explicit topology ([v0.9.0](https://github.com/kombifyio/StackKits/releases/tag/v0.9.0)).** Modern Homelab now resolves an explicit Home-and-Cloud topology with local Owner authority, Owner-specific federation projections, and governed warm-standby placement — without restoring HA as a separate kit. See [Choosing a kit](/guides/stackkits/choosing-a-kit) and [High availability readiness](/guides/stackkits/high-availability-readiness).
- **Signed execution-channel bundles.** A digest-pinned process executor and signed execution-channel bundles form the offline-verifiable boundary for TechStack Advanced Day-2 and RIL operations. Inventory carries neither credentials nor transport endpoints — the channel bundle is the only thing that authorizes an Advanced runtime call.
- **Advanced Terramate change-set apply.** Advanced Terramate change sets can now be applied through the published CLI with mandatory capability, Owner, checkpoint, rollback, and verification authority, closing the last Advanced Mode gap after v0.8's offline verification, trust, and change-set creation.

### Fixed

- **Storage roots on Cloud Kit and Modern Homelab ([v0.9.1](https://github.com/kombifyio/StackKits/releases/tag/v0.9.1)).** `#StackSpecV2`'s empty `storage` default previously won over unifying with `#StorageIntentV2`, so kits authoring `storage: {}` shipped a spec with no roots at all. `cloud-kit` and `modern-homelab` were both affected, and `stackkit validate` rejected the CLI's own `stackkit init` output with `resolvedPlan.storage.hostRoots.dataRoot: requires an absolute host storage root`. Every product kit now materializes absolute host storage roots. Basement Kit — which spelled the roots out by hand — was unaffected. If you hit this on v0.9.0, upgrade to v0.9.1 or later.
- **Advanced drift-reconcile denials expose their reason code.** Structured denials now surface their stable machine-readable reason before rendering or lifecycle side effects, matching the Advanced-capability denial contract.
- **Execution-channel verification canonicalizes before comparing digests.** Runtime requests are canonicalized and re-sealed before their governed digests are compared, removing a source of false digest mismatches on otherwise equivalent requests.
- **Native v2 Apply resumes journaled reconciliation cleanly.** `ProductApplyReconcileRequiredError` now resumes through the service-owned recovery authority using only the typed non-empty request digest from the original Apply. Unrelated failures remain fail-closed, persistent reconciliation failures expose only deterministic verified executor/runtime/health contract references and closed `FailureCode` pairs, and no provider authority is introduced.
- **Alpine VM virtualization detection.** When `systemd-detect-virt` is unavailable, Alpine VM evidence now derives the closed `kvm` virtualization class from QEMU/KVM DMI vendor data. Proxmox OS-matrix clones also disable implicit cloud-init package upgrades so the graded install phase runs against the booted kernel and its matching modules, including Alpine nftables support.
- **Debian 12/13 Docker install path.** Debian 12/13 host compatibility now installs Engine and Compose v2 from Docker's official signed apt repository, because Bookworm does not publish Ubuntu's `docker-compose-v2` package name.

### Known limits

- The v0.10.0 protected OS matrix drops the retired StackKits host-preparation authority and the removed `--context` / `--force` switches on `stackkit generate`. If you scripted against those flags, migrate to the native transactional `stackkit generate` contract.
- Candidate, device, provider, browser, and compatibility evidence remains `pending/unverified` for the v0.x line.

</Update>

## StackKits v0.8.0: account-free Basement, plus a SpeechKit Windows fix

StackKits [v0.8.0](https://github.com/kombifyio/StackKits/releases/tag/v0.8.0) is the first stable release you can run end to end without a Kombify Cloud or TechStack account — a single-node Basement homelab driven entirely by the public `stackkit` CLI, backed by attested GitHub release indexes. It ships after the v0.7.12–v0.7.16 patch series closed out the Cloud and Modern Homelab runtime graduations, and a follow-up [v0.8.0-beta.6](https://github.com/kombifyio/StackKits/releases/tag/v0.8.0-beta.6) fixed a release-index URL casing regression before stable was cut. SpeechKit shipped a Windows reliability patch in [v0.51.2](https://github.com/kombifyio/SpeechKit/releases/tag/v0.51.2).

### New

- **Standalone OSS lifecycle for Basement.** `stackkit init --owner-source=local` establishes a local Owner identity and its PocketID, TinyAuth, and step-ca binding without a Kombify Cloud or TechStack account. Local CUE, the canonical ResolvedPlan, Owner custody, and lifecycle evidence are the authoritative Stack state — the default Basement workflow renders and operates the host and Docker baseline, local ingress, PocketID, TinyAuth, step-ca, Coolify, and Hub through `init`, `validate`, `generate`, `apply`, and `verify`. See [Choosing a kit](/guides/stackkits/choosing-a-kit) and [Deploy with the CLI or TechStack](/guides/stackkits/deploy-with-cli-or-techstack).
- **Day-2 verbs on the local Owner.** Standard `stackkit upgrade`, `stackkit backup`, staged `stackkit backup restore activate`, explicit `stackkit upgrade --recover` and `stackkit backup restore recover --rollback`, and read-only `stackkit drift detect` all run against local Owner authority with signed lifecycle evidence. `stackkit drift reconcile --mode standard --owner-approve` creates a mandatory Kopia snapshot and executor-state checkpoint before every generate, Apply, and Verify.
- **Attested release-index distribution.** Public GitHub release indexes are the distribution authority for install, offline verification, and explicit `stable`, `beta`, `edge`, or exact SemVer resolution. Every archive ships with an SPDX SBOM and GitHub-OIDC attestations, and stable publication is fail-closed against archive, index, SBOM, and attestation mismatch.
- **Advanced Mode integration boundary.** Offline verification of `stackkit.advanced-capability/v1`, Owner-pinned trust bundles (`stackkit advanced trust import` / `trust inspect`), deterministic Terramate generation, and signed change-set creation (`stackkit advanced change-set create`) form the optional integration surface for a TechStack orchestration UI — without adding Cloud authority to the standalone lifecycle. Missing Advanced capability surfaces as a structured `advanced_capability_required` denial before any rendering or side effect.
- **Modern Homelab outbound-control-agent graduation ([v0.7.16](https://github.com/kombifyio/StackKits/releases/tag/v0.7.16)).** The final Modern Homelab federation-control runtime binds the exact CUE action contract, performs bind / reconcile / verify, and records fresh, digest-bound evidence for every selected Home and Cloud node. Modern Homelab remains Preview until the remaining backup, observability, policy, and partition owners graduate.

### Improved

- **Cloud Kit runtimes finished graduating.** The v0.7.12–v0.7.15 patches close out Modern Homelab's `install.sh modern-homelab` selection ([v0.7.12](https://github.com/kombifyio/StackKits/releases/tag/v0.7.12)), plus Cloud host-security ([v0.7.13](https://github.com/kombifyio/StackKits/releases/tag/v0.7.13)), Cloud Public-Edge ([v0.7.14](https://github.com/kombifyio/StackKits/releases/tag/v0.7.14)), and Cloud offsite-backup ([v0.7.15](https://github.com/kombifyio/StackKits/releases/tag/v0.7.15)) runtimes — each provider-free, node-local, and `apply-ready` for its exact generated runtime and Health target.
- **CLI and release surface are cleanly public.** The public `stackkit` CLI and release surface are structurally separated from private publisher, Admin API, database, internal-host, and service-secret paths. TechStack is now an optional consumer of pinned public StackKits artifacts, structured command results, and lifecycle events.

### Fixed

- **Release-index URL casing ([v0.8.0-beta.6](https://github.com/kombifyio/StackKits/releases/tag/v0.8.0-beta.6)).** Public release-index asset URLs now retain GitHub's repository casing, and standalone resolution treats GitHub owner and repository casing equivalently — so `install.sh` and offline verification no longer fail on case-normalized URLs.
- **Kopia password handling.** Kopia repository passwords now enter the fixed local backup executor only through sensitive stdin and a child-process environment, removing the terminal-only prompt that previously blocked the exact published-archive restore proof.
- **Windows dictation under CPU load.** SpeechKit [v0.51.2](https://github.com/kombifyio/SpeechKit/releases/tag/v0.51.2) keeps Windows dictation reliable when the machine is busy: capture and helper processes now run at priorities that keep recording responsive, speech pauses are judged from the recorded audio rather than wall-clock time, and the status overlay stays in step with what is actually being captured. A new optional performance settings block lets you turn the priority tuning off if you prefer.

### Known limits

- v0.8.0 supports the governed single-node Basement path. Multi-node rolling upgrades, Photos, Vault, Files, and the broader Modern Homelab profile remain v0.9 scope.
- Terramate change-set apply, Advanced reconcile, coordinated Advanced rollback, and restore drills remain unavailable — Standard apply, upgrade, backup, restore, drift detection, and Owner-approved standard reconcile are the account-free surface.
- Provider credentials, server provisioning, and host lifecycle remain outside StackKits and may be orchestrated by TechStack.
- Candidate, device, provider, browser, and compatibility evidence remains `pending/unverified` for the v0.x line — the release publisher validates source, export, archive, checksum, and asset integrity, not live device compatibility.

</Update>

## StackKits v0.7 goes stable, plus SpeechKit Unified Voice

Two big product tracks landed this week. StackKits shipped [v0.7.0](https://github.com/kombifyio/StackKits/releases/tag/v0.7.0) as the new stable `latest` on the native Architecture v2 line, then followed with sixteen patch releases through [v0.7.16](https://github.com/kombifyio/StackKits/releases/tag/v0.7.16) that graduate one runtime owner at a time. SpeechKit shipped its Unified Voice release in [v0.50.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.50.0), a Companion-hardware follow-up in [v0.51.0](https://github.com/kombifyio/SpeechKit/releases/tag/v0.51.0), and a Windows fix in [v0.51.1](https://github.com/kombifyio/SpeechKit/releases/tag/v0.51.1).

### New

- **Three stable StackKit families.** Basement Kit, Cloud Kit, and Modern Homelab are now the three public release families. Basement and Cloud graduate to the native Architecture v2 identity on stable; Modern Homelab is included in every public archive and installable via `install.sh modern-homelab`, but stays honestly labeled Preview. See [Choosing a kit](/guides/stackkits/choosing-a-kit) and [Local vs cloud vs hybrid](/guides/stackkits/local-vs-cloud-vs-hybrid).
- **Cloud edge, host security, and offsite backup are apply-ready.** New provider-free runtimes bind and verify the Cloud public edge, Cloud host firewall + hardening baseline, and Cloud offsite backup (with fresh backup, restore, and readback evidence on every apply). See [Deploy with the CLI or TechStack](/guides/stackkits/deploy-with-cli-or-techstack).
- **Home internal PKI is apply-ready.** Optional private TLS now has a single authenticated Home authority node, with compiler-derived leaf identities per service and public trust distribution to declared Home nodes. See [Traefik](/guides/stackkits/services/traefik).
- **Modern Homelab federation is executable end to end.** Home ↔ Cloud federation now has bound runtime owners for the federation link, origin-mTLS bridge, Cloud-side publication, backend health, and outbound control agent — plus a five-way partition of Policy, Link, Control, Backup, and Observability authority. Modern Homelab remains Preview until the remaining owners graduate. See [High availability readiness](/guides/stackkits/high-availability-readiness).
- **Live voice typing in SpeechKit.** Streaming dictation over a single warm WebSocket delivers draft words while you speak, with automatic fallback to classic transcription when a streaming provider isn't available.
- **AssemblyAI joins Deepgram as a first-class provider.** Short dictation clips finish in one round trip on AssemblyAI Universal-3.5 Pro, and AssemblyAI is now available for live streaming partials. Requests can be steered with a situational prompt, explicit key terms, and preceding dialogue turns.
- **Account-level voice preferences.** Pick your preferred speech providers once in the Workbench and every hosted request follows them automatically, with graceful fallback and honest reporting of which provider actually ran.
- **Sign in with your identity provider.** A single SpeechKit deployment now accepts both service bearer tokens and IdP-issued JWTs (`bearer_or_oidc`), so mobile and web clients can sign in per user without a second deployment.
- **Talk to a paired Kombify Box.** A paired Box can take one complete Touch-to-Talk voice turn end to end and speak back a local result, with each turn bound to the paired device and its Home Assistant claim.
- **Auditable wake-word models.** The on-device "Kombify" and "Jarvis" wake words are now produced by a fully reproducible, pinned training pipeline.

### Improved

- **Native Architecture v2 everywhere.** CLI, API, MCP, catalog, compiler, generators, artifacts, and evidence all bind the same v2 identity from authoring through apply. New writes are v2-only; v1 stays read-only for migration. See [From intent to StackSpec](/guides/stackkits/from-intent-to-stack-spec).
- **Governed RIL action surface.** A CUE-governed catalog of seven closed action primitives with explicit approval and grant requirements now sits behind a two-step `resolve` / `execute` API, with an atomic execution ledger for replay-safe operations. Provider credentials, raw SSH, arbitrary paths, and caller commands are refused before the governed owner runs.
- **Tighter renderer boundaries.** Cloud public-edge, private-admin-mesh, and offsite-backup artifacts now carry only their exact compiler-owned routes, nodes, and authority — generic storage, DNS, credentials, and lease fields cannot cross the boundary.
- **Native WebSocket clients work without dev overrides.** Mobile apps and CLIs presenting a session ticket subprotocol without an `Origin` header now proceed straight to ticket verification for SpeechKit's Voice Agent and streaming Dictation sockets. Browser origin allowlisting is unchanged.

### Fixed

- **Windows wake-word and startup crash.** SpeechKit [v0.51.1](https://github.com/kombifyio/SpeechKit/releases/tag/v0.51.1) bundles a compatible on-device speech runtime, so wake-word activation no longer aborts on startup and the app window no longer fails to open on affected machines. Update if you installed v0.50.0 or v0.51.0 on Windows.
- **Streaming dictation session leaks.** Sessions that were created but never attached (for example, when a client falls back to batch transcription) are now reaped automatically once their ticket expires, so repeated fallbacks can no longer trigger a "per user limit exceeded" error.
- **`ws_url` behind reverse proxies.** Streaming Dictation session responses now honor the configured public server URL when building `ws_url`, matching Voice Agent behavior behind proxies and Docker port mappings.
- **Auto language detection on short clips.** Short dictation clips without an explicit language keep automatic language detection instead of being forced to English.
- **`install.sh modern-homelab` works.** The installer now selects the dedicated `stackkits-modern-homelab` archive instead of rejecting the kit, and the default `all` install path stages Modern Homelab alongside Basement and Cloud.
- **Persisted plan decoding.** Canonical plans now decode integer health ports, timeouts, and expected HTTP status lists correctly without weakening fractional-value rejection.

### Known limits

- Modern Homelab stays Preview until the remaining backup, observability, policy, and partition runtime owners graduate and live evidence is captured.
- Candidate, device, provider, browser, and compatibility evidence remains `pending/unverified` for the v0.7.x line — the release publisher validates source, export, archive, checksum, and asset integrity, not live device compatibility.

</Update>

## Architecture v2 lands in beta

One prerelease this week: [v0.6.0-beta.1](https://github.com/kombifyio/StackKits/releases/tag/v0.6.0-beta.1) publishes the StackKits Architecture v2 contract for early integration. The supported v1 Basement and Cloud rollout paths remain unchanged, and stable `latest` stays on [v0.5.2](https://github.com/kombifyio/StackKits/releases/tag/v0.5.2).

### New

- **Architecture v2 preview.** The new contract binds kit identity, inventory, modules, runtime networks, and owned artifacts into a single immutable resolved plan. It is fail-closed by design: generation and apply reject missing concrete renderers or runtime evidence instead of falling back to legacy behavior. Available for integration testing only — not yet on `latest`. See [Choosing a kit](/guides/stackkits/choosing-a-kit).
- **Kit identity drives the plan.** The kit you pick now selects its capability plan directly, rather than a global context value deciding which kit is being built. Basement and Cloud share a common contract spine but keep separate deployment semantics: Basement owns home-site, LAN, private remote access, and optional public egress; Cloud owns cloud-site, private admin mesh, and public edge. Both support explicit multi-node plans without being redefined as a separate kit. See [Local vs cloud vs hybrid](/guides/stackkits/local-vs-cloud-vs-hybrid).
- **Modern Homelab is now the federation product.** Modern Homelab is defined as the local-plus-cloud federation kit, requiring explicit site federation, isolated bridge and publication policies, placement and data authority, and fail-closed partition behavior. It stays in Preview until the bridge renderer and real multi-site evidence pass.

### Improved

- **High Availability stays an add-on.** `ha-kit` is rejected as a standalone product identity; HA continues to resolve as a kit- and mode-specific add-on overlay. Existing HA setups migrate through the compatibility seam. See [High availability readiness](/guides/stackkits/high-availability-readiness).
- **v0.5 inputs still readable.** Existing v0.5 StackSpec inputs can be projected through the migration seam for one minor compatibility window. New plans persist under Architecture v2 and must be re-resolved when mandatory authority, instance, network, or artifact fields change.

### Known limits

- v0.6.0-beta.1 is a prerelease. It publishes version-tagged artifacts without advancing the stable `latest` release or OCI tag. The stable rollback baseline remains v0.5.2.
- Architecture v2 generation and apply intentionally fail closed where a concrete typed renderer or runtime-evidence implementation is still missing. Modern Homelab runtime graduation is not claimed in this release.
- Provider smokes, the Proxmox OS matrix, released-content SK-S1, and browser evidence are advisory documentation lanes for this prerelease; missing rows are published as `pending/unverified` rather than synthetic passes.

</Update>

The v0.5 line shipped this week, taking the Basement Kit to stable, previewing the new Cloud Kit, and rolling out a universal host security baseline. Four releases: [v0.5.0-beta.2](https://github.com/kombifyio/StackKits/releases/tag/v0.5.0-beta.2), [v0.5.0](https://github.com/kombifyio/StackKits/releases/tag/v0.5.0), [v0.5.1-beta.1](https://github.com/kombifyio/StackKits/releases/tag/v0.5.1-beta.1), and [v0.5.1-beta.2](https://github.com/kombifyio/StackKits/releases/tag/v0.5.1-beta.2).

### New

- **Basement Kit is stable, Cloud Kit is in preview.** [v0.5.0](https://github.com/kombifyio/StackKits/releases/tag/v0.5.0) is the new public `latest`. The single BaseKit line is now split into a shared foundation plus two shipped kits: **Basement Kit** (local, `base.stackkit.cc`) as the verified stable single-server product, and **Cloud Kit** (`cloud.stackkit.cc`) as the cloud profile in scaffolding, graduating in v0.5.1 once the managed `kombify.me` and custom-domain gates pass. The `base-kit → basement-kit` alias keeps existing installs working. See [Choosing a kit](https://docs.kombify.io/guides/stackkits/choosing-a-kit).
- **Three-kit lineup on the website.** The product surface now lists Basement (stable), Cloud (graduating), and Modern Homelab (preview / early-access), with `/kits/basement` and `/kits/cloud` detail pages and a redirect from the old `/kits/base` URL.

See [High availability readiness](https://docs.kombify.io/guides/stackkits/high-availability-readiness).

### Improved

- **Universal host security baseline.** The measured host baseline — UFW default-deny with SSH/HTTP/HTTPS allowed, fail2ban on the sshd jail, security-only unattended upgrades, sshd hardening, and sysctl controls — is now applied to **every kit** (Basement, Cloud, Modern Homelab) on any Linux/apt host, instead of Basement only.
- **Coolify custom-domain routing hardened.** Generated Coolify proxy labels ensure BaseKit service routers win over fallback routers and request wildcard TLS coverage for custom-domain service hosts. See [Deploy with the CLI or TechStack](https://docs.kombify.io/guides/stackkits/deploy-with-cli-or-techstack).
- **Deferred app readiness.** Accepted on-demand platform apps are now treated as deferred public-readiness evidence, while running and required services continue to gate the public URL check.

### Fixed

- **Cloud rollout no longer times out on first boot.** [v0.5.1-beta.2](https://github.com/kombifyio/StackKits/releases/tag/v0.5.1-beta.2) fixes cloud VM installs that failed with `failed to install Docker: apt_wait timeout` on v0.5.1-beta.1 by extending the apt-lock wait so it outlasts cloud-init and unattended-upgrades holding the dpkg lock on fresh servers.
- **Coolify proxy reconciliation.** The Coolify Docker endpoint and generated router labels now reconcile correctly, so the custom-domain path no longer depends on host-side proxy shims.
- **Browser evidence setup.** PocketID consent now completes during browser evidence capture, so BaseKit owner and passkey setup proof stays end-to-end. See [PocketID](https://docs.kombify.io/guides/stackkits/services/pocketid).
- **Website product surface.** The nav and home page now reflect two kits over one base, and `/kits/basement` and `/kits/cloud` route to their detail pages instead of the retired `/kits/base` page.

</Update>

Six releases shipped between Sunday and Wednesday: [v0.4.0-beta.1](https://github.com/kombifyio/StackKits/releases/tag/v0.4.0-beta.1), [v0.4.0](https://github.com/kombifyio/StackKits/releases/tag/v0.4.0), [v0.4.0-beta.2](https://github.com/kombifyio/StackKits/releases/tag/v0.4.0-beta.2), [v0.4.1](https://github.com/kombifyio/StackKits/releases/tag/v0.4.1), [v0.4.2](https://github.com/kombifyio/StackKits/releases/tag/v0.4.2), and [v0.4.3](https://github.com/kombifyio/StackKits/releases/tag/v0.4.3).

See [Choosing a kit](https://docs.kombify.io/guides/stackkits/choosing-a-kit) and [Install-only vs managed cloud](https://docs.kombify.io/guides/stackkits/install-only-vs-managed-cloud).
