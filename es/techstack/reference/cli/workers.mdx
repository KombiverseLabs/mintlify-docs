## techstack api workers identity upgrade approve

Aprueba la clave propuesta por un servidor legacy.

Vincula la clave pendiente identificada por `key_thumbprint`, dejando al worker vinculado a la clave (después se rechazan las solicitudes con solo bearer). Requiere al propietario y un inicio de sesión multifactor reciente (de como máximo 300 segundos). Registra con la identidad el sujeto que aprueba y la hora y los escribe en el log. Devuelve 409 `identity_upgrade_not_pending` si no hay ninguna clave pendiente no caducada con ese fingerprint.

```bash
techstack api workers identity upgrade approve <id> [flags]
```

<Warning>Requiere confirmación. Esta operación decide qué clave puede controlar el servidor; aprueba solo una clave cuyo fingerprint Guard registre en el servidor. Pasa `--yes` o responde a la pregunta; una ejecución no interactiva sin `--yes` se detiene antes de cualquier solicitud con el código de salida 9.</Warning>

| HTTP | `POST /api/v1/workers/{id}/identity/upgrade/approve` |

## techstack api workers identity upgrade-status

Muestra si la clave de identidad de un servidor aún necesita aprobación.

Para el propietario del worker. `identity_binding=legacy_bearer` con `code=guard_identity_upgrade_required` significa que el servidor se autentica solo con su credencial bearer y únicamente se observa; `pending` contiene el fingerprint de la clave propuesta, que el propietario compara con el que Guard registra en el servidor. Un worker de otro tenant o propietario devuelve 404.

```bash
techstack api workers identity upgrade-status <id> [flags]
```

## techstack api workers identity upgrades

Lista los servidores del propietario que esperan aprobación de una clave de identidad.

Para el propietario. Cada entrada corresponde a un servidor suyo que propuso una clave y solo se observa hasta que esa clave exacta se apruebe con `approveWorkerIdentityUpgrade` (requiere inicio de sesión multifactor reciente). Las entradas incluyen el hostname y el fingerprint de la clave para compararlo con el que Guard registra en el servidor. Listar no concede permisos.

## techstack api workers outcomes list

Lista los resultados no resueltos de operaciones de un kombify Guard.

Lista las operaciones de un worker propio cuyo resultado se desconoce: kombify Guard registró que el efecto pudo haber ocurrido o no y ninguna observación lo aclaró. Cada una bloquea nuevos cambios en el servidor. `state` es `reconciling` mientras Guard intenta aclararlo y `needs_operator` cuando permanece sin resolver más allá del tiempo configurado (`TECHSTACK_GUARD_OUTCOME_NEEDS_OPERATOR_AFTER`, 30 minutos por defecto). El tiempo solo cambia cómo se muestra el resultado; nunca libera el bloqueo. Un worker de otro tenant o propietario devuelve 404.

```bash
techstack api workers outcomes list <id> [flags]
```

## techstack api workers outcomes resolve

Libera un resultado de operación no resuelto de kombify Guard.

Guarda una revisión de resolución del operador que solo añade información para una operación cuyo resultado se desconoce y libera el bloqueo del worker. `disposition` es `verified_applied` (el efecto está presente), `verified_not_applied` (no ocurrió nada) o `accept_unknown` (liberar sin un resultado verificado); `note` registra qué se verificó. El actor es el sujeto autenticado y queda registrado con la revisión; un Guard no puede guardar estas decisiones. Requiere un inicio de sesión multifactor reciente (de como máximo 300 segundos). `expected_revision` debe ser la revisión devuelta por la lista; de lo contrario devuelve 409 `outcome_revision_stale`. El cuerpo se decodifica de forma estricta: claves exactas, sin campos desconocidos.

```bash
techstack api workers outcomes resolve <id> <command-id> [flags]
```

<Warning>Requiere confirmación. Esta operación libera el bloqueo de una operación cuyo resultado nunca se aclaró, por lo que pueden ejecutarse cambios conflictivos en el servidor. Pasa `--yes` o responde a la pregunta; una ejecución no interactiva sin `--yes` se detiene antes de cualquier solicitud con el código de salida 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/workers/{id}/outcomes/{command_id}/resolve` |
| Cambia el estado | Sí |
| Herramienta MCP | Ninguna |

| Argumento | Tipo | Descripción |
| --- | --- | --- |
| `<id>` | string | **Obligatorio.** ID del recurso. |
| `<command-id>` | string | **Obligatorio.** |
| `--disposition` | string | **Obligatorio.** Uno de `verified_applied`, `verified_not_applied`, `accept_unknown`. |
| `--expected-revision` | integer | **Obligatorio.** |
| `--note` | string | **Obligatorio.** |
