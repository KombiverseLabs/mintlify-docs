## techstack api jobs get

Obtiene el estado actual de un trabajo propio.

Esta es la superficie canónica de sondeo para la UI, los clientes de la API, las herramientas MCP y los agentes. `waiting_enrollment` expone una espera no terminal; el acceso al destino sigue sin estar disponible hasta que el trabajo se reanuda y alcanza un estado terminal de éxito.

```bash
techstack api jobs get <id> [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/jobs/{id}` |
| Cambia el estado | No |
| Herramienta MCP | `get_job` |

| Argumento | Tipo | Descripción |
| --- | --- | --- |
| `<id>` | string | **Obligatorio.** ID del recurso. |

## techstack api jobs list

Lista los trabajos propiedad del usuario autenticado.

Devuelve el mismo estado de trabajos, limitado al propietario, que usan la UI del operador y los clientes de automatización. Un trabajo con `state: waiting` sigue activo y el proceso actual del orquestador programa su siguiente comprobación; no es una acción fallida del proveedor. Si esa programación queda obsoleta tras reiniciar el proceso, usa la operación `resumeStackEnrollment` con el destino exacto.

```bash
techstack api jobs list [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/jobs` |
| Cambia el estado | No |
| Herramienta MCP | `list_jobs` |

| Argumento | Tipo | Descripción |
| --- | --- | --- |
| `--page` | integer | Número de página (predeterminado: 1). |
| `--per-page` | integer | Predeterminado: `50`. |
| `--stack-id` | string | — |
| `--state` | string | Uno de `pending`, `running`, `waiting`, `completed`, `failed`, `canceled`. |
| `--type` | string | — |
| `--search` | string | — |
