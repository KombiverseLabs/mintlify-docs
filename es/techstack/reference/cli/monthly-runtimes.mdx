## techstack api monthly-runtimes cleanup-readback

Lee los datos redactados del estado de limpieza de un runtime gestionado.

Devuelve datos de estado limitados al tenant y al propietario para la generación exacta y actual del recurso de control del proveedor del arrendamiento. Este endpoint de solo lectura nunca llama a un proveedor ni a un agente de runtime y nunca devuelve handles de recursos del proveedor, comandos, documentos de evidencia ni credenciales. Una operación terminal ya no está en curso, pero por sí sola no demuestra que la limpieza haya tenido éxito: la ausencia en el proveedor requiere absence_evidence_ref y la liberación de capacidad requiere capacity_released.

```bash
techstack api monthly-runtimes cleanup-readback <lease-id> [flags]
```

| HTTP | `GET /api/v1/monthly-runtimes/{lease_id}/cleanup-readback` |

| Argumento | Tipo | Descripción |

## techstack api monthly-runtimes reconnect

Recupera la sesión de Guard de un runtime gestionado.

Sondea el agregado canónico; cuando no puede demostrar una conexión de Guard, reinicia Guard a través del canal de ejecución fijado para un propietario con derecho de un servidor en ejecución y vuelve a observar la conexión dentro de una ventana acotada; después hace converger la inscripción a enrolled. ## techstack api monthly-runtimes recreate

Recrea una generación de servidor gestionado completamente liberada.

Aprovisiona explícitamente la generación N+1 para la misma ranura de runtime independiente del proveedor después de que la generación N tenga un estado terminal de arrendamiento y de servidor canónico, un estado terminal de la operación del proveedor, evidencia opaca de ausencia nativa del proveedor y la liberación exacta de la capacidad. La intención inmutable de proveedor, región, oferta, rol, StackKit y servicios se recupera del arrendamiento anterior limitado al propietario; los clientes no pueden sustituirla. El endpoint delega en la misma autoridad de expansión de runtime gestionado que Add Node, de modo que la inscripción, la evidencia de Guard, los endpoints y el despliegue del StackKit pasan por el flujo completo de creación. Un Idempotency-Key estándar es obligatorio y reproduce de forma segura la generación aceptada.

```bash
techstack api monthly-runtimes recreate <lease-id> [flags]
```

<Warning>Requiere confirmación. Esta operación sustituye el servidor del proveedor del runtime por uno recién aprovisionado y se factura. Pasa `--yes` o responde a la pregunta; una ejecución no interactiva sin `--yes` se detiene antes de cualquier solicitud con el código de salida 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/monthly-runtimes/{lease_id}/recreate` |
| Cambia el estado | Sí |
| Herramienta MCP | `recreate_monthly_runtime` |

| Argumento | Tipo | Descripción |
| --- | --- | --- |
| `<lease-id>` | string | **Obligatorio.** ID del arrendamiento de runtime mensual. |
| `--confirmed` | boolean | **Obligatorio.** Confirmación explícita de que Recreate aprovisiona y factura una nueva generación de servidor gestionado. Uno de `true`. |
| `--body` | json | Cuerpo de la solicitud JSON (`application/json`) como literal, `@path` o `-` para stdin. |

## techstack api monthly-runtimes stop

Detiene un servidor gestionado sin destruirlo.

Admite una reconciliación de control del proveedor, ligada a la generación, hacia el estado detenido. centron usa su acción de apagado ordenado del invitado; IONOS apaga el invitado a través del canal de ejecución porque la detención del proveedor IONOS libera la IPv4 DHCP asignada. El servidor conserva su disco, su dirección, su arrendamiento, su reserva de capacidad y la facturación mensual.

```bash
techstack api monthly-runtimes stop <lease-id> [flags]
```
