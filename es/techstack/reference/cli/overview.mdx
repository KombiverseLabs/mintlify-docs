<Note>Generado a partir del release v0.32.8 de Techstack (fuente `4c7d219a5d56`). Para una versión instalada, `techstack api <command> --help` es la fuente autorizada.</Note>

`techstack api` llama a la API de Techstack exactamente como la describe la [referencia de la API](#referencia-de-la-api): un comando por operación pública, generado a partir del contrato de API del release. Cada comando imprime JSON en stdout sin el sobre de la respuesta; los errores van a stderr como el objeto de error estructurado.

## Autenticación

| Variable | Significado |
| --- | --- |
| `TECHSTACK_API_URL` | URL base de la API. El valor predeterminado es `https://api.kombify.io/v1/techstack`; configúrala con la dirección de tu propia instancia de Techstack para llamar directamente a esa instancia. |
| `TECHSTACK_API_TOKEN` | Token Bearer que se envía con cada solicitud. Sin él, la CLI usa la sesión guardada por `techstack login` y falla con el código de salida 3 cuando no hay ninguna o ha caducado. |

## Opciones universales

| Opción | Se aplica a | Descripción |
| --- | --- | --- |
| `--fields <paths>` | todos los comandos | Rutas con puntos, separadas por comas, que se conservan en la salida; en los arrays se aplican a cada elemento. |
| `--ndjson` | todos los comandos | Imprime los arrays como un valor JSON compacto por línea. |
| `--dry-run` | comandos que modifican | Imprime la solicitud resuelta como JSON sin autorizarla ni enviarla. |
| `--idempotency-key <key>` | comandos que modifican | Encabezado Idempotency-Key; de forma predeterminada, un UUID nuevo. |
| `--body <json\|@path\|->` | comandos con un cuerpo JSON | Cuerpo base de la solicitud como literal, archivo o stdin; los flags de argumentos sobrescriben sus propiedades. |
| `--file <path\|->` | comandos con un cuerpo de archivo | Archivo del cuerpo de la solicitud enviado con el tipo de contenido declarado. |
| `--yes` | comandos que requieren confirmación | Confirma sin preguntar; obligatorio cuando no es interactivo. |

Los comandos marcados como que requieren confirmación piden `yes` en un terminal. Sin terminal, se niegan a enviar la solicitud salvo que se indique `--yes`, imprimen un error `CONFIRMATION_REQUIRED` y salen con el código 9.

## Códigos de salida

| Código | Significado |
| --- | --- |
| 0 | Éxito. |
| 1 | Cualquier otro fallo. |
| 2 | Entrada no válida (HTTP 400/422). |
| 3 | No autenticado (HTTP 401). |
| 4 | Denegado, pago requerido o límite de frecuencia alcanzado (HTTP 402/403/429). |
| 5 | No encontrado (HTTP 404). |
| 6 | Conflicto (HTTP 409). |
| 7 | Fallo del servidor o del transporte (HTTP 5xx). |
| 9 | Confirmación requerida o rechazada. |
