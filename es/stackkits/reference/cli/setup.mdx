Configura la cuenta de propietario de una aplicación aplicada.

Ejecuta una acción de configuración declarada en el Plan sobre la aplicación local existente. Lee los campos JSON de credenciales privadas y la ruta del archivo en la guía de configuración o en la acción de estado de la aplicación seleccionada. Las credenciales nunca se escriben en la evidencia del ciclo de vida. Volver a ejecutar tras una interrupción vuelve a observar la aplicación antes de completar la misma operación de configuración pendiente.

```bash
stackkit setup <workload> [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--complete-onboarding` | bool | — | Completa el onboarding de usuarios y administradores de la app tras verificar el inicio de sesión del propietario |
| `--credentials-file` | string | — | Archivo JSON privado de credenciales del propietario, relativo al workspace (por defecto, la guía de configuración de la aplicación seleccionada) |
| `--json` | bool | — | Emite el resultado de configuración verificado y sin secretos |
| `--operation-id` | string | — | Reanuda una operación de configuración pendiente; por defecto la configuración pendiente actual o un ID nuevo |
| `--owner-approve` | bool | — | Aprueba esta configuración de aplicación ligada al Plan |

**Ejemplos**

```bash
# Create the Photos owner from the private credentials in .stackkit/setup/owner.json
stackkit setup photos --owner-approve

# Also finish the application's onboarding after the owner login is verified
stackkit setup photos --owner-approve --complete-onboarding

# Create the Files owner from a workspace-relative credentials file of your choice
stackkit setup files --owner-approve --credentials-file private/files-owner.json
```

Subcomandos: [`stackkit setup ai-connect`](#stackkit-setup-ai-connect), [`stackkit setup ai-provider`](#stackkit-setup-ai-provider), [`stackkit setup connector`](#stackkit-setup-connector)

## stackkit setup ai-connect

Conecta Ollama de Private AI a tu kombify AI como endpoint de modelo propio.

Activa el conector opcional de kombify AI del caso de uso Private AI. Crea un endpoint de modelo en Companion Studio (Settings, AI access, Model endpoints) con el origen http://ollama:11434 y copia su token de conector. Este comando lee el token desde la entrada estándar o desde `--token-file`, nunca desde un argumento, comprueba su formato, lo mantiene bajo custodia local del propietario y activa el conector. Las siguientes acciones generate y apply inician el conector saliente junto a Ollama. No se abre nada entrante y Ollama permanece sin publicar.

`--disable` desactiva el conector y elimina el token de la custodia local. Revoca el endpoint en Companion Studio para inutilizar el token en todas partes.

```bash
stackkit setup ai-connect [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--disable` | bool | — | Desactiva el conector y elimina su token de la custodia local |
| `--json` | bool | — | Emite el resultado sin secretos |
| `--token-file` | string | — | Archivo con el token del conector; "-" o ninguna opción lee la entrada estándar |

**Ejemplos**

```bash
# Paste the connector token, then press Enter and Ctrl-D (or read it hidden on a terminal)
stackkit setup ai-connect --token-file -

# Read the token from a private file
stackkit setup ai-connect --token-file ~/kombify-connector-token

# Turn the connector off and remove its token
stackkit setup ai-connect --disable
```

## stackkit setup ai-provider

Ofrece un proveedor externo compatible con OpenAI en Private AI con una clave de tu kombify Wallet.

Permite que Open WebUI del caso de uso Private AI use un proveedor de inferencia externo compatible con OpenAI (por ejemplo OpenAI, Mistral, Groq u OpenRouter) junto al Ollama del nodo. La clave API del proveedor nunca pasa por este comando, la StackSpec ni el bundle generado: guárdala como credencial de IA en tu kombify Wallet, permite este nodo en el elemento y entrégala cifrada a este nodo con "stackkit wallet-item import". Este comando vincula la clave del proveedor a ese elemento entregado y establece la URL base https del proveedor. Cada apply lee entonces la versión entregada más reciente, de modo que una rotación en la Wallet surte efecto tras "stackkit wallet-item import" del elemento rotado y el siguiente apply. Apply falla de forma cerrada cuando el elemento no está en la custodia de este nodo.

`--disable` elimina el proveedor de Open WebUI y la vinculación de la clave de la custodia local. El elemento entregado permanece en la custodia de elementos Wallet del nodo.

```bash
stackkit setup ai-provider [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--base-url` | string | — | URL base https de la API del proveedor compatible con OpenAI |
| `--disable` | bool | — | Elimina el proveedor externo y su vinculación de clave |
| `--json` | bool | — | Emite el stackkit.command-result/v1 sin secretos |
| `--tenant-ref` | string | — | Tenant al que se entregó el elemento de Wallet |
| `--wallet-item` | string | — | Referencia del elemento de Wallet de la clave del proveedor entregada |

**Ejemplos**

```bash
# Bind the provider key delivered as Wallet item itm_... and set the provider
stackkit setup ai-provider --base-url https://api.openai.com/v1 --tenant-ref "$TENANT" --wallet-item itm_abc...

# Remove the provider
stackkit setup ai-provider --disable
```

## stackkit setup connector

Emite, revoca o verifica el conector exacto de Home Assistant local.

```bash
stackkit setup connector [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--json` | bool | — | Emite los bytes exactos del recibo firmado autenticado y los hechos locales actuales |
| `--operation-id` | string | — | Identidad exacta y estable de la operación de configuración del conector |
| `--owner-approve` | bool | — | Aprueba esta solicitud exacta de alta o revocación del conector |
| `--request-file` | string | — | JSON de solicitud de conector privado, solo metadatos y relativo al workspace; nunca contiene credenciales |
| `--verify-only` | bool | — | Lee y verifica un recibo conservado frente al vínculo local actual sin emitir ni revocar |
| `--workload` | string | — | Workload local exacto; solo se admite smart-home |
