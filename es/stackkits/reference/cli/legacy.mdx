Estos comandos existen en el árbol de comandos pero no forman parte del flujo de trabajo actual. Los comandos heredados se rechazan en los releases actuales; los comandos obsoletos siguen funcionando e indican su reemplazo.

## stackkit app add

Añade o actualiza un traspaso de app PaaS de compatibilidad v0.6.

<Warning>Los releases actuales rechazan este comando; pertenece a la línea de compatibilidad exacta v0.6.</Warning>

```bash
stackkit app add <name> [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--auth` | string | `login-gateway` | Modo de autenticación de la ruta: login-gateway o public |
| `--env` | stringArray | — | Variable de entorno en texto plano como KEY=value; repetible |
| `--health-path` | string | `/health` | Ruta HTTP de health |
| `--host` | string | — | Host de la ruta para la app |
| `--image` | string | — | Imagen de contenedor para el traspaso a PaaS |
| `--kind` | string | `sveltekit` | Tipo de app (actualmente solo sveltekit) |
| `--port` | int | `3000` | Puerto del contenedor que expone la app |
| `--secret` | stringArray | — | Referencia de secreto como KEY=env:NAME, KEY=vault:NAME o KEY=file:PATH; repetible |

## stackkit backup migrate-from-restic

Importa un repositorio Restic existente a Kopia (una sola vez).

<Warning>Los releases actuales rechazan este comando; pertenece a la línea de compatibilidad exacta v0.6.</Warning>

Ejecuta el importador puntual de Restic a Kopia.

Lee el repositorio Restic configurado en el addon v1, recorre cada snapshot y lo recrea dentro de Kopia conservando las marcas de tiempo originales. Tras una importación correcta, el addon cambia automáticamente engine: "restic-import" a "kopia".

```bash
stackkit backup migrate-from-restic [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--dry-run` | bool | — | Imprime el plan sin importar |

## stackkit cluster join-token

Crea un token de unión para nodos worker o de almacenamiento.

<Warning>Los releases actuales rechazan este comando; pertenece a la línea de compatibilidad exacta v0.6.</Warning>

Crea un token de unión para nodos worker o de almacenamiento.

El token es la única vía admitida para tratar otra instalación de BaseKit como miembro de este homelab. El registro de servidores remotos de Coolify y las actualizaciones del espejo de TechStack consumen esta identidad de clúster en pasos posteriores del despliegue.

```bash
stackkit cluster join-token [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--endpoint` | string | — | Endpoint del nodo principal que usan los workers para unirse |
| `--homelab-id` | string | — | ID del homelab (por defecto, el nombre de la stack spec) |
| `--main-node` | string | — | ID/nombre del nodo principal (por defecto, el nodo de tipo principal de la stack spec) |
| `--output, -o` | string | `.stackkit/cluster/join-token.json` | Ruta de salida del JSON del token |
| `--ttl` | duration | `24h0m0s` | Duración de validez del token |

## stackkit kit upgrade

Resuelve e instala un release verificado de StackKit.

<Warning>Obsoleto: usa stackkit upgrade</Warning>

Resuelve un release público de StackKit desde GitHub, verifica su archivo, el SBOM SPDX, la atestación GitHub OIDC/Sigstore y la raíz de confianza en caché, y después lo instala atómicamente en .stackkit/releases/.

Con `--dry-run` genera el destino verificado solo en un workspace sombra acotado e informa de una diferencia canónica de plan/artefactos. Sin `--dry-run` primero inspecciona ese destino, crea un snapshot nativo de Kopia más un punto de control de recuperación del estado del ejecutor firmado por el propietario, prepara y verifica los datos de reversión sin activarlos, y solo entonces instala y ejecuta la transacción exacta generate/apply/verify del destino. Una transacción de destino fallida puede restaurar y verificar el ejecutor anterior solo antes de que se admita el Apply del destino. Tras Apply, el reinicio del runtime anterior queda bloqueado hasta que exista una activación verificada de los datos anteriores; la preparación aislada de Kopia por sí sola no la autoriza. Una confirmación de destino completada conserva su prueba de éxito para la finalización explícita. Las actualizaciones nuevas requieren soporte en la política de Kit CUE integrada; la recuperación de una operación existente sigue su diario y punto de control firmados.

```bash
stackkit kit upgrade [flags]
```

| Flag | Tipo | Predeterminado | Descripción |
| --- | --- | --- | --- |
| `--dry-run` | bool | — | Verifica e inspecciona la generación del destino en un workspace sombra acotado sin aplicarla. |
| `--json` | bool | — | Emite JSON stackkit.command-result/v1. |
| `--recover` | string | — | Recupera explícitamente un ID exacto de operación de ciclo de vida interrumpida. |
| `--to` | string | `latest` | Destino: latest, vX.Y.Z o channel:stable\|beta\|edge. |

**Ejemplos**

```bash
# Verify the newest stable release and preview its plan and artifact diff without applying it
stackkit upgrade --dry-run

# Upgrade to the newest stable release
stackkit upgrade

# Upgrade to the newest beta prerelease
stackkit upgrade --to channel:beta

# Recover an interrupted upgrade by its lifecycle operation ID
stackkit upgrade --recover <operation-id>
```
