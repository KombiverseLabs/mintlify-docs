StackKits es el estándar de homelab abierto e independiente. Proporciona definiciones de kits portables, la CLI `stackkit` y el conector MCP, y un ciclo de vida local para validar, generar, aplicar y verificar un stack.

StackKits funciona con un host que ya controlas; no requiere una cuenta de kombify ni un endpoint alojado de kombify.

## Documentación específica de cada release

Consulta el [catálogo de casos de uso](/es/stackkits/reference/use-case-catalog), la [compatibilidad de SO](/es/stackkits/reference/os-compatibility) y la [compatibilidad de entrega de aplicaciones](/es/stackkits/reference/application-delivery-compatibility) para ver los componentes listados y la compatibilidad declarada. Cada referencia identifica y enlaza el release publicado que describe. La compatibilidad de SO y la columna Lifecycle test de la compatibilidad de entrega de aplicaciones proceden de ejecuciones automatizadas del ciclo de vida de ese release en máquinas virtuales nuevas: install, init, generate, apply, verify, backup y restore. El catálogo de casos de uso y las capacidades de adaptador declaradas no son evidencia de despliegue ni de verificación en un host real.

Las guías y los ejemplos que nombran una versión describen esa versión. No des por sentado que un ejemplo antiguo se haya verificado con un release más reciente.

## Definiciones de kits

<CardGroup cols={3}>
  <Card title="Basement Kit" icon="house" href="/es/stackkits/kits/basement-kit">
    El kit local actual de un solo entorno para hardware de tu casa o de tu red privada.
  </Card>
  <Card title="Cloud Kit" icon="cloud" href="/es/stackkits/kits/cloud-kit">
    Una definición publicada de un solo entorno para un VPS o un host en la nube existente que operas.
  </Card>
  <Card title="Modern Homelab (alfa)" icon="network-wired" href="/es/stackkits/kits/modern-homelab">
    Un archivo de definición alfa que abarca Home y Cloud; hoy se valida y se genera, pero aún no es un destino de instalación.
  </Card>
</CardGroup>

Modern Homelab se distribuye en cada release como un archivo de definición alfa para creación y validación; no es una vía de instalación.

Elige el kit según el entorno que controlas, no según el número de servicios que quieres ejecutar.

La primera vía independiente correcta está en la [Guía de inicio rápido](/es/stackkits/quickstart).

## Lo que StackKits no hace

- crear ni comprar un servidor por ti
- guardar credenciales de proveedor ni gestionar recursos del proveedor
- requerir un plano de control alojado para el Standard Mode
- sustituir al propietario local ni a la evidencia que produce el ciclo de vida independiente
