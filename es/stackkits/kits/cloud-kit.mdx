Cloud Kit se incluye en el release público actual (v0.35.x) como vista previa. Ninguna ejecución automatizada del ciclo de vida cubre aún un VPS público, así que [Compatibilidad de SO](/es/stackkits/reference/os-compatibility) lo lista como `unverified`. Usa el mismo ciclo de vida de creación independiente que Basement Kit, pero está pensado para un host en la nube existente con DNS público y TLS bajo tu control.

<Note>
  El release incluye la definición y el instalador de Cloud Kit. Trata el arranque de la configuración y la evidencia de runtime en vivo específica del release como afirmaciones separadas.
</Note>

## Antes de empezar

Prepara esto fuera de StackKits:

- un host ya disponible que estés autorizado a operar
- un dominio y registros DNS que controles
- una postura de host y de red adecuada para servicios públicos

StackKits valida y aplica su propia definición de sistema en ese host. No aprovisiona un servidor, no selecciona un proveedor ni guarda credenciales de proveedor.

## Inicia un Cloud Kit

Arranca el workspace publicado en Linux o macOS:

```bash
curl -sSL https://cloud.stackkit.cc | DOMAIN=example.com sh
cd ~/my-cloud-homelab
```

Usa un dominio de tu propiedad en lugar de `example.com`. Conserva la StackSpec y la salida de verificación junto al workspace, y cambia solo la StackSpec antes de regenerar los artefactos.

Si ya tienes la CLI, [elige un kit](/es/guides/stackkits/choosing-a-kit) y [configura la StackSpec](/es/guides/stackkits/configure-stack-spec).
