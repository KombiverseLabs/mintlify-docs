<Info>
  证据状态（2026-09-24，v0.41.0）：自动化为 `planned`。它没有发布版本，也没有日期，发布目录中还没有对应条目。本页描述的是仍在评审中的设计方向，而不是你现在就能安装的东西。
</Info>

自动化目前还不是可以选择的使用场景。团队正在评估一款自托管的工作流引擎，它把你的其他使用场景连接起来，并以有限的权限运行经过审查的例行任务。

## 规划中的设计

| 候选 | 角色 | 说明 |
| --- | --- | --- |
| [n8n](https://n8n.io/) | 首选的首个引擎 | 以其 [Sustainable Use License](https://github.com/n8n-io/n8n/blob/master/LICENSE.md) 分发，在其规定的条件下允许个人、非商业和内部业务使用。它不是通用的宽松开源许可证，因此在商业或托管使用之前请先核对许可证。 |
| [Activepieces](https://www.activepieces.com/) | 备选 | 核心采用 MIT 许可证；部分企业功能适用单独的许可证。 |
| [Node-RED](https://nodered.org/) | 专项候选 | 考虑用于基于流程的家庭和 IoT 自动化。 |
| [Windmill](https://www.windmill.dev/) | 专项候选 | 考虑用于以脚本和代码为先的工作流。 |

## 你可以期待什么

- 起点是单一的工作流引擎，而不是四个工具同时上线。
- 配方需要明确的批准和限定范围的凭据；自动化不会仅仅因为运行在同一个 kit 上，就获得访问其他使用场景的权限。
- 有限的、经过审查的入门例行任务，先于开放式的工作流画布。

请查看 [StackKits 更新日志](/zh-Hans/changelog/overview)或[使用场景目录](/zh-Hans/stackkits/reference/use-case-catalog)，了解自动化是否已经走出规划阶段。
