StackKits 将应用选择与执行归属分开。Standalone Compose 是原生默认方式。Komodo 是没有应用商店的运维平台。Marketplace 计划作为基于 Coolify 的可选用例；Coolify 是该用例的应用，而不是原生运行时目标。

查看你已安装版本中内嵌的矩阵：

```bash
stackkit app compatibility --json
```

## 选择适配器

| 适配器 | 当前状态 | 适用场景 |
| --- | --- | --- |
| `standalone-compose` | 原生默认 | 使用已安装版本声明的工作负载路径，并检查其生命周期凭据。 |
| [Coolify](/zh-Hans/stackkits/apps/coolify) | 计划中的 Marketplace 应用 | 只有发布的目录包含此用例且生命周期已验证后，才能作为 Marketplace 安装。 |
| [Komodo](/zh-Hans/stackkits/apps/komodo) | 运维平台草案 | 仅在当前固定版本的凭据证明的工作负载范围内显式选择。 |

发布的[应用交付兼容性](/zh-Hans/stackkits/reference/application-delivery-compatibility)矩阵描述声明的适配器契约。历史兼容性行不能证明当前固定版本的支持。请检查所选应用和版本的生命周期凭据；部署能力本身不证明备份或恢复能力。

对于独立的 Basement Kit，除非你有意运营某个应用平台，否则请从 `standalone-compose` 开始：

```json
{
  "workloads": {
    "files": {
      "alternative": "cloudreve",
      "runtimeAdapterRef": "standalone-compose",
      "placement": {
        "siteRefs": ["home"],
        "nodeRefs": ["main"]
      }
    }
  }
}
```

## 每个工作负载只有一个所有者

- 不要同时通过 Coolify 和独立的 Compose 路由同一个工作负载。
- 不要手动添加 Docker 标签或生成的路由。
- 显式 Komodo 路径需要当前固定版本的凭据；它不是默认方式，也不是应用商店。
- 在应用不同的适配器之前，先验证更改后的意图并检查解析后的计划。

平台集成请参见[平台服务](/zh-Hans/stackkits/apps/overview)，完整的编辑流程请参见[配置 StackSpec](/zh-Hans/guides/stackkits/configure-stack-spec)。
