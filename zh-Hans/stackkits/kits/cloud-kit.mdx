Cloud Kit 作为预览版包含在当前公开版本（v0.35.x）中。目前还没有自动化的生命周期运行覆盖公共 VPS，因此[操作系统兼容性](/zh-Hans/stackkits/reference/os-compatibility)将其列为 `unverified`。它使用与 Basement Kit 相同的独立创作生命周期，但面向的是一台由你掌控公共 DNS 和 TLS 的现有云主机。

<Note>
  该版本包含 Cloud Kit 定义和安装程序。请将配置引导与特定版本的实时运行时证据视为相互独立的声明。
</Note>

## 通俗地说

Cloud Kit 适用于你租用并且已在运营的服务器（例如虚拟专用服务器），并且你希望通过自有域名下的名称来访问它。当你的 homelab 应当运行在那台服务器上而不是家中的电脑上时，它就是合适的套件。如果你从未设置过服务器，请先阅读[开始之前](/zh-Hans/guides/stackkits/before-you-start)；Basement Kit 是更温和的起点。

## 开始之前

请在 StackKits 之外准备好以下内容：

- 一台你有权操作的现成主机
- 你所掌控的域名和 DNS 记录
- 适合公共服务的主机和网络安全态势

简而言之，你需要先准备：

1. 对主机的命令行访问权限，并有权限运行安装程序。
2. 域名，以及其 DNS 设置的访问权限。
3. 决定哪些端口和服务可以从互联网访问。
4. 一个用于保存设置所创建的访问详情的私密位置。

StackKits 会在该主机上验证并应用它自己的系统定义。它不会预配服务器、选择提供商，也不保存提供商凭据。

## 启动 Cloud Kit

在 Linux 或 macOS 上引导已发布的工作区：

```bash
curl -sSL https://cloud.stackkit.cc | DOMAIN=example.com sh
cd ~/my-cloud-homelab
```

请用你自己拥有的域名替换 `example.com`。请将 StackSpec 和验证输出与工作区放在一起，并且在重新生成产物之前只修改 StackSpec。

每个部分之后，你应当看到以下结果：

1. 该命令会创建工作区文件夹 `~/my-cloud-homelab` 并将你带入其中。
2. 该文件夹中的 StackSpec 写明了你的域名。在更改主机之前请先检查它。
3. 验证输出会告诉你部署是否与计划一致。请使用与 [CLI 演练](/zh-Hans/guides/stackkits/cli-walkthrough)和[审查计划并应用](/zh-Hans/guides/stackkits/review-plan-and-apply)相同的步骤。
4. 打开输出中的 Node Hub 地址，并按照 [Node Hub 指南](/zh-Hans/guides/stackkits/node-hub)所述完成保护。

如果你已有 CLI，请[选择一个套件](/zh-Hans/guides/stackkits/choosing-a-kit)并[配置 StackSpec](/zh-Hans/guides/stackkits/configure-stack-spec)。

## 什么存放在哪里

配置（StackSpec）、验证输出和访问详情保存在你主机上的工作区文件夹中，因此请保持该文件夹私密。你的域名和 DNS 记录由你和你的提供商掌管，StackKits 不保存提供商凭据。请通过[备份与恢复](/zh-Hans/guides/stackkits/back-up-and-restore)规划备份。

## 出现问题时

- 某个名称打不开：检查你域名的 DNS 记录是否指向该主机，然后将地址与 Node Hub 中的地址对比。参见[故障排查](/zh-Hans/guides/stackkits/troubleshooting)。
- 安装程序因错误而停止：用 `stackkit logs latest --json` 读取日志，并检查[操作系统兼容性](/zh-Hans/stackkits/reference/os-compatibility)中你的主机。请记住 Cloud Kit 是预览版。
- 设置完成后的日常使用，参见[日常使用](/zh-Hans/guides/stackkits/daily-use)。
