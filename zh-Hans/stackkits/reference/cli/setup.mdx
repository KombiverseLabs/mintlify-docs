设置已应用应用的 Owner 账号。

在现有的本地应用上运行 Plan 声明的设置操作。私有凭据的 JSON 字段和文件路径，请从所选应用的设置指南或状态操作中读取。凭据绝不会写入生命周期证据。中断后重新运行时，会先重新观察该应用，再完成同一个待处理的设置操作。

```bash
stackkit setup <workload> [flags]
```

| 标志 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--complete-onboarding` | bool | — | 在验证 Owner 登录之后，完成应用用户和管理员的引导 |
| `--credentials-file` | string | — | 工作区相对路径的私有 Owner 凭据 JSON 文件（默认取所选应用的设置指南） |
| `--json` | bool | — | 输出不含密钥的已验证设置结果 |
| `--operation-id` | string | — | 继续一个待处理的设置操作；默认为当前待处理的设置，或新建 ID |
| `--owner-approve` | bool | — | 批准此与 Plan 绑定的应用设置 |

**示例**

```bash
# Create the Photos owner from the private credentials in .stackkit/setup/owner.json
stackkit setup photos --owner-approve

# Also finish the application's onboarding after the owner login is verified
stackkit setup photos --owner-approve --complete-onboarding

# Create the Files owner from a workspace-relative credentials file of your choice
stackkit setup files --owner-approve --credentials-file private/files-owner.json
```
子命令：[`stackkit setup ai-connect`](#stackkit-setup-ai-connect), [`stackkit setup ai-provider`](#stackkit-setup-ai-provider), [`stackkit setup connector`](#stackkit-setup-connector)

## stackkit setup ai-connect

将 Private AI 的 Ollama 作为自有模型端点连接到你的 kombify AI。

开启 Private AI 用例的可选 kombify AI 连接器。在 Companion Studio（Settings、AI access、Model endpoints）中创建一个源为 http://ollama:11434 的模型端点，并复制其连接器令牌。此命令从标准输入或 `--token-file` 读取令牌，绝不从参数读取；它会检查令牌格式，将令牌保存在本地 Owner 托管中，然后开启连接器。下一次 generate 和 apply 会在 Ollama 旁启动出站连接器。不会开放任何入站连接，Ollama 仍不会被公开。

`--disable` 会关闭连接器，并从本地托管中移除令牌。在 Companion Studio 中撤销该端点，可使令牌在任何地方都无法使用。

```bash
stackkit setup ai-connect [flags]
```

| 标志 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--disable` | bool | — | 关闭连接器，并从本地托管中移除其令牌 |
| `--json` | bool | — | 输出不含秘密的结果 |
| `--token-file` | string | — | 包含连接器令牌的文件；"-" 或不指定此标志时从标准输入读取 |

**示例**

```bash
# Paste the connector token, then press Enter and Ctrl-D (or read it hidden on a terminal)
stackkit setup ai-connect --token-file -

# Read the token from a private file
stackkit setup ai-connect --token-file ~/kombify-connector-token

# Turn the connector off and remove its token
stackkit setup ai-connect --disable
```

## stackkit setup ai-provider

在 Private AI 中提供一个外部的 OpenAI 兼容提供方，其密钥来自你的 kombify Wallet。

让 Private AI 用例的 Open WebUI 在节点自带的 Ollama 之外，也使用外部的 OpenAI 兼容推理提供方（例如 OpenAI、Mistral、Groq 或 OpenRouter）。提供方的 API 密钥不会经过此命令、StackSpec 或生成的 bundle：请将其作为 AI 凭据保存在你的 kombify Wallet 中，在该项目上允许此节点，并通过 "stackkit wallet-item import" 将其密封交付到此节点。此命令将提供方密钥绑定到已交付的项目，并设置提供方的 https 基础 URL。之后每次 apply 都会读取最新交付的版本，因此在 Wallet 中轮换后，对轮换后的项目执行 "stackkit wallet-item import" 并进行下一次 apply 即可生效。当该项目不在此节点的托管中时，apply 会失败关闭。

`--disable` 会将提供方从 Open WebUI 中移除，并从本地托管中删除绑定。已交付的项目仍保留在节点的 Wallet 项目托管中。

```bash
stackkit setup ai-provider [flags]
```

| 标志 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--base-url` | string | — | OpenAI 兼容提供方 API 的 https 基础 URL |
| `--disable` | bool | — | 移除外部提供方及其密钥绑定 |
| `--json` | bool | — | 输出不含密钥的 stackkit.command-result/v1 结果 |
| `--tenant-ref` | string | — | 交付该 Wallet 项目所在的租户 |
| `--wallet-item` | string | — | 已交付提供方密钥的 Wallet 项目引用 |

**示例**

```bash
# Bind the provider key delivered as Wallet item itm_... and set the provider
stackkit setup ai-provider --base-url https://api.openai.com/v1 --tenant-ref "$TENANT" --wallet-item itm_abc...

# Remove the provider
stackkit setup ai-provider --disable
```

## stackkit setup connector

签发、撤销或验证确切的本地 Home Assistant 连接器。

```bash
stackkit setup connector [flags]
```

| 标志 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--json` | bool | — | 输出经认证的确切签名回执字节和当前本地事实 |
| `--operation-id` | string | — | 确切的稳定连接器设置操作标识 |
| `--owner-approve` | bool | — | 批准此确切的连接器确保或撤销请求 |
| `--request-file` | string | — | 工作区相对路径的私有、仅含元数据的连接器请求 JSON；绝不包含凭据 |
| `--verify-only` | bool | — | 读取并根据当前本地绑定验证已保留的回执，不签发或撤销 |
| `--workload` | string | — | 确切的本地工作负载；仅允许 smart-home |
