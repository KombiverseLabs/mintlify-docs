解析并安装经过验证的 StackKit 发布版本。

从 GitHub 解析公开的 StackKit 发布版本，验证其归档、SPDX SBOM、GitHub OIDC/Sigstore 证明以及缓存的可信根，然后原子地将其安装到 .stackkit/releases/ 之下。

使用 `--dry-run` 时，它只在有界的影子工作区中生成经过验证的目标，并报告规范的计划/产物差异。不使用 `--dry-run` 时，它会先检查该目标，创建原生 Kopia 快照以及经 Owner 签名的执行器状态恢复检查点，暂存并验证回滚数据但不激活，然后才安装并执行确切目标的 generate/apply/verify 事务。失败的目标事务只有在目标 Apply 被准入之前，才能恢复并验证先前的执行器。Apply 之后，在存在经验证的先前数据激活之前，会阻止先前运行时的重启；仅有隔离的 Kopia 暂存并不能授权重启。已完成的目标提交会保留其成功证明，以便显式收尾。全新升级需要内嵌 CUE Kit 策略的支持；现有操作的恢复则遵循其已签名的日志和检查点。

```bash
stackkit upgrade [flags]
```

| 标志 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--dry-run` | bool | — | 在有界的影子工作区中验证并检查目标的生成，但不应用。 |
| `--json` | bool | — | 输出 stackkit.command-result/v1 JSON。 |
| `--recover` | string | — | 显式恢复一个确切的被中断的生命周期操作 ID。 |
| `--to` | string | `latest` | 目标：latest、vX.Y.Z，或 channel:stable\|beta\|edge。 |

**示例**

```bash
# Verify the newest stable release and preview its plan and artifact diff without applying it
stackkit upgrade --dry-run

# Upgrade to the newest stable release
stackkit upgrade

# Upgrade to the newest beta prerelease
stackkit upgrade --to channel:beta

# Recover an interrupted upgrade by its lifecycle operation ID
stackkit upgrade --recover <operation-id>
```
