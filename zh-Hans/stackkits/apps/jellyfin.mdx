Jellyfin 在独立 Compose 主机上通过 `media` 工作负载提供[媒体](/zh-Hans/guides/stackkits/use-cases/media)用例。请在你的 [Basement Kit](/zh-Hans/stackkits/kits/basement-kit) 基线验证通过之后再设置它。使用 `stackkit app compatibility --json` 可以查看所安装版本的适配器能力。

## 它是什么

Jellyfin 是用于你所拥有的电影、音乐和家庭视频的媒体服务器。它会扫描你的文件，以带有封面和简介的整洁图库形式展示，并将其串流到家中的电视、手机和电脑。StackKit 包含它，是为了让你的家人无需订阅服务就能观看自己的收藏。

## 哪些套件和用例包含它

Jellyfin 是媒体用例的默认应用，作为可选的 `media` 工作负载交付在独立 Compose 主机上，需在你的 [Basement Kit](/zh-Hans/stackkits/kits/basement-kit) 基线验证通过之后。Coolify 和 Komodo 出现在 `media` 的兼容性表中，但不具备备份和恢复。

## 如何打开

打开 CLI 打印的或 [Node Hub](/zh-Hans/guides/stackkits/node-hub) 中列出的、已声明的私有 Media 路由。默认本地域名为 `home.test`；该名称必须能在你用来观看的每台设备上解析。

## 将工作负载指向现有的媒体目录

要使用现有的媒体库，请在生成并应用栈之前，把 StackSpec 中的 `storage.mediaRoot` 设置为运行时主机上媒体所在的绝对目录，例如 `/srv/household-media`：

- StackKits 会将该目录以只读方式绑定到 `/media`。Jellyfin 可以扫描并串流这些文件，但不能编辑或删除它们。
- 该目录必须已经存在。StackKits 不会创建它，也不会更改其权限；目录缺失会导致交付失败，因此请自行准备并保护主机存储。
- 不设置 `storage.mediaRoot`，则保留由计划管理的命名媒体库卷。
- 该路径指的是运行时主机上的存储，而不是运行远程观看端的那台机器上的存储。

## 设置所有者账户

创建一个私有的、位于工作区内的凭据文件 `.stackkit/setup/media-owner.json`：

```json
{
  "username": "<your administrator name>",
  "password": "<your unique password>"
}
```

将该文件限制为仅工作区所有者可访问，并且不要把其内容放入命令参数或聊天消息中。然后运行：

```bash
stackkit setup media --credentials-file .stackkit/setup/media-owner.json --owner-approve --json
```

该命令在执行之前，会验证当前计划、已签名的 Apply、确切的本地容器以及固定的 Jellyfin 版本。首次运行时，它会设置你所选择的管理员凭据——绝不会使用默认的首位用户密码。在已有的安装上，它会改为执行一次普通登录和管理员回读。临时的设置会话会在已签名的结果被记录之前撤销。

## 完成向导并添加媒体库

如果不加其他标志，未完成的 Jellyfin 启动向导会保持未完成：请在其已声明的私有路由打开 Media，自行选择媒体库路径、语言和家庭设置。若希望使用当前应用设置完成启动向导，之后再配置媒体库，请添加 `--complete-onboarding`：

```bash
stackkit setup media --credentials-file .stackkit/setup/media-owner.json --owner-approve --complete-onboarding --json
```

该标志只会完成启动向导。它不会添加媒体库、更改远程访问设置，也不会配置转码。添加媒体库时，请遵循计划中的媒体卷映射——即所有者托管目录对应的只读 `/media` 挂载。请为家庭观众创建各自独立的非管理员 Jellyfin 账户，并让每个播放器直接连接到已声明的 Media URL。

## 首次使用

1. 在主机上准备好你的媒体目录，并在 StackSpec 中设置 `storage.mediaRoot`。
2. 应用该栈并运行上面的所有者设置命令。
3. 打开 Media 路由，并使用你选择的管理员账户登录。
4. 添加一个遵循计划卷映射的媒体库。
5. 为家庭观众创建各自独立的非管理员账户。

## 恢复限制

应用配置与媒体字节是分别托管的：

- Jellyfin 的配置和转码缓存位于不同的卷中。请查看应用备份声明以了解包含的数据；可写存储本身并不意味着备份覆盖。
- 你的媒体源不是 StackKits 备份。无论你为 `storage.mediaRoot` 设置了什么，都要为这些字节保留一个独立的恢复来源，并在栈之外记录下来。
- 容器健康以及已验证的管理员设置，并不能证明媒体库内容或可恢复性；请显式检查这两者。

## 在真实客户端上测试

请在预期使用的客户端上，测试播放你自己的一个文件。先检查直接播放，仅在你明确配置了转码时才检查转码。健康的容器并不能证明客户端兼容性、带宽和转码质量——请在你实际打算观看的设备上验证。

## 预期情况

扫描大型媒体库需要时间。容器健康并不能说明在特定电视或手机上的播放情况，因此请测试你实际打算使用的设备。

## 出现问题时

- 交付立即失败：媒体目录缺失。StackKits 不会创建它；请准备好主机存储后重新应用。
- 播放器无法连接：确认它使用的是已声明的 Media URL，并且该名称能在该设备上解析。
- 播放卡顿：先检查直接播放，仅在你配置了转码时才检查转码。
- 另请参见[故障排查](/zh-Hans/guides/stackkits/troubleshooting)。

## 恢复被中断的设置

如果某次设置运行被中断，请使用报告的 `--operation-id` 重试。该命令会重新检查应用状态，绝不会重新打开已经完成的启动向导。
