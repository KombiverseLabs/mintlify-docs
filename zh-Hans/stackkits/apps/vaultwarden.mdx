Vaultwarden 提供[密码](/zh-Hans/guides/stackkits/use-cases/passwords)用例。它是可选的原生 v2 `vault` 工作负载的已发布备选方案，初始的 Basement 和 Cloud StackSpec 不会启用它。

## 它是什么

Vaultwarden 是一个小型服务器，把你家庭的密码和安全笔记保存在你自己运行的机器上。它与 Bitwarden 使用相同的协议，因此每个人都使用常规的 Bitwarden 应用和浏览器扩展，只需将它们指向你自己的服务器。StackKit 包含它，是为了让家人不必把密码托付给第三方。

## 哪些套件和用例包含它

Vaultwarden 是 Vault 用例中 Passwords 体验的默认应用。已发布的目录在独立 Compose 上为 Basement Kit 和 Cloud Kit 提供它。它是可选的，需要你自己选择。

## 已发布的契约

| 属性 | 值 |
| --- | --- |
| 工作负载 | `vault` |
| 备选方案 | `vaultwarden` |
| 数据类别 | secret |
| 必需的密钥引用 | `admin-token` |
| 支持的独立适配器 | `standalone-compose` |

`admin-token` 槽位保存一个不透明的 `secret://` 引用；实际的令牌保留在本地所有者托管中。请在 [StackSpec](/zh-Hans/guides/stackkits/configure-stack-spec) 中选择工作负载、放置位置和适配器，然后按照[添加工作负载](/zh-Hans/stackkits/reference/day-2-operations#向现有工作区添加工作负载)进行验证、建立托管、生成、检查计划、应用并验证。

## 如何打开

部署后，打开 CLI 打印的或 [Node Hub](/zh-Hans/guides/stackkits/node-hub) 中列出的、生成的 Passwords 地址。默认本地域名为 `lab.home`，该名称必须能在你使用的设备上解析。Bitwarden 应用需要把这同一个地址作为其服务器 URL。

## 首次使用

1. 在添加真实密钥之前，先创建应用所有者账户并选择注册策略。
2. 接受邀请后，完成账户注册，并通过你的 Bitwarden 客户端登录。
3. 创建并同步一个密码库条目，以确认账户已就绪。仅有邀请并不能完成此设置。

[密码](/zh-Hans/guides/stackkits/use-cases/passwords)页面说明了如何让 Bitwarden 客户端指向你自己的服务器，[设置你的密码管理器应用](/zh-Hans/guides/stackkits/use-cases/passwords/clients)则面向你家庭中的成员逐步演示。

## 备份内容

恢复流程涵盖 Vaultwarden 数据卷，其中保存着密码库数据库和附件。请将你的恢复材料保存在服务器之外。在密码库保存无法重新创建的密钥之前，请确认你的备份覆盖了该卷，并通过[备份与恢复](/zh-Hans/guides/stackkits/back-up-and-restore)演练一次分阶段恢复。恢复后的应用级回读在已发布的证据中仍处于待定状态。

## 预期情况

密码库体积小且始终在运行。一个人只有在 Bitwarden 客户端中注册、登录并同步一个条目之后，才算准备就绪。主密码由选择它们的人自行保管。

## 出现问题时

- Bitwarden 应用无法连接服务器：检查服务器 URL 是否为你生成的 Passwords 地址，并确认该名称能在该设备上解析。参见[故障排查](/zh-Hans/guides/stackkits/troubleshooting)。
- 某人有邀请但无法登录：只有在官方 Bitwarden 客户端完成注册之后，该账户才算完整。
- 浏览器对连接发出警告：不要点击跳过你不理解的警告。将地址与 Node Hub 中的地址对比。

对于已经准入的工作负载，请通过 StackSpec 和生命周期命令更改 StackKits 意图；不要在目标上编辑生成的应用配置。
