Immich 提供[照片](/zh-Hans/guides/stackkits/use-cases/photos)用例。它是可选的原生 v2 `photos` 工作负载的已发布备选方案，初始的 Basement 和 Cloud StackSpec 不会启用它。选择它之前，请先在“照片”页面规划存储和恢复。

## 它是什么

Immich 是运行在你自己主机上的照片和视频库。它的作用与云端照片服务相同：手机应用上传新照片，你在网页图库中浏览、搜索和分享。StackKit 包含它，是为了让你家人的照片保存在你所掌控的硬件上。

## 哪些套件和用例包含它

Immich 是 Photos 用例的默认应用。已发布的目录在独立 Compose 上为 Basement Kit 和 Cloud Kit 提供它；Cloud Kit 是预览版，尚无自动化的生命周期运行。Coolify 和 Komodo 也出现在 `photos` 的兼容性表中，但不具备备份和恢复。

## 已发布的契约

| 属性 | 值 |
| --- | --- |
| 工作负载 | `photos` |
| 备选方案 | `immich` |
| 数据类别 | personal |
| 必需的密钥引用 | `database-password` |
| 支持的独立适配器 | `standalone-compose` |

已发布的 CLI 会验证并生成这一工作负载契约，包括持久的照片和数据库分配，以及生成的 Photos 路由。[用例目录](/zh-Hans/stackkits/reference/use-case-catalog)展示了该版本所声明的组件。

`database-password` 槽位保存一个不透明的 `secret://` 引用；其密码由本地所有者托管保管。请在 [StackSpec](/zh-Hans/guides/stackkits/configure-stack-spec) 中选择工作负载、放置位置和适配器，然后按照[添加工作负载](/zh-Hans/stackkits/reference/day-2-operations#向现有工作区添加工作负载)进行验证、建立托管、生成、检查计划、应用并验证。

## 如何打开

打开 CLI 打印的或 [Node Hub](/zh-Hans/guides/stackkits/node-hub) 中列出的、生成的 Photos 路由。默认本地域名为 `home.test`，该名称必须能在你的设备上解析。手机应用要求填写的服务器地址也是同一个地址。

## 首次使用

1. 在一次已具备有效的、绑定所有者的托管的部署之后，完成 StackKits 验证。
2. 从 Node Hub 或部署输出中打开生成的 Immich 地址。
3. 创建应用所有者账户，并且只在确认存储容量和备份之后再连接客户端。
4. 使用[从手机备份照片](/zh-Hans/guides/stackkits/use-cases/photos/phone-backup)连接每一部手机。

任何配置更改之后，请再次验证 StackKits 工作区。

## 备份内容

恢复既需要原始照片和视频，也需要 Immich 数据库；缺少任何一部分都不是完整的恢复。照片原件属于 `media` 覆盖组，该组是需要选择而非继承的，因此首个快照不会悄悄包含庞大的图库。运行 `stackkit backup status --json` 即可确切看到下一个快照包含哪些卷，并通过[备份与恢复](/zh-Hans/guides/stackkits/back-up-and-restore)演练一次分阶段恢复。恢复后的应用级回读，最近一次是在 v0.33.3 上针对备份周期验证的；请参见该页面上的证据说明。

## 预期情况

照片库通常是 homelab 中最大的数据集，并且会持续增长，因此请根据照片和视频的增长来规划主存储和备份存储。大相册首次从手机上传可能需要一段时间；首次检查时，用一个只含一张备用照片的小相册就足够了。

## 出现问题时

- 地址打不开：将其与部署输出对比，并确认该名称能在设备上解析。参见[故障排查](/zh-Hans/guides/stackkits/troubleshooting)。
- 手机无法登录：使用你在网页图库中创建的 Immich 账户；它不是你的 kombify 账户。
- 测试照片没有到达：检查所选相册和应用的照片访问权限，然后按照[从手机备份照片](/zh-Hans/guides/stackkits/use-cases/photos/phone-backup)操作。
- 存储已满：停止添加照片，并在下一个快照之前解决容量问题。
