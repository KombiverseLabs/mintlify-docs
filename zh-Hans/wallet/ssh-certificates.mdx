你不必再把 SSH 密钥复制到每台服务器和每个人手里，而是在你的 Wallet 中保管一个证书颁发机构。你的服务器信任它的公钥。当你、代理或产品需要登录时，Wallet 会为那把密钥签发一张证书，按你允许的名称和时长生效。证书到期后访问即告结束，而颁发机构自己的密钥永远不会离开 Wallet。

## 创建颁发机构

1. 打开**设置**，选择**密钥与连接**，然后选择**添加条目**。
2. 选择类型 **SSH 证书颁发机构**，并输入**名称**。
3. 在**证书颁发机构密钥**下，选择**在 Wallet 中创建（推荐）**。Wallet 会生成一把新的 Ed25519 密钥并保管它。该密钥不会到达你的浏览器。或者选择**导入现有密钥**，导入一把未加密、没有密码短语的 Ed25519 OpenSSH 密钥。
4. 设定签发策略（见下文），然后选择**保存到 Wallet**。

## 设定签发策略

在**此证书颁发机构可以签发的内容**下，你为每张证书设定限制：

- **证书类型**：**用户证书**供登录服务器的人员和代理使用，**主机证书**供服务器证明自己的身份。代理永远不会收到主机证书。
- **用户证书的最长有效期**：从 1 分钟到 1 天，例如 `30m` 或 `8h`。
- **主机证书的最长有效期**：从 1 分钟到 366 天，例如 `90d`。
- **允许的主体（principal）**：证书可以携带的用户名或服务器名，每行一个或用逗号分隔。`*.example.com` 表示 `example.com` 前恰好多一个名称，例如 `web1.example.com`。
- **用户证书的扩展**：只有你勾选的扩展才能出现在用户证书中。`permit-pty` 允许交互式终端。
- **要求来源地址**：这样每张用户证书都必须写明它可用的来源地址。

没有策略时，颁发机构不会签发任何内容。你可以在该条目的**设置**中更改策略，更改从下一张证书起生效。策略不能被移除。若要让某个颁发机构停止签发，请撤销它。

## 在你的服务器上信任公钥

颁发机构的**公钥**显示在列表中，旁边有**复制**按钮。`kombify-wallet get my-ca` 也会输出它。对于由 kombify StackKits 设置的服务器，公钥计划由系统替你安装；该集成尚未发布。对于其他任何服务器，请自行信任它：

1. 在服务器上，将公钥作为一行保存到 `/etc/ssh/kombify_user_ca.pub`。
2. 将这一行添加到 `/etc/ssh/sshd_config`：

   ```text
   TrustedUserCAKeys /etc/ssh/kombify_user_ca.pub
   ```

3. 重新加载 SSH 服务：

   ```bash
   sudo systemctl reload ssh
   ```

   在某些系统上，该服务名为 `sshd`。

默认情况下，当证书的某个主体等于你登录时使用的账户名，服务器就会接受它。主体为 `deploy` 的证书允许持有者以 `deploy` 身份登录。

## 为你的密钥签发证书

在 **Wallet** 部分，对该颁发机构选择**签发证书**。

1. 在**你的公钥**下粘贴你的公钥。请使用你的 `.pub` 文件的内容，例如 `~/.ssh/id_ed25519.pub`，切勿使用私钥。支持 Ed25519、ECDSA P-256 以及 2048 位及以上的 RSA 密钥。
2. 选择**证书类型**，用于登录服务器时选**用户证书**。
3. 输入**主体（principal）**，例如 `deploy`。
4. 输入**有效期**，例如 `8h`。它不能超过策略的最大值。
5. 如果策略要求，请输入**来源地址**。
6. 选择**签发证书**，然后选择**复制证书**或**下载**。

将证书保存在私钥旁边，例如保存为 `~/.ssh/id_ed25519-cert.pub`，然后照常登录。OpenSSH 会自动找到它。

你也可以在终端中完成同样的操作。该命令会把证书写到你的密钥旁边：

```bash
kombify-wallet ssh-sign my-ca ~/.ssh/id_ed25519.pub --principals deploy --ttl 8h
```

要查看证书允许什么以及何时到期：

```bash
ssh-keygen -L -f ~/.ssh/id_ed25519-cert.pub
```

## 主机证书

主机证书让服务器证明自己的身份，这样你就不必手动核对它的密钥。将服务器的主机公钥复制到你的电脑，然后用 `--host` 为它签发：

```bash
kombify-wallet ssh-sign my-ca ssh_host_ed25519_key.pub --principals server.example.com --ttl 90d --host
```

将生成的 `ssh_host_ed25519_key-cert.pub` 复制回服务器，并将这一行添加到 `/etc/ssh/sshd_config`：

```text
HostCertificate /etc/ssh/ssh_host_ed25519_key-cert.pub
```

在你的电脑上，在 `~/.ssh/known_hosts` 中加入下面这一行，即可信任由该颁发机构签发的服务器，其中的密钥是该颁发机构的公钥：

```text
@cert-authority *.example.com ssh-ed25519 AAAA...
```

## 访问何时结束

证书到期时访问即告结束。证书的有效期是几分钟到几小时，不超出你策略的限制。撤销颁发机构会立即停止签发新证书，但已经签发的证书在到期前仍然有效。目前还没有证书吊销列表。

颁发机构没有新版本，因为服务器信任的是它的密钥。要替换它，请创建一个新的颁发机构，在迁移期间同时信任两把公钥，然后撤销旧的那个。
