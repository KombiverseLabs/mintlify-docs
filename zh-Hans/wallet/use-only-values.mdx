大多数密钥是用来使用的，而不是用来读取的：API 密钥会被放进请求标头。采用代理调用（brokered use）时，由 Wallet 亲自发起调用。调用方说明想调用什么，Wallet 添加凭据并发送请求，调用方只得到响应。该值永远不会到达调用方。

## 选择谁可以查看该值

在条目的**设置**中，或在添加条目时，**谁可以查看该值**提供两种选择：

- **拥有读取权限的代理和人员可以查看该值。** 这是默认设置。你可以随时查看该值。代理只有在拥有读取权限时才能看到它。
- **任何人都看不到该值，只能使用它。** 连你也无法查看，因此之后你无法把它从 Wallet 中复制出来。拥有使用权限的代理和产品只能用它执行操作，例如在 API 调用中。该条目会显示**仅可使用**标记。

## 设置使用目标

使用目标说明某个值可以发送到哪里。在**使用目标**下通过**添加目标**来添加目标。每个目标包含：

- **主机**：小写的主机名，例如 `api.example.com`，需要时带端口。不要加 `https://` 或路径。不接受 IP 地址。
- **方法**：GET、HEAD、POST、PUT、PATCH 和 DELETE 中的任意几项。
- **路径前缀**：调用可发往此路径或其下的路径，例如 `/v1`。
- **该值的发送方式**：**Authorization 标头，Bearer**、**你选择的标头**（并填写**标头名称**），或针对登录信息的**使用用户名和密码的 Basic 认证**。

一个条目最多可有 16 个目标。没有目标时，该值无法在调用中使用。API 密钥、令牌和证书、登录信息以及服务器访问都可以设置目标。

## Wallet 如何处理一次调用

1. 拥有使用权限的代理或产品请求 Wallet 用某个方法调用一个 URL。
2. Wallet 将请求与你的目标进行比对。主机、方法和路径必须全部匹配某一个目标，否则拒绝。
3. Wallet 记录该操作，按目标规定的方式添加该值，并通过 HTTPS 发送请求。
4. 它返回响应，响应中该值的任何副本都会被替换为 `[redacted]`。

调用方不能添加自己的授权标头，Wallet 也不会跟随重定向。请求和响应限制在 1 MiB 以内，并且只返回一组固定的响应标头。

<Note>
脱敏只会移除该值的完全相同的副本。如果某个服务在响应中重复凭据之前对其做了改动，则不在覆盖范围内。
</Note>

谁可以使用某个条目由你决定。参见[代理](/zh-Hans/wallet/agents)和[产品](/zh-Hans/wallet/products)。
