运行 homelab 有许多优秀的工具。本节帮助你找到契合你需求的工具。这只是参考信息，而非排名。每篇详细页面都会说明另一款工具擅长什么、在今天何时是更合适的选择，同时坦诚说明 kombify 目前的局限性。

## 按你的需求选择

| 你想要 | 可考虑的工具 |
| --- | --- |
| 开机即用且自带应用商店的一体化设备 | [Umbrel](https://umbrel.com)、[CasaOS](https://casaos.io) 与 ZimaOS、[HexOS](https://hexos.com) |
| 面向存储的操作系统 | [TrueNAS](https://www.truenas.com)、[Unraid](https://unraid.net)、[Synology DSM](https://www.synology.com) |
| 面向虚拟机的虚拟化管理程序 | [Proxmox VE](https://www.proxmox.com) |
| 容器与 Compose 项目管理工具 | [Portainer](https://www.portainer.io)、[Dockge](https://github.com/louislam/dockge)、[Komodo](https://komo.do) |
| 部署自有应用的平台 | [Coolify](https://coolify.io)、[Dokploy](https://dokploy.com)、[Runtipi](https://runtipi.io)、[Cosmos](https://cosmos-cloud.io) |

这些工具之间存在部分重叠，很多人会同时组合使用其中的两三种。

## kombify 的定位

kombify 用一个声明式文件定义整个 homelab。StackKits 将这份定义转化为计划、加以应用并验证结果。登录、每个服务的访问策略、路由、备份和更新都是定义的一部分，并会默认配置妥当。Homelab 负责运行 homelab，而 kombify Cloud 和 kombify AI 均为可选项。同一份定义既可描述家中的服务器，也可描述云上的服务器。

kombify 是位于上述工具之旁或之上的一层。它并不取代虚拟化管理程序、NAS 操作系统或应用平台。

## kombify 目前能做什么

- 通过 Pocket ID 使用通行密钥（passkey）登录，没有默认密码。
- 为每个服务设置明确的访问策略。
- 在切换之前先恢复到隔离的暂存副本。
- 更新前先拍摄快照。
- 从同一份定义完成计划、应用与验证。
- 每次安装都自带一个本地 MCP 服务器，以便你自己的 AI 代理读取并操作 homelab（参见[连接你自己的 AI 代理](/zh-Hans/guides/stackkits/connect-your-ai-agent)）。

## 目前的局限性

- kombify 仍处于 1.0 之前阶段，发布频率较高。
- 兼容性仍在持续验证中。请参阅[系统兼容性](/zh-Hans/stackkits/reference/os-compatibility)。
- 安装需要一台准备好的 Linux 宿主机和一条命令。目前尚无引导镜像。
- kombify 不管理磁盘或 RAID。
- 将你自己的 Compose 项目纳入 homelab 的登录、路由与备份体系尚未实现。
- 目录内容经过精选，详见[使用场景目录](/zh-Hans/stackkits/reference/use-case-catalog)。
- “已连接”与“由 kombify 托管”目前处于预览阶段。
