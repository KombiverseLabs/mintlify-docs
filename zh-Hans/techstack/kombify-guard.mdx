kombify Guard 是每台 kombify 服务器的信任标识。它运行在你家庭实验室的每台服务器上，旨在让服务器的运行可靠、安全且可验证。它让服务器始终绑定于你的 Techstack，只执行你授权的工作，检查各项防护确实到位，并记录发生了什么，即使经历连接中断、重启和更新也是如此。

kombify Guard 是 [Techstack](/zh-Hans/techstack/overview) 的一部分。它不是单独的产品、套餐或价格。本页其余部分简称为 Guard。

<Note>
**公开测试版（Public Beta）。** 本页描述的是 Guard 的设计工作方式。只有当某种配置存在交付证据时，相应能力才算可用；目前公开了哪些内容，请参阅 [Techstack 可用性](/zh-Hans/techstack/availability)。Guard 不承诺正常运行时间保证，不承诺服务器不出故障或不被攻破，也不是端点检测与响应（EDR）。
</Note>

## 为什么它很重要

家庭实验室的可信程度，取决于它所运行的服务器。Guard 旨在把“我希望我的服务器没问题”变成你能看到的证据：

- **绑定于你。** 每台服务器只配对一次，并在每次连接时用它自己的密钥证明身份。分离一台服务器会在所有地方撤销它。
- **安全配置。** 防火墙、SSH 访问、暴力破解防护和安全更新都会对照 StackKits 基线进行检查，无论在家里还是在云端。偏差会被上报，修复只在获得授权时进行。
- **安全遥测。** 健康和安全态势数据只通过经过身份验证的 Guard 通道传输，并且只包含[kombify Guard 会发送什么](/zh-Hans/techstack/guard-telemetry)中列出的内容。
- **随处可访问。** 每个安装都可以通过你自己的域名或 `*.kombify.me` 地址访问，本地硬件和租用的服务器同样适用。凭据按服务器签发，并随服务器一同撤销。
- **一个家庭实验室，所有设备。** 装有 Guard 的服务器、通过 Workbench 工作的开发设备以及客户端设备，都是 kombify Connect 中同一个家庭实验室的成员。
- **从设计上保证可恢复。** 结果在断开连接和重启后依然保留，不确定的结果会被如实上报而不是猜测。Guard 的更新经过签名，并会自动回退。

## Guard 向你展示什么

服务器的 Guard 面板显示七项事实。只有在有最新证据支持时，一项事实才算数。缺失或过旧的证据会显示为 **Not evidenced**，绝不会显示为正常；已知的问题显示为 **Needs attention**。只有七项事实全部有证据支持，服务器才是 **Guard-ready**。

| 事实 | 含义 |
| --- | --- |
| Bound | 服务器在每次连接时用自己的密钥证明身份。仍只使用凭据的配置会显示为防护降低。已撤销的服务器不再处于绑定状态。 |
| Connected | Guard 通过其经过身份验证的连接上报。最近没有上报的服务器不算已连接。 |
| Operations durable | Guard 保存持久的操作日志，且没有任何未解决的事项。等待确认的结果和结果未知的操作都会列出。 |
| Configuration secured | 主机符合 StackKits 安全基线，但你批准的例外除外。面板会显示基线版本以及每个偏离基线的控制项。 |
| Up to date | Guard 已签名且为最新版本，操作系统没有待安装的安全更新，也无需重启。 |
| Recoverable | 存在新的备份，并且已验证过一次恢复。只有经过测试的恢复才能证明可以恢复。 |
| Reachable & governed | 服务器已在其 kombify.me 地址注册，并列入 kombify Connect。 |

每项事实都会显示其证据的观察时间，并在出现问题时说明你下一步可以做什么。在你配对服务器时，进度页面会显示 **Bound**、**Connected**、**Configuration verified** 和 **Reachable** 这几个步骤，每一步都对照 Techstack 已记录的内容进行检查。你可以下载或打印 Guard 报告。它只列出 Techstack 已记录的内容及每次观察的时间，不包含任何凭据。

## 配对与身份

[配对命令](/zh-Hans/techstack/pairing-command)只需一次，即可将服务器绑定到你的 Techstack。配对期间，Guard 在服务器上生成自己的密钥，此后使用短期访问令牌证明它持有该密钥。仅凭一个凭据并不能证明是哪台机器在通信。

每个 Guard 只绑定一台服务器，而一个家庭实验室通常有多台。服务器镜像可以自带一个已启用但尚未绑定的 Guard，等待配对。镜像中从不包含你的凭据。

Guard 由两部分构成。Guard 本身以无特权的系统用户身份运行，服务经过加固。需要管理员权限的服务器更改，会通过一个单独的辅助进程执行；该进程只在请求到达时才启动，并且只接受带类型且已获授权的操作。仍采用早期全部以管理员权限运行的布局的服务器，会显示为 **Reduced protection**。这种拆分可以保护 Guard 的凭据，以及服务器免受机器上其他用户和进程的影响。它并不意味着一个被攻破的 Guard 是无害的。

要结束绑定，请在服务器的 Guard 面板中分离该服务器。分离会撤销 Guard 的凭据，并终止服务器的可达性：即它的 kombify.me 地址和它在 kombify Connect 中的列表条目。机器本身以及其上运行的内容不会受到影响。若要再次管理该服务器，请重新配对。随后 Guard 会删除其凭据和本地日志。你也可以轮换服务器的凭据：系统会签发一个替代凭据并只显示一次，旧凭据不再被接受。

## 安全配置

StackKits 定义主机安全基线。Guard 对照基线检查服务器，并将每个控制项报告为合规、偏离、未知或已批准的例外。检查范围包括防火墙、SSH 访问、暴力破解防护、自动与待安装的安全更新、重启状态、内核参数、对外开放的监听端口以及证书到期。对于家庭站点，基线要求具备感知暴露面的防火墙、仅限密钥的 SSH 以及暴力破解防护。

- **未知绝不等于安全。** 证据会过期。未被观察到或证据过旧的控制项算作未知，而不是合规。
- **发现项自带说明。** 每个发现项都会显示控制项、严重程度、预期值与观察值以及修复方法。
- **例外清晰可见。** 例外需要所有者和到期时间，并始终保持列出。
- **偏差会被上报，而不是悄悄修复。** 观察到发现项并不等于授权修复。只有最新证据报告为偏离的控制项才会被修复，并且只在你批准后、在限制范围内进行：一次只修复一项，每个控制项有冷却时间，每日有尝试次数预算，服务器上还有熔断器。StackKits 会拒绝任何会切断 Techstack 访问服务器的途径或把你锁在门外的更改。你可以为一小组安全的控制项（暴力破解防护、防火墙、内核参数和自动更新）批准自动修复。它默认关闭，会到期，并且不会自行续期。SSH 控制项始终由人来处理。

在 Guard 面板中选择 **Verify now**，可重新检查服务器。

## 随处可访问

每台与 Guard 配对的服务器都旨在无需手动密钥，即可通过它自己的 `*.kombify.me` 地址或你自己的域名访问，这与硬件放在家里还是租用无关。这条路径的凭据在配对时按服务器签发，随 Guard 轮换，并在你分离服务器时撤销。请参阅 [kombify.me](/zh-Hans/kombify-me/overview)。

## kombify Connect 中的一个家庭实验室

kombify Connect 为你的家庭实验室提供统一的设备模型。通过 Workbench 工作的开发设备、桌面、移动设备和 Companion 等客户端设备，以及你家庭实验室中的服务器（每台都带有自己的 Guard），都是同一个家庭实验室的成员。在 Public Beta 中，装有 Guard 的服务器会出现在 Connect 的设备视图中，你可以在那里撤销其中一台。被列出并不意味着获得访问权：Connect 中的服务器没有任何可在其上运行工作的路径。在服务器上运行工作的权限仍然属于你的 Techstack。

## 在故障中依然保持可靠的操作

在 Guard 更改任何内容之前，它会先把意图记录到服务器上的持久日志中，并保留每个结果，直到 Techstack 确认已收到。连接中断或重启之后，Guard 会重新投递结果，而不会重复执行更改。如果故障使人无法确定某项更改是否生效，Guard 会报告**未知结果**而不是猜测，并阻止该服务器上的进一步更改，直到结果得到处理。Guard 会先尝试自行解决。否则由你检查服务器并记录你的发现。解除阻止需要在最近五分钟内使用第二重验证重新登录。

在与 Techstack 的连接中断期间，服务器上的应用继续运行，Guard 也会保留其观察记录。新的特权工作需要有效授权，没有授权就不会启动。

## 更新

Guard 更新在安装之前会经过检查。服务器会验证更新的签名，以及它比已安装的版本更新，并会拒绝已被撤销的发布版本。随后，新的 Guard 必须在试用期内完成与 Techstack 的一次经过身份验证的签到。如果做不到，会自动恢复先前的版本。配对、密钥和日志在更新后保持不变。首次安装通过 HTTPS 来自你自己的 Techstack；签名检查适用于更新。

## 你可以做什么

- **在服务器上检查服务。** `sudo systemctl status techstack-agent` 显示 Guard 是否在运行，`sudo journalctl -u techstack-agent -f` 跟踪其日志。
- **在 Techstack 中打开服务器的 Guard 面板**，查看各项事实、验证配置、审查未知结果、轮换凭据或下载报告。
- **分离**你不想再管理的服务器。
- **了解 Guard 会发送什么**，请参阅[kombify Guard 会发送什么](/zh-Hans/techstack/guard-telemetry)。
