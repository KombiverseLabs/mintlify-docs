## techstack api servers detach

吊销并分离一台确切的、由客户自行运营的 BYO 服务器。

保留终态的规范服务器回执，且不执行任何提供商 API 调用。

```bash
techstack api servers detach <server-id> [flags]
```

<Warning>需要确认：此操作会吊销该服务器的凭据并将其移出管理，而不会触碰该机器。传入 `--yes` 或回答提示；未使用 `--yes` 的非交互式运行会在发出任何请求之前以退出码 9 停止。</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/servers/{serverId}/detach` |
| 更改状态 | 是 |
| MCP 工具 | `detach_self_owned_server` |

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `<server-id>` | string | **必填。** 规范的服务器运行时 ID。 |
| `--confirm-server-id` | string | **必填。** 必须与 serverId 路径参数完全相同。 |
| `--body` | json | JSON 请求正文（`application/json`），可以是字面量、`@path`，或用 `-` 表示 stdin。 |

## techstack api servers maintenance run

为拥有的服务器排队执行操作系统更新计划、操作系统更新或重启。

需要 Edge 签名的 `techstack.servers.maintenance` 权益、租户内的服务器所有权，以及委托原生 MCP 调用所需的当前服务器绑定常设权限。这三种常规操作不需要新的 MFA 登录或单独的 owner_approved 声明。请求体严格解码：键名必须精确且小写，不允许重复键或未知字段。相同 Idempotency-Key 的重放会在目标验证前返回已存储回执。每台服务器可同时有一项重启或操作系统更新，以及单独一项更新计划；任务未在期限内完成时以 `deadline_exceeded` 失败并释放槽位。仅当服务器代理声明 `stackkit.host-maintenance.v1` 时才在 `allowed_actions` 中提供该操作；重启还要求服务器报告 `host_boot_id`。拒绝响应为 client-error-envelope/v1；409 的 `reason_code` 可为 control_plane_host、substrate_node、protected_demo_server、service_locked、maintenance_active、node_operation_active、plan_stale、agent_capability_missing、boot_id_unknown、agent_not_connected、heartbeat_stale、inventory_revision_stale 或 idempotency_key_reused；403 携带 entitlement_required 或 maintenance_origin_authority_denied。

```bash
techstack api servers maintenance run <server-id> [flags]
```

| `<server-id>` | string | **必填。** 规范的服务器运行时 ID。 |
| `--action` | string | **必填。** 可选值：`os_update_plan`、`os_update`、`reboot`。 |

## techstack api servers network rebind

将已迁移的服务器重新绑定到当前网络。

通过服务器的 kombify Guard 运行 `stackkit network rebind`：节点重新检测 LAN 地址，重新签发已签名的 LAN DNS 保管记录，并重新生成和应用工作区。请求没有请求体。需要所有者、Inventory 的 operate 授权、`techstack.servers.maintenance` 权益和已连接的 Guard，否则返回 409 `server_network_not_ready`。已有排队或运行中的重新绑定时返回该任务，不会再次排队。

```bash
techstack api servers network rebind <server-id> [flags]
```

<Warning>需要确认：此操作重新检测服务器当前网络地址，重新签发已签名的本地 DNS 记录，并重新应用其工作区。传入 `--yes` 或回答提示；非交互式运行未提供 `--yes` 时，会在发出任何请求前以退出码 9 停止。</Warning>

## techstack api servers reach set

将服务器发布到 kombify.me 地址，或停止发布。

默认不发布任何内容：已配对服务器没有公开路由，中继也不承载流量。所有者为每台服务器指定 `service` 名称和 `target_port` 后启用，并可随时撤销；源站始终是 Guard 主机的回环地址，绝不是其他机器。中继验证 Guard，而非访客，因此该端口上的服务必须自行保护。启用需要所有者、`techstack.servers.maintenance` 权益及新的多因素登录（原因 `server_reach_step_up_required`）；撤销不会受此门槛限制。响应返回服务器读取模型中的 reach 部分；随后由协调器创建或撤销路由。

```bash
techstack api servers reach set <server-id> [flags]
```

<Warning>需要确认：此操作将服务器服务发布到公开的 kombify.me 地址，互联网上任何人都可以打开。传入 `--yes` 或回答提示；非交互式运行未提供 `--yes` 时，会在发出任何请求前以退出码 9 停止。</Warning>

## techstack api servers security repairs request

修复指定的、发生偏离的主机安全控制项。

请求在限定范围内修复新鲜主机安全证据显示发生偏离且可自动修复的控制项。需要服务器所有者、Edge 签名的 `techstack.servers.maintenance` 权益及新的多因素登录（最多 300 秒前）。修复作为带类型、记入日志的 Guard 命令，针对指定控制项运行 `stackkit host security repair --apply`；StackKits 会在变更前拒绝可能切断管理路径或将所有者锁在系统外的变更。限制包括：每台服务器同时仅一次修复（409 `repair_in_progress`）、每个控制项的冷却期（429 `repair_cooldown`）、每日尝试预算（429 `repair_attempts_exhausted`）及连续失败后的熔断（429 `repair_circuit_open`）；429 响应携带 `retry_after`。已合规（409 `control_not_drifted`）、有批准例外（`control_has_exception`）、需要手工修复（`control_not_repairable`）、缺少授权 SSH 密钥（`needs_authorized_key`）或未被观测的控制项均被拒绝。请求体严格解码。

```bash
techstack api servers security repairs request <server-id> [flags]
```

<Warning>需要确认：此操作通过服务器的 kombify Guard 恢复指定的主机安全控制项（防火墙、ssh、暴力破解防护和自动更新）。传入 `--yes` 或回答提示；非交互式运行未提供 `--yes` 时，会在发出任何请求前以退出码 9 停止。</Warning>

## techstack api servers security verify
