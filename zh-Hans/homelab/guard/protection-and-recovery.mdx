服务器可以在仍连接的情况下配置过时。应用可以在运行的情况下备份不可用。Guard 的保护模型把这些问题描述为彼此独立的状态，各有其范围、证据时间和负责的所有者。

下面的控制项说明了架构和已发布的运维约定。覆盖范围取决于已安装的版本、操作系统以及应用生命周期的绑定关系。它们并不声称每个配置都已通过资格验证；请参阅[可用性](/zh-Hans/homelab/availability)。

## 主机保护与应用保护

| 范围 | 可以确定的内容 | 边界 |
| --- | --- | --- |
| 主机基线 | 观测到的防火墙与暴露面、SSH 配置、暴力破解防护、更新以及受支持的系统控制项 | 主机受保护并不证明每个应用都安全 |
| 已纳入堆栈的应用 | 具有已接受 StackKits 绑定的应用的配置与生命周期证据 | 仅准入受支持的、经授权的生命周期操作 |
| 未纳入堆栈的应用 | 通过明确授予的集成获得的清单与观测数据 | 发现并不授予更新、重启、重新配置或纳管它的权力 |

混合安装会按应用分别保持这些边界。手动安装的服务不会仅因 Guard 在其主机上运行就算作受管。纳管需要明确的生命周期绑定；在准入变更之前，必须理解其数据和现有职责。

## 基线观测不止两种状态

- **符合：** 所测量的控制项与所选基线一致。
- **偏离：** 观测到的状态与该基线不同。
- **未知：** 当前证据缺失、过期或无法获取。
- **已批准的例外：** 某项具体偏差具有明确的范围与原因。

例外不同于通过控制项。有用的发现会说明受影响的资源、基线版本、观测时间以及可用的下一步操作。不受支持的检查与不可用的观测仍然可见。

[服务器参考](/zh-Hans/homelab/reference/cli/servers)区分了对新安全观测的请求与报告本身。请求验证不会对主机做任何更改；只有返回的观测才会更新其安全证据。

## 修复是一项单独的授权操作

检测并不授权补救。已发布的主机安全修复约定通过所属的 StackKits 操作接受具名控制项，需要所有者授权和文档所述的身份验证要求。它会拒绝那些会切断管理路径或把所有者锁在外面的变更。

并发限制、按控制项的冷却时间、尝试预算和熔断器为反复修复设定了边界。已经符合、被已批准例外覆盖、无法自动修复或缺少前置条件的控制项不会被悄悄改写。确切的要求和拒绝代码见[已发布的服务器操作](/zh-Hans/homelab/reference/cli/servers)。

例如，在没有可用授权密钥的情况下更改 SSH 设置，可能移除唯一的恢复路径。拒绝该变更可以保住访问，同时说明缺失的前置条件。

## 备份还不等于恢复

StackKits 持有节点的备份与恢复托管职责；Homelab 协调经授权的操作，Guard 汇报由此产生的证据。

| 证据 | 它告诉你什么 |
| --- | --- |
| 备份配置 | 已配置备份策略或目标 |
| 备份成功 | 某一次备份操作已完成 |
| 完整性验证 | 受检的备份数据通过了所选的完整性检查 |
| 隔离恢复 | 指定的恢复点已在测试环境中恢复 |
| 应用恢复 | 已恢复的应用及其所需数据通过了指定的检查 |

这些是不同的证明层级。恢复报告应说明其恢复点、目标、版本、观测时间和检查项。隔离的文件恢复并不能确定数据库可用、用户可登录或应用完整。可恢复性还取决于所需配置、解密材料和依赖项在需要时是否可用。

演练必须防止已恢复的服务产生意外的线上影响，例如发送通知。恢复时间和可恢复数据的新旧程度必须针对所测试的场景进行测量；两者都不能仅凭一次绿色的备份任务得出。

## 更新信任与更新状况

Guard 的更新设计把已发布产物的验证与分阶段激活、恢复分开。真实的版本仍可能启动失败。证据必须表明获准的版本已成功激活，或恢复已还原了可接受的先前版本，同时保留身份和操作状态。

这描述的是 Guard 自身的更新路径。它并不承诺为每个应用或数据库迁移提供事务性回滚。这些变更仍属于受支持的 StackKits 生命周期及其数据恢复约定。

## 解读 Guard 就绪状态

完整的 Guard 就绪约定要求下面七项事实都有新鲜证据。一个显示七项指标的界面面板本身并不能证明其证据满足该约定。

| 事实 | 需要的证据 |
| --- | --- |
| 已绑定 | 已确认的纳管注册和已接受的主机身份 |
| 已连接 | 最近一次经过身份验证的命令与结果往返 |
| 操作持久 | 日志健康，且没有未解决的操作结果 |
| 配置受保护 | 当前基线符合要求，或具有已批准、范围明确的例外 |
| 已更新 | 已签名的 Guard 产物达到或超过最低版本，且操作系统安全更新符合策略 |
| 可恢复 | 在所选的策略内有一次新的备份和经核验的隔离恢复 |
| 可达且受治理 | 已验证的预期路由、资源注册和有效的撤销 |

最后一项事实针对的是预期授权路由；它并不要求把每个应用都公开。被禁用或未测试的路由不能算作已验证可达的证明。心跳的新鲜度不能替代命令往返，聚合结果也不得掩盖未知证据。

就绪状态仅限于实际通过验证的版本、服务器配置和检查项。它不是认证，不是端点检测保证，也不承诺零中断、零入侵或零数据丢失。
