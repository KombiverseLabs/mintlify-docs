这里说明地址创建之后你可以做什么，以及之后访客会看到什么。

## 你可以更改什么

| 更改 | 是否可以？ |
| --- | --- |
| 地址指向的位置（target） | 可以 |
| 开启或关闭某个应用（“exposed”） | 可以 |
| 暂停或恢复地址（status） | 可以 |
| 描述 | 可以 |
| 名称本身 | 不可以 |

名称无法重命名。若要获得不同的名称，请用你想要的名称添加一个新地址，把访客转移过去，然后移除旧地址。

更改会很快生效。kombify.me 保留约 60 秒的路由缓存，并在你更改或删除地址时清除它。

## 步骤

**关闭应用：** 关闭该应用的 “exposed”。访客随后会得到 “not exposed” 页面 (404)。可随时重新开启。

**暂停地址：** 将其状态设为 inactive。访客会得到 503 “inactive” 的答复。设为 active 即可恢复。

**指向别处：** 更改 target。新的 target 必须遵循与之前相同的规则。公共地址需要一个公共网址。

**移除地址：** 删除它。移除后，该名称停止工作。

## 访客看到什么

| 情形 | 访客看到 |
| --- | --- |
| 应用已关闭 | 404 “not exposed” |
| 地址已暂停 | 503 “inactive” |
| 临时分享期已结束 | 410 “publication expired” |
| 无法访问你的服务器 | 502 “Bad Gateway” |
| 私有地址，辅助程序离线 | 503，请稍后重试 |

## 被暂停的账户

如果自托管账户被暂停，其 API 密钥会被拒绝，并返回 403 “account suspended” 消息。kombify.me 没有关于举报或被封禁地址的单独公共页面。如果你认为这是误判，请写信给 [info@kombify.io](mailto:info@kombify.io)，并附上名称和时间。

## 替换你的密钥

自托管账户可以替换其 API 密钥。旧密钥会立即失效，所以请更新所有使用它的地方。

## 如果出了问题

| 你看到的情况 | 该怎么做 |
| --- | --- |
| 更改被拒绝，“access denied” (403) | 该地址属于另一个账户。 |
| “subdomain not found” (404) | 检查名称。它可能已被移除。 |
| target 被拒绝 | 公共路径只接受公共的 `http` 或 `https` 地址。 |
| 仍显示旧的 target | 等待约一分钟后重新加载。 |

更多内容见[故障排查](/zh-Hans/kombify-me/troubleshooting)。
