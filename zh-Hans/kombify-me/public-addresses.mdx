当服务已经通过公共 HTTP(S) URL 响应时，请使用此路径。kombify.me 会终止 TLS，并将浏览器代理到该源站。在此路径上，私有、回环和链路本地目标会被拒绝。

## 开始之前

- 源站必须能够从互联网通过 HTTP 或 HTTPS 访问。
- 已登录的 kombify 账号通过 [api.kombify.io](https://api.kombify.io) 注册名称。自托管安装在邮箱验证后使用 API 密钥注册。
- 已连接的 StackKits 和 Techstack 流程可以为你注册官方套件名称。

## 为服务命名

1. 为家庭实验室注册一个基础名称。托管账号获得 `{homelab}-{you}.kombify.me`。自托管安装获得 `sh-{homelab}-{device}.kombify.me`。
2. 在该基础名称下注册服务。`auth`、`id` 和 `coolify` 等官方套件标识始终会变成 `{base}-{service}.kombify.me`。
3. 将服务指向公共源站 URL。
4. 暴露服务路由。未暴露的服务名称保持未发布状态。

然后在浏览器中打开 `https://{base}-{service}.kombify.me`。

`auth.kombify.me` 这类保留的根域名保持不使用。套件登录仍会落在 `{your-lab}-auth.kombify.me`。

## 如果源站不是公开的

请在此停止，并按照[访问私有服务](/zh-Hans/kombify-me/private-targets)操作。不要在公共代理上发布 localhost 或仅限局域网的 URL。

仅限本地的名称保留在 StackKits 安装的家庭实验室解析器上。它们不是 kombify.me 名称。
