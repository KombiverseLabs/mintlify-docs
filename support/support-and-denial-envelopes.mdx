All denied actions must return actionable envelopes, not generic failures.

## Required denial fields

- stable `error_code`
- stable `reason_code`
- `required_features`
- `missing_features`
- retryability
- `user_guidance` (clear next step)

## Support boundary by policy level

| Level | Support capability |
| --- | --- |
| Anonymous Guide | public, cited, tool-free guidance |
| Authenticated free | tenant-aware read-only diagnostics and support |
| Paid operated | proposal, approval/deny, execution, and verifiable run evidence |

This keeps security and support behavior consistent across web, mobile, and
voice-connected journeys.

<Note>
  **Availability / evidence:** the paid-operated row is a policy/target
  contract. It does not by itself prove that approval/execution is currently
  live on every client. Companion approve/deny/resume mutations are not current
  mobile capability.
</Note>
