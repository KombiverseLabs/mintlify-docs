SpeechKit deliberately ships **three strict modes** instead of one blurry voice pipeline. Each mode has a hard boundary, so hosts always know what a request may and may not do.

## Dictation

Turn speech into text — and nothing else.

- STT only: no LLM rewriting, no utilities, no codewords.
- Ideal for writing into any focused text field, transcription, and note capture.
- Customization happens through [Words & Replacements](#words--replacements), not through model-side rewriting — so the output stays deterministic.

## Assist

Turn one spoken (or typed) request into **one useful result**.

- A request resolves to a codeword, a utility, or an LLM answer — with optional spoken output.
- This is the "voice companion" mode: ask a question, trigger a command, transform selected text.
- Results carry explicit UI-surface metadata so the host decides where the answer lands.

## Voice Agent

Run **realtime audio-to-audio dialogue**.

- Live conversation over a streaming session — for brainstorming, support, and fast follow-ups.
- Realtime providers (for example Gemini Live or OpenAI Realtime) run in-process in the Go backend or behind the server's WebSocket API.

## Hands-Free

Hands-Free is **not a fourth mode** — it is the activation and voice-output layer over the three modes:

| Piece | What it does |
| --- | --- |
| Wake activation | Wake-word detection starts a session ("Hey Kombify") |
| Microphone capture | Managed capture with voice-activity detection |
| Auto-end policy | Sessions end on silence or explicit stop |
| Speaker output | Optional spoken replies |

Assist uses Hands-Free for Siri/Alexa-style voice-companion requests, Voice Agent uses it for continuous dialogue, and Dictation uses it only as UI-assisted activation with a visible text target.

## Words & Replacements

Words & Replacements are the first-class customization axis over all three modes:

- **Words** teach SpeechKit the terms it should recognize — names, jargon, product vocabulary.
- **Replacements** define deterministic transformations: text corrections, commands, snippets, synonyms, and templates.
- **Native Templates** are versioned, curated packs of the same data — for example the default punctuation template — replacing the old "custom dictionary" concept without adding a new mode.

## Add-on capabilities

Speaker **diarization**, **identification**, and **attribution** are add-on capabilities over the three modes. Provider support varies — Deepgram and AssemblyAI cover streaming diarization, and the capability matrix in the repository tracks the current provider/auth status.
