## Where your apps get their addresses

The installer picks the address zone that fits the host it detects, so you
choose no domain before you start.

| Where you install | Zone the installer selects | What you get |
| --- | --- | --- |
| A home server or mini PC | `*.lab.home` | A private home zone for devices on your own network. The kit runs standalone, with no kombify account. |
| A public VPS or cloud host | `*.kombify.me` | The public zone, because private home addresses are not reachable from a public server. |

A public host needs a reachable origin and an account before it actually
serves public names. `stackkit connect` binds the server to your kombify
account; from then on your apps get `{base}-{app}.kombify.me` names, and you
decide per app whether it stays home-only or is reachable from the internet.

<Note>
  kombify.me is Beta software. Names, headers and error shapes can still
  change, so do not treat it as a general-availability release.
</Note>

## The commands you will actually use

These cover the standalone lifecycle basics of a server you run yourself:

| Command | What it does |
| --- | --- |
| `stackkit init` | Initialize a new deployment from a StackKit |
| `stackkit apply` | Apply infrastructure changes |
| `stackkit status` | Show deployment status |
| `stackkit verify` | Run post-deployment verification checks |
| `stackkit backup` | Manage backups (Kopia engine) |

One command is optional. `stackkit connect` binds the server to your kombify
account, which is what activates public `*.kombify.me` names and the connected
features. The five commands above work without it.

The [CLI reference](/stackkits/reference/cli/overview) lists every command
with its flags and examples.
