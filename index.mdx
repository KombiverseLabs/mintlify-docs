# kombify documentation

Turn a computer you already own into a running homelab with Photos, Files and
Vault. It runs on your own hardware, needs no kombify account, and can add a
public HTTPS address when you want one.

## Your addresses

One command gives your apps HTTPS names, and you configure no domain first.
Public `*.kombify.me` names are the frictionless default: no domain, no DNS
setup and no certificate on a phone or laptop. Local network only is the
explicit alternative when you want nothing reachable from outside.

| Mode | Addresses | What it takes |
| --- | --- | --- |
| Public names | `*.kombify.me` | The default on a public server. On a home server, set `DOMAIN=kombify.me` before the one-liner and turn on a reach path with `stackkit reach`. |
| Local network only | `*.lab.home` | The default on a home server, and always available as an explicit choice: set `DOMAIN=lab.home`. Each device needs the one-time DNS and CA step. |

`stackkit connect` binds the server to your kombify account, which is what
activates `{base}-{app}.kombify.me` names. You then decide per app whether it
stays home-only or is reachable from the internet.

<Note>
  kombify.me is Beta software. Names, headers and error shapes can still
  change.
</Note>

## The six commands

These cover setup, day-2 operation and the optional connection to kombify:

| Command | What it does |
| --- | --- |
| <code>stackkit init</code> | Initialize a new deployment from a StackKit |
| <code>stackkit apply</code> | Apply infrastructure changes |
| <code>stackkit status</code> | Show deployment status |
| <code>stackkit verify</code> | Run post-deployment verification checks |
| <code>stackkit backup</code> | Manage backups (Kopia engine) |
| <code>stackkit connect</code> | Bind the server to your kombify account for public `*.kombify.me` names |

The [CLI reference](/stackkits/reference/cli/overview) lists every command with
its flags and examples; the rest of the command tree sits under Advanced
Reference there.
