kombify Connect lets your other Workbench Desktop installations work in an
environment on this computer: its projects, threads and, if you allow it, its
terminal. You choose which computer shares its environment and which
installations may reach it. You can take that access back at any time.

<Warning>
kombify Connect in Workbench Desktop is in Beta. Screens, names and what is
available to your account can still change.
</Warning>

## Before you start

- You need a kombify account. If you do not have one, create it first with
  [Create an account](/apps/cloud/get-started).
- Connect is part of the **Cloud** edition of Workbench Desktop. The **Local**
  edition has no kombify account and no Connect. See
  [Local and Cloud editions](#local-and-cloud-editions).
- Every installation that takes part must be signed in to the same kombify
  account.
- The sharing computer must be switched on and running Workbench Desktop while
  others use its environment. It only makes outgoing connections, so you do not
  open any ports on your router.

## Share this computer's environment

<Steps>
  <Step title="Open Connections">
    In Workbench Desktop, open **Settings** and choose **Connections**. The
    **kombify Connect** row sits with your kombify account in the settings of
    this environment.
  </Step>
  <Step title="Turn sharing on">
    Turn on **Share this environment through kombify Connect**. Expect the
    message "Environment shared". The home screen also offers this as
    **Share this computer**.
  </Step>
</Steps>

If the switch is unavailable, the text next to it says why. For example, you
are not signed in, the installation is not registered yet, or the computer
could not open its Connect key.

## Pair another installation

A pairing code connects one more installation to the environment you shared.

<Steps>
  <Step title="Create a code on the sharing computer">
    Under **Pair another installation**, choose **Create code**. Turn on
    **Terminal** first only if the other installation should also get a
    terminal in this environment. The code is valid for 10 minutes and works
    once.
  </Step>
  <Step title="Enter the code on the other installation">
    On the other installation, open **Settings**, then **Connections**. Under
    **Use a pairing code**, enter the code and choose **Pair**. Expect the
    message "Installation paired".
  </Step>
  <Step title="Open the shared environment">
    The shared environment appears under **Remote environments** on the other
    installation. Open its projects and threads as you would local ones.
  </Step>
</Steps>

A code only works on an installation signed in to the same account, and never
on the installation that created it. If 10 minutes pass, create a new code.

### Let new installations connect automatically

Instead of pairing each installation, you can turn on **Automatically connect
new devices**. New installations that sign in to your account then get access
to your shared environments. Pairing codes stay available for one-off
connections. Leave this off if other people use computers signed in to your
account.

## See who has access

**kombify Connect devices** lists every installation of your account with its
state and how its
key is protected: in the TPM, by the operating system, or in software. The
entry marked "this device" is the computer you are using. The state reads
**Access to this environment** (or **with terminal**) for an installation you
paired, **Active** for one signed in without access, **Waiting for
confirmation** for a new one, and **Revoked** for one you shut out.

## Revoke access

- **One installation:** in **kombify Connect devices**, choose **Revoke** next
  to it. Expect the message "Installation revoked". Its open sessions end,
  normally within seconds, and it can no longer reach any of your
  environments. If a computer that shares an environment cannot be reached at
  that moment, choose **Revoke** again once it is back online.
- **One installation's access, keeping the installation:** choose **Remove
  access** next to it. It loses the access it was given, including the
  terminal, but stays registered to your account, so you can pair it again
  later.
- **Everyone:** turn off **Share this environment through kombify Connect**.
  Expect the message "Environment no longer shared". Existing remote sessions
  end.

Revoking is final for that installation: a revoked installation cannot be
paired again. If you want access later, use **Remove access** instead.

## Local and Cloud editions

Workbench Desktop comes in two editions with separate installers:

| | Local | Cloud |
| --- | --- | --- |
| kombify account | none | required |
| kombify Connect | not included | included |
| Error reports to kombify | none | metadata only, no prompts or files |

The two editions keep separate data on your computer. An update always stays
within the edition you installed and never switches it.

To switch editions, install the other edition. Nothing is copied over
automatically: your projects on disk stay where they are, and you add them in
the new edition yourself. Threads and settings stay in the edition that
created them. You can keep both editions installed.

## If something goes wrong

- **"Could not redeem the pairing code".** The code expired, was already used,
  or the two installations are signed in to different accounts. Create a new
  code on the sharing computer and check the account on both.
- **"kombify Connect is unavailable".** Connect may not be available for your
  account yet, or the service cannot be reached. Try again later.
- **The shared environment does not appear.** Check that the sharing computer
  is on, Workbench Desktop is running there and sharing is still on.
- **Still stuck.** Write to [info@kombify.io](mailto:info@kombify.io), say
  which screen you were on and when it happened, and never send a password or
  a pairing code.
