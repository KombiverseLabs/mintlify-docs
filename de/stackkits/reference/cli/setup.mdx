Den Owner-Account einer angewendeten Anwendung einrichten.

Führt eine vom Plan deklarierte Setup-Aktion auf der bestehenden lokalen Anwendung aus. Lies die privaten Credential-JSON-Felder und den Dateipfad aus der Setup-Anleitung oder der Status-Aktion der ausgewählten Anwendung. Credentials werden nie in Lifecycle-Nachweise geschrieben. Ein erneuter Lauf nach einer Unterbrechung beobachtet die Anwendung neu, bevor dieselbe ausstehende Setup-Operation abgeschlossen wird.

```bash
stackkit setup <workload> [flags]
```

| Flag | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `--complete-onboarding` | bool | — | Das Onboarding von App-Benutzern und Administrator abschließen, nachdem der Owner-Login verifiziert wurde |
| `--credentials-file` | string | — | Workspace-relative private Owner-Credential-JSON-Datei (Standard ist die Setup-Anleitung der ausgewählten Anwendung) |
| `--json` | bool | — | Das secretfreie, verifizierte Setup-Ergebnis ausgeben |
| `--operation-id` | string | — | Eine ausstehende Setup-Operation fortsetzen; Standard ist das aktuell ausstehende Setup oder eine neue ID |
| `--owner-approve` | bool | — | Dieses an den Plan gebundene Anwendungs-Setup freigeben |

**Examples**

```bash
# Create the Photos owner from the private credentials in .stackkit/setup/owner.json
stackkit setup photos --owner-approve

# Also finish the application's onboarding after the owner login is verified
stackkit setup photos --owner-approve --complete-onboarding

# Create the Files owner from a workspace-relative credentials file of your choice
stackkit setup files --owner-approve --credentials-file private/files-owner.json
```
