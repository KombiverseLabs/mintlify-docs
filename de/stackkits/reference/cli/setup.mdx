Den Owner-Account einer angewendeten Anwendung einrichten.

Führt eine vom Plan deklarierte Setup-Aktion auf der bestehenden lokalen Anwendung aus. Lies die privaten Credential-JSON-Felder und den Dateipfad aus der Setup-Anleitung oder der Status-Aktion der ausgewählten Anwendung. Credentials werden nie in Lifecycle-Nachweise geschrieben. Ein erneuter Lauf nach einer Unterbrechung beobachtet die Anwendung neu, bevor dieselbe ausstehende Setup-Operation abgeschlossen wird.

```bash
stackkit setup <workload> [flags]
```

| Flag | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `--complete-onboarding` | bool | — | Das Onboarding von App-Benutzern und Administrator abschließen, nachdem der Owner-Login verifiziert wurde |
| `--credentials-file` | string | — | Workspace-relative private Owner-Credential-JSON-Datei (Standard ist die Setup-Anleitung der ausgewählten Anwendung) |
| `--json` | bool | — | Das secretfreie, verifizierte Setup-Ergebnis ausgeben |
| `--operation-id` | string | — | Eine ausstehende Setup-Operation fortsetzen; Standard ist das aktuell ausstehende Setup oder eine neue ID |
| `--owner-approve` | bool | — | Dieses an den Plan gebundene Anwendungs-Setup freigeben |

**Examples**

```bash
# Create the Photos owner from the private credentials in .stackkit/setup/owner.json
stackkit setup photos --owner-approve

# Also finish the application's onboarding after the owner login is verified
stackkit setup photos --owner-approve --complete-onboarding

# Create the Files owner from a workspace-relative credentials file of your choice
stackkit setup files --owner-approve --credentials-file private/files-owner.json
```

Unterbefehle: [`stackkit setup ai-connect`](#stackkit-setup-ai-connect)

## stackkit setup ai-connect

Private AI Ollama als eigenen Modell-Endpunkt mit deiner kombify AI verbinden.

Den optionalen kombify-AI-Connector des Private-AI-Anwendungsfalls aktivieren. Erstelle in Companion Studio (Settings, AI access, Model endpoints) einen Modell-Endpunkt mit dem Ursprung http://ollama:11434 und kopiere dessen Connector-Token. Dieser Befehl liest das Token von der Standardeingabe oder aus `--token-file`, niemals aus einem Argument, prüft sein Format, bewahrt es in lokaler Besitzerverwahrung auf und aktiviert den Connector. Das nächste generate und apply starten den ausgehenden Connector neben Ollama. Eingehend wird nichts geöffnet, und Ollama bleibt unveröffentlicht.

`--disable` schaltet den Connector aus und entfernt das Token aus der lokalen Verwahrung. Widerrufe den Endpunkt in Companion Studio, damit das Token überall unbrauchbar wird.

```bash
stackkit setup ai-connect [flags]
```

| Flag | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `--disable` | bool | — | Den Connector ausschalten und sein Token aus der lokalen Verwahrung entfernen |
| `--json` | bool | — | Das geheimnisfreie Ergebnis ausgeben |
| `--token-file` | string | — | Datei mit dem Connector-Token; "-" oder kein Flag liest die Standardeingabe |

**Beispiele**

```bash
# Paste the connector token, then press Enter and Ctrl-D (or read it hidden on a terminal)
stackkit setup ai-connect --token-file -

# Read the token from a private file
stackkit setup ai-connect --token-file ~/kombify-connector-token

# Turn the connector off and remove its token
stackkit setup ai-connect --disable
```
