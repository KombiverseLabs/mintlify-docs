Richte deine eigenen Services mit portablen StackKits ein und pflege sie. Diese Seiten listen jeden `stackkit`-Befehl mit seinen Flags und Beispielen auf. Sie werden aus den StackKits-Befehlsdefinitionen generiert; wenn deine installierte Version älter ist, ist `stackkit <command> --help` für sie maßgeblich.

## Das CLI installieren

```bash
curl -sSL https://install.stackkit.cc | STACKKIT_CLI_ONLY=1 sh
```

Mit `STACKKIT_CLI_ONLY=1` legt der Installer `stackkit`, `stackkit-server`, `stackkit-mcp`, das mitgelieferte OpenTofu und den öffentlichen Kit-Katalog in `~/.stackkits` ab, ohne ein StackKit zu installieren. Ohne diese Variable erkennt der Installer den Host und fährt mit Basement Kit oder Cloud Kit fort.

## Globale Flags

Diese Flags funktionieren mit jedem Befehl.

| Flag | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `--chdir, -C` | string | `.` | Vor der Ausführung in das Verzeichnis wechseln |
| `--correlation-id` | string | — | Validierte Korrelations-ID des Aufrufers, die in lokalen Rollout-Nachweisen festgehalten wird |
| `--no-log` | bool | — | Strukturiertes Deploy-Logging deaktivieren |
| `--progress-jsonl` | string | — | Geschwärzten maschinenlesbaren Rollout-Fortschritt als JSONL in einen Pfad schreiben, oder '-' für stdout |
| `--quiet, -q` | bool | — | Nicht wesentliche Ausgaben unterdrücken |
| `--spec, -s` | string | `stack-spec.yaml` | Pfad zur Stack-Spezifikationsdatei (kombination.yaml wird akzeptiert, wenn der Standard fehlt) |
| `--verbose, -v` | bool | — | Ausführliche Ausgabe aktivieren |
