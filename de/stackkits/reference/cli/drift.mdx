Lokalen StackKit-Drift beobachten und abgleichen.

```bash
stackkit drift [flags]
```

Unterbefehle: [`stackkit drift detect`](#stackkit-drift-detect), [`stackkit drift reconcile`](#stackkit-drift-reconcile)

## stackkit drift detect

Den maßgeblichen lokalen Zustand lesen und Drift melden.

Den kanonischen ResolvedPlan, die generierten Artefakte, den vom Owner signierten Apply-Nachweis, die lokale Owner-Bindung und die Live-Basement-Compose-Runtime lesen und verifizieren, ohne den Runtime-Zustand zu aktualisieren. Unter dem Terramate-Generierungsziel führt der Befehl außerdem einen schreibgeschützten OpenTofu-Plan mit detailed-exitcode über Terramate in jedem Stack des lokalen Host-Projekts aus und fügt pro Stack einen stacks-Eintrag hinzu; er wendet nie an. Der inhaltsadressierte Report wird als lokaler Owner-Nachweis für jedes ausgewählte Application Kit aufbewahrt.

```bash
stackkit drift detect [flags]
```

| Flag | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `--json` | bool | — | stackkit.command-result/v1-JSON ausgeben |

**Beispiele**

```bash
# Compare the live deployment with the applied plan
stackkit drift detect

# The same drift report as JSON
stackkit drift detect --json
```

## stackkit drift reconcile

Drift über den gesteuerten lokalen Lifecycle abgleichen.

Der Standard-Modus verlangt eine ausdrückliche lokale Owner-Freigabe, verifiziert die aktuelle lokale Autorität, erstellt einen verpflichtenden Rollback-Checkpoint aus Kopia und Executor-State und führt dann generate, apply und verify über das exklusive Lifecycle-Journal aus. Eine fehlgeschlagene Zielphase stellt den erfassten vorherigen Executor-State automatisch wieder her, wendet ihn erneut an und verifiziert ihn. Der Advanced-Modus bleibt fail-closed, bis eine offline verifizierte Capability übergeben wird; nach der Advanced-Mutation beobachtet er den Drift-Report erneut, einschließlich jedes Terramate-Stack-Plans, und schlägt fehl, sofern der Report nach dem Abgleich nicht sauber ist.

```bash
stackkit drift reconcile [flags]
```

| Flag | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `--candidate-spec` | string | — | Advanced: exakte Terramate-Kandidaten-StackSpec |
| `--capability` | string | — | Advanced: kanonische Offline-Capability-Datei |
| `--change-set` | string | — | Advanced: exakte vom Owner signierte Change-Set-ID |
| `--expect-sha256` | string | — | Advanced: exakter Byte-Digest des gespeicherten Change-Sets |
| `--json` | bool | — | stackkit.command-result/v1-JSON ausgeben |
| `--mode` | string | `standard` | Abgleichsmodus: standard oder advanced |
| `--owner-approve` | bool | — | Ausdrückliche lokale Owner-Freigabe für den Standard-Abgleich festhalten |

**Beispiele**

```bash
# Reconcile drift in standard mode: checkpoint, then generate, apply, and verify
stackkit drift reconcile --owner-approve

# The same reconciliation with a JSON result
stackkit drift reconcile --owner-approve --json
```
