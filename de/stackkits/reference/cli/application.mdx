Unterstützte vorhandene Anwendungen übernehmen, ohne ihre Konten oder Daten zu ersetzen.

```bash
stackkit application [flags]
```

Unterbefehle: [`stackkit application adopt`](#stackkit-application-adopt), [`stackkit application control`](#stackkit-application-control), [`stackkit application inspect`](#stackkit-application-inspect), [`stackkit application release`](#stackkit-application-release), [`stackkit application verify`](#stackkit-application-verify)

## stackkit application adopt

Die geprüfte vorhandene Anwendung an ihren deklarierten Lebenszyklus binden.

```bash
stackkit application adopt [workload] [flags]
```

| Flag | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `--container-id` | string | — | Exakte unveränderliche Docker-Container-ID mit 64 Zeichen |
| `--json` | bool | — | Den versionierten, geheimnisfreien Anwendungsnachweis ausgeben |
| `--operation-id` | string | — | Stabile Vorgangskennung für eine idempotente Fortsetzung |
| `--owner-approve` | bool | — | Diesen exakten, an den Besitzer gebundenen Anwendungsvorgang genehmigen |
| `--owner-file` | string | `.stackkit/setup/home-assistant-owner.json` | Workspace-relative vorhandene private Besitzer-Berechtigungsdatei, die accessToken enthält |
| `--plan-digest` | string | — | Exakter geprüfter und quellgebundener Digest des Übernahmeplans |
| `--workload` | string | — | Exakter ausgewählter Anwendungs-Workload (Alternative zum positionsabhängigen Workload) |
