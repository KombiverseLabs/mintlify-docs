## techstack api inventory servers access-context

Bereinigten Zugriffskontext für einen eigenen Server abrufen.

Gibt nur Adress-Metadaten, Kanalzustand und mit Aktualität qualifizierte Service-Links zurück. Nie zurückgegeben werden Endpoint-Referenzen, Access-Profile-Referenzen, Routen-IDs, Zugangsdaten, Tokens, SSH-Benutzer, Ports, Schlüssel, Befehle oder Logs. Diese Schnittstelle erfordert die Berechtigung „inventory operate“; Leserechte allein reichen nicht aus.

```bash
techstack api inventory servers access-context <server-id> [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/inventory/servers/{serverId}/access-context` |
| Ändert Zustand | Nein |
| MCP-Tool | `server_access_context` |

| Argument | Typ | Beschreibung |
| --- | --- | --- |
| `<server-id>` | string | **Erforderlich.** Kanonische Server-Runtime-ID. |

## techstack api inventory servers list

Bereinigtes Server-Inventory des authentifizierten Owners auflisten.

Gibt nur Server zurück, die dem authentifizierten Subjekt im vertrauenswürdigen Tenant-Kontext gehören. Überschreibungen von Tenant und Owner werden nicht akzeptiert. Rohe Metadaten, Kanal-Endpoints, Referenzen auf Anbieter-Ressourcen, Zugangsdaten, SSH-Material, Tokens und Logs werden nie zurückgegeben. Die Lease-Projektion enthält nur einen opaken Bezeichner und den Zustand. Cursor-Seiten teilen sich eine an Autorisierung und Filter gebundene Collection-Watermark und schließen spätere Einfügungen aus.

```bash
techstack api inventory servers list [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/inventory/servers` |
| Ändert Zustand | Nein |
| MCP-Tool | `list_servers` |

| Argument | Typ | Beschreibung |
| --- | --- | --- |
| `--limit` | integer | Standard `50`. |
| `--cursor` | string | — |

## techstack api inventory servers rename

Den vom Owner gewählten Namen eines eigenen Servers setzen oder löschen.

Schreibt servers.display_name, das Runtime-Projektionen nie überschreiben. `null` oder ein leerer String löscht die Umbenennung. Erfordert das signierte Entitlement techstack.inventory.write und die FGA-Server-Relation `caller`; der Schreibvorgang ist an den authentifizierten Tenant und Owner gebunden, und ein Server außerhalb dieses Bereichs wird abgelehnt, ohne zu verraten, ob er existiert. Das kanonische Inventory-Feld `name` meldet den gewählten Namen, wenn einer gesetzt ist.

```bash
techstack api inventory servers rename <server-id> [flags]
```

| | |
| --- | --- |
| HTTP | `PATCH /api/v1/inventory/servers/{serverId}` |
| Ändert Zustand | Ja |
| MCP-Tool | `rename_server` |

| Argument | Typ | Beschreibung |
| --- | --- | --- |
| `<server-id>` | string | **Erforderlich.** Kanonische Server-Runtime-ID. |
| `--display-name` | string | **Erforderlich.** |
| `--body` | json | JSON-Request-Body (`application/json`) als Literal, `@path` oder `-` für stdin. |
