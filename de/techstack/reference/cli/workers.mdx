## techstack api workers identity upgrade approve

Den von einem Legacy-Server vorgeschlagenen Schlüssel freigeben.

Bindet den durch `key_thumbprint` bezeichneten ausstehenden Schlüssel und bindet damit den Worker an den Schlüssel (Anfragen nur mit Bearer-Credential werden danach abgelehnt). Erfordert den Owner und eine frische Multi-Faktor-Anmeldung (höchstens 300 Sekunden alt). Freigebendes Subjekt und Zeitpunkt werden mit der Identität aufgezeichnet und protokolliert. 409 `identity_upgrade_not_pending`, wenn kein noch gültiger ausstehender Schlüssel diesen Fingerabdruck hat.

```bash
techstack api workers identity upgrade approve <id> [flags]
```

<Warning>Erfordert Bestätigung: Diese Operation entscheidet, welcher Schlüssel den Server steuern darf; gib nur einen Schlüssel frei, dessen Fingerabdruck Guard auf dem Server protokolliert. Übergib `--yes` oder beantworte die Rückfrage; ein nicht interaktiver Lauf ohne `--yes` stoppt vor jeder Anfrage mit Exit-Code 9.</Warning>

## techstack api workers identity upgrade reject

Den von einem Legacy-Server vorgeschlagenen Schlüssel verwerfen.

Zurücksetzen durch den Owner, wenn der ausstehende Schlüssel nicht der eigene Schlüssel des Servers ist: Der Vorschlag wird verworfen und muss erneut gestellt werden. Das Rotieren der Server-Zugangsdaten beendet den Zugriff ihres Inhabers auf den Bindungs-Endpoint.

## techstack api workers identity upgrade-status

Anzeigen, ob der Identitätsschlüssel eines Servers noch freigegeben werden muss.

Für den Owner des Workers. `identity_binding=legacy_bearer` mit `code=guard_identity_upgrade_required` bedeutet, dass der Server sich ausschließlich mit seinem Bearer-Credential authentifiziert und nur beobachtet wird. `pending` enthält den Fingerabdruck des vorgeschlagenen Schlüssels; der Owner vergleicht ihn mit dem von Guard auf dem Server protokollierten Fingerabdruck. Ein Worker eines anderen Tenants oder Owners liefert 404.

## techstack api workers identity upgrades

## techstack api workers outcomes list

Die ungeklärten Operationsergebnisse eines kombify Guard auflisten.

Listet die Operationen eines eigenen Workers auf, deren Ergebnis unbekannt ist: kombify Guard hat aufgezeichnet, dass die Wirkung möglicherweise eingetreten ist, möglicherweise aber auch nicht, und keine Beobachtung dies geklärt hat. Jede solche Operation sperrt weitere Änderungen am Server. `state` ist `reconciling`, solange Guard die Klärung versucht, und `needs_operator`, sobald das Ergebnis über die konfigurierte Zeit hinaus ungeklärt blieb (`TECHSTACK_GUARD_OUTCOME_NEEDS_OPERATOR_AFTER`, standardmäßig 30 Minuten). Die Zeit verändert ausschließlich die Darstellung des Ergebnisses; sie hebt die Sperre niemals auf. Ein Worker eines anderen Tenants oder Owners liefert 404.

techstack api workers outcomes list <id> [flags]

## techstack api workers outcomes resolve

Ein ungeklärtes Operationsergebnis des kombify Guard freigeben.

Speichert für eine Operation mit unbekanntem Ergebnis eine neue Operator-Auflösungsrevision, die die bisherigen Einträge nur ergänzt, und hebt die Sperre des Workers auf. `disposition` ist `verified_applied` (die Wirkung liegt vor), `verified_not_applied` (es ist nichts geschehen) oder `accept_unknown` (Freigabe ohne verifiziertes Ergebnis); `note` hält fest, was verifiziert wurde. Akteur ist das authentifizierte Subjekt; es wird mit der Revision aufgezeichnet. Ein Guard darf diese Festlegungen nicht speichern. Eine frische Multi-Faktor-Anmeldung (höchstens 300 Sekunden alt) ist erforderlich. `expected_revision` muss der von der Liste zurückgegebenen Revision entsprechen, andernfalls 409 `outcome_revision_stale`. Der Body wird strikt dekodiert: exakte Schlüssel, keine unbekannten Felder.

```bash
techstack api workers outcomes resolve <id> <command-id> [flags]
```

<Warning>Erfordert Bestätigung: Diese Operation hebt die Sperre einer Operation auf, deren Ergebnis nie geklärt wurde; dadurch können widersprüchliche Änderungen am Server ausgeführt werden. Übergib `--yes` oder beantworte die Rückfrage; ein nicht interaktiver Lauf ohne `--yes` stoppt vor jeder Anfrage mit Exit-Code 9.</Warning>
