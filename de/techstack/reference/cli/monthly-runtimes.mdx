## techstack api monthly-runtimes cleanup-readback

Geschwärzte Zustandsfakten zur Bereinigung einer Managed Runtime lesen.

Gibt auf Tenant und Owner begrenzte Zustandsfakten für die exakte aktuelle Provider-Control-Ressourcengeneration der Lease zurück. Dieser schreibgeschützte Endpoint ruft nie einen Anbieter oder einen Runtime-Agent auf und gibt nie Anbieter-Ressourcen-Handles, Befehle, Nachweisdokumente oder Zugangsdaten zurück. Eine terminale Operation läuft nicht mehr, ist für sich aber kein Beweis für eine erfolgreiche Bereinigung: Die Abwesenheit beim Anbieter erfordert absence_evidence_ref, und die Freigabe der Kapazität erfordert capacity_released.

```bash
techstack api monthly-runtimes cleanup-readback <lease-id> [flags]
```

## techstack api monthly-runtimes reconnect

Die Guard-Session einer Managed Runtime wiederherstellen.

Prüft das kanonische Aggregat; kann es keine Guard-Verbindung nachweisen, startet es Guard für einen berechtigten Owner eines laufenden Servers über den festgelegten Ausführungskanal neu, beobachtet die Verbindung innerhalb eines begrenzten Zeitfensters erneut und führt die Registrierung dann in den Zustand enrolled über. Eine gestoppte Runtime wird abgelehnt (managed_runtime_stopped). Keine Anbieter-Ressource wird angefasst.

```bash
techstack api monthly-runtimes reconnect <lease-id> [flags]
```

## techstack api monthly-runtimes recreate

Eine vollständig freigegebene Generation eines verwalteten Servers neu erstellen.

Stellt ausdrücklich Generation N+1 für denselben anbieterneutralen Runtime-Slot bereit, nachdem Generation N einen terminalen Lease- und kanonischen Server-Zustand, einen terminalen Zustand der Anbieter-Operation, opake anbieternative Abwesenheitsnachweise und eine exakte Kapazitätsfreigabe hat. Der unveränderliche Intent aus Anbieter, Region, Angebot, Rolle, StackKit und Services wird aus der alten Owner-bezogenen Lease wiederhergestellt; Clients können ihn nicht ersetzen. Der Endpoint delegiert an dieselbe Managed-Runtime-Erweiterungsautorität wie Add Node, sodass Registrierung, Guard-Nachweise, Endpoints und StackKit-Rollout den vollständigen Creation-Ablauf durchlaufen. Ein Standard-Idempotency-Key ist Pflicht und wiederholt die angenommene Generation sicher.

```bash
techstack api monthly-runtimes recreate <lease-id> [flags]
```

<Warning>Erfordert Bestätigung: Diese Operation ersetzt den Anbieter-Server der Runtime durch einen neu bereitgestellten und wird abgerechnet. Übergib `--yes` oder beantworte die Rückfrage; ein nicht interaktiver Lauf ohne `--yes` stoppt vor jeder Anfrage mit Exit-Code 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/monthly-runtimes/{lease_id}/recreate` |
| Ändert Zustand | Ja |
| MCP-Tool | `recreate_monthly_runtime` |

| Argument | Typ | Beschreibung |
| --- | --- | --- |
| `<lease-id>` | string | **Erforderlich.** ID der monatlichen Runtime-Lease. |
| `--confirmed` | boolean | **Erforderlich.** Ausdrückliche Bestätigung, dass Recreate eine neue Generation eines verwalteten Servers bereitstellt und abrechnet. Einziger möglicher Wert: `true`. |
| `--body` | json | JSON-Request-Body (`application/json`) als Literal, `@path` oder `-` für stdin. |

## techstack api monthly-runtimes stop

Einen verwalteten Server stoppen, ohne ihn zu zerstören.

Lässt eine generationsgebundene Provider-Control-Reconciliation in Richtung stopped zu. centron nutzt seine Aktion zum ordnungsgemäßen Herunterfahren des Gastsystems; bei IONOS wird das Gastsystem über den Ausführungskanal heruntergefahren, weil der Stopp beim Anbieter IONOS die gebundene DHCP-IPv4 freigibt. Der Server behält Festplatte, Adresse, Lease, Kapazitätsreservierung und monatliche Abrechnung.

```bash
techstack api monthly-runtimes stop <lease-id> [flags]
```
