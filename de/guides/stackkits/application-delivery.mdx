StackKits trennt die Anwendungswahl von der Ausführungsverantwortung. Standalone Compose ist der native Standard. Komodo ist eine Betriebsplattform ohne App-Store. Marketplace ist als optionaler Anwendungsfall mit Coolify geplant; Coolify ist dessen Anwendung und kein natives Laufzeitziel.

Sieh dir die Matrix an, die in deinem installierten Release eingebettet ist:

```bash
stackkit app compatibility --json
```

## Einen Adapter wählen

| Adapter | Aktueller Status | Nutze ihn, wenn |
| --- | --- | --- |
| `standalone-compose` | Nativer Standard | Nutze den deklarierten Workload-Pfad des installierten Releases und prüfe seinen Lifecycle-Nachweis. |
| [Coolify](/de/stackkits/apps/coolify) | Geplante Marketplace-Anwendung | Als Marketplace erst installierbar, wenn der veröffentlichte Katalog den Anwendungsfall enthält und sein Lifecycle verifiziert ist. |
| [Komodo](/de/stackkits/apps/komodo) | Entwurf einer Betriebsplattform | Wähle den Pfad ausdrücklich und nur für Workloads mit einem Nachweis am aktuellen Pin. |

Die veröffentlichte Matrix zur [Kompatibilität der Anwendungsbereitstellung](/de/stackkits/reference/application-delivery-compatibility) beschreibt deklarierte Adapterverträge. Historische Kompatibilitätszeilen belegen keine Unterstützung am aktuellen Pin. Prüfe den Lifecycle-Nachweis für deine Anwendung und dein Release; Deployment allein belegt weder Backup noch Wiederherstellung.

Beginne bei einem eigenständigen Basement Kit mit `standalone-compose`, sofern du nicht bewusst eine der Anwendungsplattformen betreibst:

```json
{
  "workloads": {
    "files": {
      "alternative": "cloudreve",
      "runtimeAdapterRef": "standalone-compose",
      "placement": {
        "siteRefs": ["home"],
        "nodeRefs": ["main"]
      }
    }
  }
}
```

## Einen Verantwortlichen pro Workload behalten

- Route denselben Workload nicht gleichzeitig über Coolify und Standalone Compose.
- Füge Docker-Labels oder generierte Routen nicht von Hand hinzu.
- Ein expliziter Komodo-Pfad benötigt einen Nachweis am aktuellen Pin; er ist weder Standard noch App-Store.
- Validiere die geänderte Absicht (Intent) und prüfe den aufgelösten Plan, bevor du einen anderen Adapter anwendest.

Siehe [Plattformdienste](/de/stackkits/apps/overview) für die Plattformintegrationen und [Eine StackSpec konfigurieren](/de/guides/stackkits/configure-stack-spec) für den vollständigen Bearbeitungsablauf.
