## StackKits moves Coolify workloads between servers and adds an Early Access channel

StackKits veröffentlichte [v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) bis [v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) mit dem Umzug von Coolify-Workloads, einem optionalen Release-Kanal, der heute Early Access heißt, Private-AI-Paketen und dem Erhalt der Daten beim Entfernen einer App.

### New features

- **Move Coolify workloads to another server.** [StackKits v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) adds `stackkit relocate plan`, `check`, `drain`, `send`, and `receive`. Drain stops your apps before the final send, so the backup is consistent, and `drain --undo` rolls the move back. See [`stackkit relocate` (English)](https://docs.kombify.io/stackkits/reference/cli/relocate).
- **Early-Access-Kanal.** [v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) führte einen optionalen Release-Kanal ein. StackKits hat ihn inzwischen eingestellt und liefert nur noch Stable aus.
- **Preview footprint and capacity before you install.** [v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) shows the footprint and capacity of your selected use cases on the target with `stackkit use-cases pick --kit`. See [`stackkit use-cases`](/de/stackkits/reference/cli/use-cases).
- **Private AI bundles by goal.** [v0.53.8](https://github.com/kombifyio/stackKits/releases/tag/v0.53.8) groups Private AI into bundles such as My private Chat and My local AI. It adds the LiteLLM model router for API access and a model manager setup action, and shows memory and GPU fit for each choice. See [Personal AI](/de/guides/stackkits/use-cases/personal-ai).
- **OpenCloud for Files and an MQTT add-on.** [v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) adds OpenCloud as a Files alternative and an MQTT add-on with authenticated messaging. See [Documents and files](/de/guides/stackkits/use-cases/documents-and-files).
- **Household access per app.** [v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) adds per-app household access groups on your node, and completes native owner setup for Navidrome and Audiobookshelf. See [Media](/de/guides/stackkits/use-cases/media).

### Updates

- **Removing an app keeps its data.** [StackKits v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) retains application volumes on ordinary removal. Deletion is an explicit choice.
- **Clearer install and upgrade guidance.** [v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) resumes interrupted installs and explains unsupported Cloud or Modern upgrades with a supported route before anything changes.
- **Private DNS with AdGuard Home.** [v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) activates private-client DNS through AdGuard Home, and [v0.53.8](https://github.com/kombifyio/stackKits/releases/tag/v0.53.8) backs up its configuration. See [Network](/de/guides/stackkits/use-cases/network).
- **Smart Home notifications and MQTT.** [v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) connects Home Assistant to kombify notify, [v0.53.6](https://github.com/kombifyio/stackKits/releases/tag/v0.53.6) installs ntfy live notifications, and [v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) configures Home Assistant MQTT from your plan. See [Smart Home](/de/guides/stackkits/use-cases/smart-home).
- **Bring your own AI provider.** [v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) connects Private AI to an external OpenAI-compatible provider with a key from the kombify Wallet, and pulls selected model packs into Ollama during Apply.
- **Coolify and Dokploy are back.** [v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) restores Coolify and Dokploy as optional application platforms. The default core still uses no PaaS. See [Coolify](/de/stackkits/apps/coolify).

### Bug fixes

- **Coolify restores recover.** [StackKits v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) recovers interrupted Coolify application restores, and [v0.53.8](https://github.com/kombifyio/stackKits/releases/tag/v0.53.8) restores signed Coolify application data.
- **Restores are checked.** [v0.53.6](https://github.com/kombifyio/stackKits/releases/tag/v0.53.6) reads back restored volume content during live restore. See [Back up and restore](/de/guides/stackkits/back-up-and-restore).
- **Friendlier install refusals.** [v0.53.6](https://github.com/kombifyio/stackKits/releases/tag/v0.53.6) fixes the non-root install path and explains a low-memory refusal. [v0.53.9](https://github.com/kombifyio/stackKits/releases/tag/v0.53.9) adds recovery guidance when a stored plan is rejected.
- **Stable capacity on Windows.** [v0.53.1](https://github.com/kombifyio/stackKits/releases/tag/v0.53.1) keeps Windows host capacity stable across working drives.

</Update>

## StackKits lässt dich die Game-Plattform wählen und Anwendungsfälle ergänzen

StackKits veröffentlichte [v0.50.4](https://github.com/kombifyio/stackKits/releases/tag/v0.50.4) bis [v0.52.6](https://github.com/kombifyio/stackKits/releases/tag/v0.52.6) : eine Auswahl an Game-Plattformen, zusätzliche Anwendungsfälle für laufende Installationen und sicherere Wiederherstellungen.

### Neue Funktionen

- **Wähle deine Game-Plattform.** [StackKits v0.52.0](https://github.com/kombifyio/stackKits/releases/tag/v0.52.0) installiert Calagopus für neue Game-Installationen; Pelican und Pterodactyl stehen als Alternativen zur Verfügung. Der Owner-Schlüssel erlaubt nur Lesen, die Stromsteuerung, den Konsolenzugriff und das Bearbeiten von Dateien. `stackkit setup game`, `stackkit game list`, `power` und `allow` funktionieren auf allen drei Plattformen gleich. Bestehende Installationen behalten ihre Plattform. Siehe [Game](/de/guides/stackkits/use-cases/game).
- **Ergänze einen Anwendungsfall in einer laufenden Installation.** [v0.51.0](https://github.com/kombifyio/stackKits/releases/tag/v0.51.0) führt `stackkit use-cases add` ein, beispielsweise für `mail`, ohne bestehende Workloads, Routen oder Speicher zu verändern. Der Befehl ist auch über den StackKits MCP verfügbar. Siehe [`stackkit use-cases`](/de/stackkits/reference/cli/use-cases).
- **Ziehe deinen Server in ein anderes Netzwerk um.** [v0.51.7](https://github.com/kombifyio/stackKits/releases/tag/v0.51.7) bindet einen Server nach einem Netzwerkwechsel neu ein, damit seine Listener die neue Adresse verwenden. Siehe [`stackkit network`](/de/stackkits/reference/cli/network).

### Updates

- **Der Home-Assistant-Connector bleibt auf deinem Node.** [StackKits v0.52.0](https://github.com/kombifyio/stackKits/releases/tag/v0.52.0) erstellt, verwendet und widerruft den Home-Assistant-Agent-Connector über `stackkit setup`. Er wird ausschließlich lokal und verschlüsselt gespeichert. Siehe [Smart Home](/de/guides/stackkits/use-cases/smart-home).
- **Stelle frühere Wiederherstellungspunkte wieder her.** [v0.52.5](https://github.com/kombifyio/stackKits/releases/tag/v0.52.5) macht authentifizierte historische Wiederherstellungspunkte zugänglich. Siehe [Sichern und wiederherstellen](/de/guides/stackkits/back-up-and-restore).
- **Mehr Apps laufen nativ auf OpenTofu.** [v0.51.0](https://github.com/kombifyio/stackKits/releases/tag/v0.51.0) kann Paperless, Mosquitto, Stalwart, Zigbee2MQTT, SearXNG, Roundcube, Euro-Office, Navidrome, Audiobookshelf, ESPHome, Emby und weitere Apps ohne Compose-Wrapper anwenden. Die native Ausführung wird pro App ausdrücklich aktiviert.
- **Geheimnisse bleiben aus Umgebungen und Datenvolumes heraus.** [v0.51.0](https://github.com/kombifyio/stackKits/releases/tag/v0.51.0) stellt App-Geheimnisse als Dateien bereit. Das MQTT-Passwort von Zigbee2MQTT und der App-Schlüssel von Pterodactyl landen nicht mehr in einem Datenvolume.
- **Verwaltete Zertifikate im Advanced mode.** [v0.51.7](https://github.com/kombifyio/stackKits/releases/tag/v0.51.7) stellt Origin-CA-Zertifikate für verwaltete kombify.me-Origins aus. Siehe [`stackkit advanced`](/de/stackkits/reference/cli/advanced).

### Fehlerbehebungen

- **Unterbrochene Wiederherstellungen werden fortgesetzt.** [StackKits v0.52.6](https://github.com/kombifyio/stackKits/releases/tag/v0.52.6) stellt eine unterbrochene Wiederherstellung über das verifizierte ursprüngliche Release wieder her. [v0.52.5](https://github.com/kombifyio/stackKits/releases/tag/v0.52.5) erhält dabei die Dateieigentümer in Containern.
- **Offsite-Backups starten auf einem frischen Bucket.** [v0.51.2](https://github.com/kombifyio/stackKits/releases/tag/v0.51.2) initialisiert das Offsite-Backup-Repository auf einem leeren Bucket.
- **Die Paperless-Anmeldung funktioniert.** [v0.50.6](https://github.com/kombifyio/stackKits/releases/tag/v0.50.6) behebt die Anmeldung von Paperless-ngx über PocketID und den Neustart des Mosquitto-Brokers.

</Update>

## Das Private-AI-Labor von StackKits, Gameserver und ein MCP auf jeder Installation

StackKits veröffentlichte [v0.33.0](https://github.com/kombifyio/stackKits/releases/tag/v0.33.0) bis [v0.50.3](https://github.com/kombifyio/stackKits/releases/tag/v0.50.3) : ein vollständiges lokales KI-Labor, einen Game-Anwendungsfall, mehr Apps pro Anwendungsfall, den Advanced mode und einen StackKits MCP auf jeder Installation.

### Neue Funktionen

- **Private AI wird zu einem lokalen KI-Labor.** Mit [StackKits v0.48.0](https://github.com/kombifyio/stackKits/releases/tag/v0.48.0) kannst du Open WebUI oder AnythingLLM als Chat auswählen und Websuche, Dokumentanalyse, einen Hermes-Assistenten, einen OpenHands-Agenten unter gVisor sowie ComfyUI für Bilder und Videos hinzufügen. Es läuft auf der CPU oder auf NVIDIA- und AMD-GPUs. Ein optionaler Connector verbindet dein Homelab-Modell ausgehend mit kombify AI, sodass kein eingehender Port geöffnet wird. Siehe [Personal AI](/de/guides/stackkits/use-cases/personal-ai).
- **Gameserver.** [v0.41.0](https://github.com/kombifyio/stackKits/releases/tag/v0.41.0) fügt einen optionalen Game-Anwendungsfall mit dem Pterodactyl Panel hinzu. `stackkit setup game` erstellt Minecraft-Java- und Bedrock-Server mit sicheren Standardeinstellungen, und [v0.43.0](https://github.com/kombifyio/stackKits/releases/tag/v0.43.0) ergänzt Paper, Terraria und Valheim. Die Einrichtung prüft die Bereitschaft durch einen echten Client-Beitritt und lehnt einen Server ab, für den der Host nicht genügend Arbeitsspeicher hat. Siehe [Game](/de/guides/stackkits/use-cases/game).
- **Mehr Apps pro Anwendungsfall.** [v0.47.0](https://github.com/kombifyio/stackKits/releases/tag/v0.47.0) installiert Nextcloud, Forgejo, Emby und Passbolt als Alternativen zu den Standard-Apps. Add-ons werden neben einem Anwendungsfall installiert: Paperless-ngx, Euro-Office, Navidrome, Audiobookshelf und ESPHome. Siehe den [Anwendungsfallkatalog](/de/stackkits/reference/use-case-catalog).
- **Mail auf deine Art.** [v0.47.0](https://github.com/kombifyio/stackKits/releases/tag/v0.47.0) fügt Roundcube-Webmail für ein bereits vorhandenes Postfach sowie einen optionalen Stalwart-Mailserver auf einem eigenen Knoten hinzu. Siehe [Mail](/de/guides/stackkits/use-cases/mail).
- **Advanced mode für verwaltete Haushalte.** [v0.47.0](https://github.com/kombifyio/stackKits/releases/tag/v0.47.0) führt Änderungssätze, Drift-Erkennung und Abgleich pro Stack, koordinierte Rollbacks und Wiederherstellungsübungen über Terramate auf OpenTofu aus. Basement-Installationen verwenden jetzt standardmäßig OpenTofu, und [v0.48.0](https://github.com/kombifyio/stackKits/releases/tag/v0.48.0) verschlüsselt Status und Pläne. Siehe [`stackkit advanced`](/de/stackkits/reference/cli/advanced).
- **Ein StackKits MCP auf jeder Installation.** [v0.46.0](https://github.com/kombifyio/stackKits/releases/tag/v0.46.0) veröffentlicht auf jedem Core einen token-geschützten `/mcp`-Endpunkt, sodass sich ein KI-Agent direkt mit deinem Server verbinden kann. Jeder öffentliche CLI-Befehl ist jetzt ein MCP-Tool oder eine aufgeführte Ausnahme; Befehle, die ein Geheimnis offenlegen würden, bleiben auf die CLI beschränkt. Siehe [MCP-Connector](/de/stackkits/reference/mcp-connector).
- **Betriebssystemupdates über die CLI.** [v0.47.0](https://github.com/kombifyio/stackKits/releases/tag/v0.47.0) plant Betriebssystemupdates, wendet sie an und plant Neustarts auf einem Knoten. Siehe [`stackkit host`](/de/stackkits/reference/cli/host).
- **Vorbereitete Images.** [v0.50.0](https://github.com/kombifyio/stackKits/releases/tag/v0.50.0) fügt `stackkit image plan`, `prepare` und `verify` hinzu, um die Toolchain und Core-Images vorab zwischenzuspeichern. Jede Installation erhält beim ersten Start weiterhin eigene Besitzerschlüssel und Geheimnisse. Siehe [`stackkit image`](/de/stackkits/reference/cli/image).

### Aktualisierungen

- **Anmeldung für weitere Apps.** [StackKits v0.48.0](https://github.com/kombifyio/stackKits/releases/tag/v0.48.0) meldet Paperless-ngx, Media und Smart Home über PocketID an und stellt Haushaltskonten in Files bereit. [v0.38.0](https://github.com/kombifyio/stackKits/releases/tag/v0.38.0) fügt für den Besitzer-Passkey `stackkit user owner status` und `activate` hinzu. Siehe [PocketID](/de/stackkits/apps/pocketid).
- **Smart Home wächst.** [v0.47.1](https://github.com/kombifyio/stackKits/releases/tag/v0.47.1) installiert Mosquitto und Zigbee2MQTT mit vom Besitzer ausgewählten LAN-Listenern und Device-Passthrough, und [v0.50.0](https://github.com/kombifyio/stackKits/releases/tag/v0.50.0) übernimmt einen vorhandenen Home Assistant, ohne dessen Zustand zu ersetzen. Siehe [Smart Home](/de/guides/stackkits/use-cases/smart-home).
- **Jede Anwendung erhält eine Route.** [v0.39.0](https://github.com/kombifyio/stackKits/releases/tag/v0.39.0) gibt Media, Smart Home, AI, Dev und Documents dieselbe HTTPS-Route und Datenbindung wie Photos, Files und Vault.
- **Backups nach Abdeckungsgruppe.** [v0.37.0](https://github.com/kombifyio/stackKits/releases/tag/v0.37.0) wählt Daten nach `config`, `content` oder `media` aus. Eine nicht festgelegte Abdeckung wird als `content` aufgelöst, sodass Medien immer ausdrücklich ausgewählt werden. Siehe [Sichern und Wiederherstellen](/de/guides/stackkits/back-up-and-restore).
- **Ubuntu 26.04 als Standard.** [v0.50.0](https://github.com/kombifyio/stackKits/releases/tag/v0.50.0) verwendet Ubuntu 26.04 LTS für neue Installationen und bleibt mit 24.04 kompatibel. [v0.35.0](https://github.com/kombifyio/stackKits/releases/tag/v0.35.0) ergänzt Backups unter Debian 13. Siehe [Betriebssystemkompatibilität](/de/stackkits/reference/os-compatibility).
- **Kompatibilität aus echten Läufen.** [v0.33.0](https://github.com/kombifyio/stackKits/releases/tag/v0.33.0) und [v0.34.0](https://github.com/kombifyio/stackKits/releases/tag/v0.34.0) bewerten jedes Kit pro Umgebung anhand automatisierter Installations-bis-Wiederherstellungs-Läufe, und [v0.41.0](https://github.com/kombifyio/stackKits/releases/tag/v0.41.0) bewertet Cloud Kit auf einem öffentlichen VPS als unterstützt.
- **Jeder Befehl ist dokumentiert.** [v0.33.0](https://github.com/kombifyio/stackKits/releases/tag/v0.33.0) fügt Beispiele zu `stackkit <command> --help` hinzu und veröffentlicht die vollständige [CLI-Referenz](/de/stackkits/reference/cli/overview). Das Installationsprogramm prüft außerdem das heruntergeladene Archiv anhand der Release-Prüfsummen.
- **Basement verwendet standardmäßig `lab.home`.** [v0.47.5](https://github.com/kombifyio/stackKits/releases/tag/v0.47.5) verwendet `lab.home` als Standarddomain, und vorhandene Basement-Domains werden mit signierter Wiederherstellung migriert.

### Fehlerbehebungen

- **4-GB-Server erfüllen das Minimum von 4 GB.** [StackKits v0.45.0](https://github.com/kombifyio/stackKits/releases/tag/v0.45.0) rundet den installierten Arbeitsspeicher auf das nächste GiB, sodass Cloud Kit einen VPS mit 4 GB nicht mehr ablehnt.
- **Upgrades von früheren Releases funktionieren.** [v0.39.0](https://github.com/kombifyio/stackKits/releases/tag/v0.39.0) behebt Fehler von `stackkit upgrade` und `stackkit kit list` mit `unexpected EOF`. Installiere vor dem Upgrade eine aktuelle CLI.
- **Konfigurationsänderungen erreichen laufende Dienste.** [v0.45.0](https://github.com/kombifyio/stackKits/releases/tag/v0.45.0) erstellt einen Dienst neu, wenn sich dessen generierte Konfigurationsdatei ändert, und die Anmeldung am Game Panel lädt Google reCAPTCHA nicht mehr.
- **Sicherere Wiederherstellung.** [v0.48.0](https://github.com/kombifyio/stackKits/releases/tag/v0.48.0) lässt einen wiederholten Apply-Lauf eine unterbrochene Ausführung wiederherstellen und setzt eine unterbrochene Cloud-Installation aus jedem Verzeichnis fort. [v0.49.0](https://github.com/kombifyio/stackKits/releases/tag/v0.49.0) lehnt die Updateplanung ab, während ein Update läuft, und verlangt eine ausdrückliche Bestätigung für `stackkit remove` mit JSON-Ausgabe.
- **Cloud-Kit-Korrekturen.** [v0.38.0](https://github.com/kombifyio/stackKits/releases/tag/v0.38.0) sorgt dafür, dass Backups und Besitzeranmeldung auf Cloud Kit funktionieren, und nennt ein Let's-Encrypt-Ratenlimit samt Wiederholungszeit. [v0.48.3](https://github.com/kombifyio/stackKits/releases/tag/v0.48.3) lehnt rein lokale Cloud-Kit-Domains bei init ab.

</Update>

## StackKits-Installer, der das Kit auswählt

StackKits veröffentlichte [v0.25.1](https://github.com/kombifyio/stackKits/releases/tag/v0.25.1) bis [v0.32.1](https://github.com/kombifyio/stackKits/releases/tag/v0.32.1) : ein Installer, der den Host erkennt und das Kit anbietet, Login-Gates vor den Homelab-Routen und Haushaltsnutzer über PocketID.

### Neue Funktionen

- **Der StackKits-Installer wählt das Kit aus.** [v0.32.0](https://github.com/kombifyio/stackKits/releases/tag/v0.32.0) lässt `install.stackkit.cc` den Host erkennen, zwischen Basement und Cloud wählen, vor jeder Installation nach Owner und Anwendungsfällen fragen und anbieten, ein StackKit zu installieren, sobald die CLI vorhanden ist. Eine falsche Installer-URL erholt sich, statt zu scheitern. Siehe [CLI-Walkthrough](/de/guides/stackkits/cli-walkthrough).
- **Haushaltsnutzer ohne handgebaute Konten.** [v0.29.0](https://github.com/kombifyio/stackKits/releases/tag/v0.29.0) richtet Haushaltsnutzer über PocketID-Gruppen ein, und [v0.30.0](https://github.com/kombifyio/stackKits/releases/tag/v0.30.0) fügt `stackkit user add`, `list` und `remove` hinzu. Siehe [PocketID](/de/stackkits/apps/pocketid).

### Updates

- **Login-Gates vor den Homelab-Routen.** [v0.31.0](https://github.com/kombifyio/stackKits/releases/tag/v0.31.0) stellt TinyAuth vor die Routen für Fotos, Dateien, Vault, Medien, Smart Home, KI, Entwickler, Dokumente und Coolify, und die Verifikation akzeptiert die Login-Weiterleitung als gesund, statt sie als Fehler zu lesen. Siehe [TinyAuth](/de/stackkits/apps/tinyauth).
- **Cloud Kit braucht keine eigene Domain.** [v0.32.0](https://github.com/kombifyio/stackKits/releases/tag/v0.32.0) verwendet standardmäßig einen kombify.me-Namen, wenn keine eigene Domain angegeben ist, und erzeugt einen SSH-Schlüssel für den Ausführungskanal, bevor der Root-Login deaktiviert wird. Siehe [kombify.me](/de/kombify-me/overview).
- **Apply wartet auf das Zertifikat.** [v0.31.5](https://github.com/kombifyio/stackKits/releases/tag/v0.31.5) wartet auf die Ausstellung, bevor öffentliches TLS und interne PKI-Leaves verifiziert werden, und [v0.32.0](https://github.com/kombifyio/stackKits/releases/tag/v0.32.0) zeigt den Fortschritt, während generate und apply laufen, statt einer stillen Pause.

### Fehlerbehebungen

- **Das Entfernen räumt native Stacks auf.** [v0.32.0](https://github.com/kombifyio/stackKits/releases/tag/v0.32.0) lässt `stackkit remove` native Compose-Stacks deinstallieren und den Installer-Workspace finden, und [v0.31.1](https://github.com/kombifyio/stackKits/releases/tag/v0.31.1) verschiebt die Anwendungsbeobachtung auf die Restore-Aktivierung, sodass eine Wiederherstellung keine Anwendungen mehr prüft, die noch nicht laufen.

</Update>

## StackKits Smart Home und Media

StackKits veröffentlichte [v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) bis [v0.24.27](https://github.com/kombifyio/stackKits/releases/tag/v0.24.27) : die Anwendungsfälle Smart Home und Media, einen browserbasierten Planer unter stackkit.cc/planner und modullokale Compute-Profile.

### Neue Funktionen

- **Smart-Home-Anwendungsfall in StackKits.** [StackKits v0.23.0](https://github.com/kombifyio/stackKits/releases/tag/v0.23.0) fügt einen Home-Assistant-Workload auf den Kits Basement, Cloud und Modern hinzu. Generate schreibt die Reverse-Proxy-Basis und ein natives MCP-Client-Fragment, und das Setup legt das Homelab-Owner-Konto an. Siehe den [Anwendungsfall-Katalog](/de/stackkits/reference/use-case-catalog).

Die Medienbibliothek bleibt in der Verwahrung des Owners und ist bewusst keine StackKits-Backup-Quelle. Siehe [Jellyfin](/de/stackkits/apps/jellyfin).

## StackKits öffentliche Adressen und Compute-Tiers

StackKits veröffentlichte [v0.21.10](https://github.com/kombifyio/stackKits/releases/tag/v0.21.10) bis [v0.22.0](https://github.com/kombifyio/stackKits/releases/tag/v0.22.0) : verwaltete öffentliche Dienstadressen mit automatischem TLS auf Cloud Kit und Compute-Tiers, die ein Kit zur Hardware passen lassen, die du wirklich hast.

### Neue Funktionen

- **Verwaltete öffentliche Adressen mit automatischem TLS auf Cloud Kit.** [StackKits v0.21.20](https://github.com/kombifyio/stackKits/releases/tag/v0.21.20) bis [v0.21.24](https://github.com/kombifyio/stackKits/releases/tag/v0.21.24) geben Cloud-Kit-Diensten verwaltete öffentliche kombify.me-Adressen: einen secret-freien Adressplan, Routen, die aus deinem validierten Subdomain-Präfix gerendert werden, und Zertifikate, die per ACME HTTP-01 ausgestellt werden, damit das Cloudflare-Gateway das Origin-TLS validieren kann, während der Dienstverkehr HTTPS bleibt. Siehe [Cloud Kit](/de/stackkits/kits/cloud-kit).
- **Compute-Tiers passen das Kit an deine Hardware an.** [StackKits v0.22.0](https://github.com/kombifyio/stackKits/releases/tag/v0.22.0) fügt pro Kit die Compute-Tiers `low`, `standard` und `high` hinzu. Apply bescheinigt lokale CPU, RAM und Festplatte vor dem Auflösen und blockiert mit einem klaren Grund, statt auf einem unterdimensionierten Host zu deployen. Siehe [Ein Kit wählen](/de/guides/stackkits/choosing-a-kit) und [Prüfen, planen und anwenden](/de/guides/stackkits/review-plan-and-apply).
- **Secrets-Verwahrung zu einem bestehenden Homelab hinzufügen.** [StackKits v0.21.11](https://github.com/kombifyio/stackKits/releases/tag/v0.21.11) fügt einen ausdrücklichen, idempotenten Befehl `stackkit secrets materialize` hinzu, damit ein eigenständiges Homelab nach der Auswahl eines neuen Workloads eine Owner-gebundene Verwahrung einrichten kann, ohne seine ursprüngliche StackSpec erneut auszuführen. Siehe [Day-2-Operationen](/de/stackkits/reference/day-2-operations).

### Updates

- **Die vom Owner freigegebene Entfernung zielt auf einen Node.** [StackKits v0.21.11](https://github.com/kombifyio/stackKits/releases/tag/v0.21.11) bis [v0.21.13](https://github.com/kombifyio/stackKits/releases/tag/v0.21.13) lassen die vom Owner freigegebene Workload-Entfernung eine exakte Node-Platzierung aus einem verifizierten Multi-Node-Apply-Ergebnis auswählen, wobei der Abwesenheitsnachweis weiter mit demselben Apply korreliert wird.
- **Reichhaltigeres Access-Manifest.** [v0.21.16](https://github.com/kombifyio/stackKits/releases/tag/v0.21.16) erweitert das native Access-Manifest auf v3 mit Anwendungsgruppierung, Anzeigenamen, Lifecycle-Auswirkung und secret-freien internen Adressen für laufende Dienste.

### Fehlerbehebungen

- **Cloud-Härtung kann dich nicht mehr aussperren.** [StackKits v0.21.10](https://github.com/kombifyio/stackKits/releases/tag/v0.21.10) bewahrt ein Nicht-Root-Konto mit Schlüsselauthentifizierung, bevor die Cloud-Host-Sicherheit den Root-Login deaktiviert, und [v0.21.17](https://github.com/kombifyio/stackKits/releases/tag/v0.21.17) lässt die gehärtete sshd-Richtlinie gegenüber Provider- und cloud-init-Defaults gewinnen, sodass der Root-Schlüssel-Login deaktiviert bleibt.
- **Ein erneutes Apply auf den Ports 80 und 443 ist sicher.** [v0.21.18](https://github.com/kombifyio/stackKits/releases/tag/v0.21.18) lässt ein idempotentes Apply die Ports 80 und 443 nur dann wiederverwenden, wenn Docker belegt, dass sie zum Cloud-Core des aktuellen Workspaces gehören. Fremde oder veraltete Listener blockieren weiterhin.
- **Workloads ohne Placement-Block funktionieren einfach.** [v0.21.11](https://github.com/kombifyio/stackKits/releases/tag/v0.21.11) wendet die geregelten Placement-Defaults an, wenn ein StackSpec-Autor einen Workload ohne `placement`-Block auswählt. Siehe [Eine Stack-Spec konfigurieren](/de/guides/stackkits/configure-stack-spec).
- **Ein fehlgeschlagenes Apply sagt dir, was als Nächstes zu tun ist.** [v0.22.0](https://github.com/kombifyio/stackKits/releases/tag/v0.22.0) beendet ein fehlgeschlagenes Product Apply mit Hinweisen zu Retry, `status` und `logs` sowie der Run-ID, und die Installer setzen einen vorhandenen Workspace fort, statt abzubrechen.

</Update>

## StackKits Cloud Core

StackKits [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) rundet zehn vollwertige Anwendungsfälle ab und bringt die anbieterneutrale Cloud-Core-Runtime, gefolgt von einer Reihe von Cloud-Apply- und Verify-Fixes bis [v0.21.9](https://github.com/kombifyio/stackKits/releases/tag/v0.21.9) .

### Neue Funktionen

- **Zehn vollwertige Anwendungsfälle in StackKits.** [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) vervollständigt die CUE-Autoritäten für alle zehn Anwendungsfälle, einschließlich Vault, Media und die Entwürfe AI/Dev/Remote, plus die Post-1.0-Entwürfe Mail und Game. Bestehende Rollen von Basement Kit und Cloud Kit sind daran gebunden. Siehe [Ein Kit wählen](/de/guides/stackkits/choosing-a-kit).
- **Anbieterneutrale Cloud-Core-Runtime.** [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) implementiert die anbieterneutrale Cloud-Core-Runtime mit einem geschützten lokalen Product Apply, Live-Verify-Beobachtung und der exakten Access-Manifest-v2-Projektion für `base`, `auth`, `id` und `coolify`. Provider- und Zugangsdaten-Verwahrung bleiben in Techstack. Siehe [Cloud Kit](/de/stackkits/kits/cloud-kit).

### Fehlerbehebungen

- **Cloud Apply erreicht auf einem Standard-Ubuntu-Host die deklarierte Haltung.** [StackKits v0.21.9](https://github.com/kombifyio/stackKits/releases/tag/v0.21.9) installiert die Pakete, die hinter den Cloud-Host-Security-Units und deren Regelwerk stehen, statt bei fehlendem `nft` und `fail2ban` zu scheitern, und lädt einen laufenden `sshd` nur neu, während auf Socket-aktivierten Hosts das Verzeichnis für die Privilegientrennung sichergestellt wird.

- **Das exakte Cloud-Core-Verify kommt mit dem Socket-Proxy und Diensten mit Health-Checks zurecht.** [v0.21.6](https://github.com/kombifyio/stackKits/releases/tag/v0.21.6) akzeptiert die Beobachtung `not-configured` für den absichtlich Healthcheck-losen Socket-Proxy, und [v0.21.7](https://github.com/kombifyio/stackKits/releases/tag/v0.21.7) behält exakte, von der Runtime verantwortete Health-Ergebnisse öffentlicher Routen, nachdem sie gegen die Cloud-Core-Modul-Probes validiert wurden.
- **Cloud Kit Apply scheitert nicht mehr geschlossen an Dispatcher-Metadaten.** [v0.21.4](https://github.com/kombifyio/stackKits/releases/tag/v0.21.4) akzeptiert Dispatcher-Plan-Class-Metadaten bei Cloud-Kit-Ownern und Host-Admission, sodass Product Apply nicht mehr mit `health:stackkits-host-admission=executor-failed` fehlschlägt. [v0.21.5](https://github.com/kombifyio/stackKits/releases/tag/v0.21.5) führt rein lokale Cloud-Kit-Owner über ihren exakten lokalen Router aus. Siehe [Prüfen, planen und anwenden](/de/guides/stackkits/review-plan-and-apply).
- **Verify und Status lehnen veraltete Cloud-Dienstprojektionen ab.** [v0.21.1](https://github.com/kombifyio/stackKits/releases/tag/v0.21.1) lehnt veraltete, fremde oder veränderte Cloud-Dienstprojektionen beim Readback von Verify und Status ab.

## StackKits v0.15.0 – v0.18.1: geführter Installer, dienststeuerbare Rollouts und ein anbieterneutraler Cloud Core

StackKits ging diese Woche von v0.14.28 auf [v0.18.1](https://github.com/kombifyio/stackKits/releases/tag/v0.18.1). Ein neuer geführter Installer bringt eine unvorbereitete Maschine in drei Modi zu einem laufenden Homelab. Cloud Kit erhielt einen anbieterneutralen Cloud Core, Besitz öffentlicher TLS-Routen und optionales Offsite-Backup. `apply`, `status`, `verify` und `logs` sind bei jedem Ergebnis vollständig maschinenlesbar, und ein neuer Befehl `stackkit service` steuert einzelne Dienste zwischen vollständigen Applies.

### Neue Funktionen

- **Geführter Installer zu einem laufenden Homelab.** [StackKits v0.17.0](https://github.com/kombifyio/stackKits/releases/tag/v0.17.0) liefert eine vollständige geführte Installation mit drei Modi und einem `v2 init`-Ablauf, der `--use-case`, `--platform` und `--enable` akzeptiert. Der Installer richtet Docker und die Speicher-Wurzeln direkt ein, arbeitet sicher unter `sudo` und gibt wahrheitsgemäße native Zugangsdaten aus. Siehe [Quickstart](/de/stackkits/quickstart) und [Ein Kit wählen](/de/guides/stackkits/choosing-a-kit).
- **Anbieterneutraler Cloud Core mit öffentlichen TLS-Routen.** [StackKits v0.15.0](https://github.com/kombifyio/stackKits/releases/tag/v0.15.0) löst einen erforderlichen `cloud-core`-Workload für `base`, `auth`, `id` und `coolify` auf, rendert ein einziges Compose-Projekt mit festgepinnten Digests und führt es über einen geschlossenen lokalen Runtime-Owner auf einem extern bereitgestellten Host aus. [v0.18.0](https://github.com/kombifyio/stackKits/releases/tag/v0.18.0) lässt Cloud Kit öffentliche TLS-Routen durchgängig besitzen und materialisieren. Die Cloud-Runtime-Verwahrung speichert nur dienstbezogenes Material von PocketID, TinyAuth und Coolify. Provider-Zugangsdaten, Server-Zugangsdaten, Leases und Inventar bleiben außerhalb von StackKits. Siehe [Cloud Kit](/de/stackkits/kits/cloud-kit).
- **Befehl `stackkit service` für die Steuerung nach dem Rollout.** [v0.16.0](https://github.com/kombifyio/stackKits/releases/tag/v0.16.0) fügt `stackkit service start|stop|restart <service-key>` und `stackkit service logs <service-key>` für von StackKits verwaltete Cloud-Core-Dienste hinzu. Mutationen erfordern `--owner-approve`, und `--json` liefert ein versioniertes Aktionsergebnis. Nutze ihn, um zwischen vollständigen Applies einen Dienst neu zu starten oder zu untersuchen. Siehe [Day-2-Operationen](/de/stackkits/reference/day-2-operations).

```bash
stackkit service restart coolify --owner-approve --json
stackkit service logs auth --tail 100
```

- **Vollständig maschinenlesbare Ausgabe bei apply, status, verify und logs.** [v0.15.8](https://github.com/kombifyio/stackKits/releases/tag/v0.15.8) hält `stackkit apply --json`, `stackkit status --json` und `stackkit verify --json` bei Erfolg, Ablehnung und Fehler parsebar. `stackkit logs` liefert geschwärzte, begrenzte Seiten mit digest-gebundenen Cursorn und expliziten Abschneide-Metadaten. Der MCP-Connector stellt dieselben strukturierten Nachweise bereit. Siehe [MCP-Connector](/de/stackkits/reference/mcp-connector) und [Ein StackKit betreiben](/de/stackkits/reference/day-2-operations).
- **Runtime-Listener der Architektur v2 für produktverantwortete Anwendungsbereitstellung.** [v0.15.3](https://github.com/kombifyio/stackKits/releases/tag/v0.15.3) stellt Runtime-Listener auf den Katalogprojektionen der Architektur v2 bereit, damit Anwendungen ihre eigene Bereitstellung steuern können, ohne die Lifecycle-Autorität aus StackKits zu verlagern. Siehe [Anwendungsbereitstellung](/de/guides/stackkits/application-delivery).

### Updates

- **Offsite-Backup auf Cloud Kit ist jetzt Opt-in.** [v0.16.1](https://github.com/kombifyio/stackKits/releases/tag/v0.16.1) macht Offsite-Backup auf Cloud Kit zu einer ausdrücklichen Entscheidung. Siehe [Sichern und wiederherstellen](/de/guides/stackkits/back-up-and-restore).
- **Die Traefik-Admin-API bleibt auf Cloud Kit nur auf localhost.** [v0.18.1](https://github.com/kombifyio/stackKits/releases/tag/v0.18.1) hält die Traefik-Admin-API in den Produkt- und öffentlichen Release-Verträgen an localhost gebunden.

### Fehlerbehebungen

- **Apply bindet die Mutation an den erwarteten Plan-Hash.** [StackKits v0.17.0](https://github.com/kombifyio/stackKits/releases/tag/v0.17.0) verhindert, dass apply gegen einen Plan läuft, der sich darunter geändert hat. Siehe [Prüfen, planen und anwenden](/de/guides/stackkits/review-plan-and-apply).
- **Authentifizierte Pulls öffentlicher Runtime-Images.** [v0.16.8](https://github.com/kombifyio/stackKits/releases/tag/v0.16.8) authentifiziert die Pulls öffentlicher Runtime-Images, die eine frische Installation durchführt.
