Homelab Runtime is the optional orchestration and operator experience built on top of
the StackKits CLI contract. StackKits continues to own stack definitions and
the standalone lifecycle; Homelab adds guided configuration, runtime
inventory, multi-server coordination, and governed Day-2 operations.

<Warning>
Homelab is currently a Beta. The open-source Windows client supports the
account-free local path, while the hosted entry at
[homelab.kombify.io](https://homelab.kombify.io) and managed capabilities
remain preview scope.
</Warning>

## In plain words

Think of StackKits as the tool that sets up your own server. Homelab is an
optional app on top that helps you configure it, see what runs on each server,
and look after several servers together.

## What you need first

For the Windows Beta you need a Windows computer and a server in your home
network. No kombify account is required for the local path.

## What Homelab owns

- Easy and Techie configuration flows that produce a StackSpec proposal
- runtime and service inventory across registered servers
- orchestration of a pinned, released StackKits CLI
- review and execution of governed Day-2 operations
- connected and managed placement workflows

Homelab does not redefine StackKit architectures, copy the StackKits catalog,
or become a requirement for a local StackKit. The generated StackSpec still
passes through the StackKits validation and execution boundary.

## How it relates to StackKits

[kombify Guard](/homelab/guard/overview) is Homelab's server-side reliability
and security component. It connects server identity, admitted operations and
protection evidence. Its technical guide explains what a connected server,
a secured configuration and a demonstrated recovery each establish.

| Concern | Owner |
| --- | --- |
| Kits, modules, StackSpec, local lifecycle, and verification | StackKits |
| Wizard, configuration proposals, inventory, and orchestration | Homelab |
| Provider lifecycle, leases, and managed-resource cleanup | Homelab |
| Local owner identity and standalone evidence | StackKits |

Removing Homelab must not make a standalone StackKit unusable. Start with the
[StackKits quickstart](/stackkits/quickstart) when you want an installation
path that is publicly available today.

## What to expect

Homelab is pre-1.0. You add each server as a Node, and every Node has a role
in its StackKit. The simplest way to connect a server is the one-line pairing
command. Some options depend on what your account has enabled.

## If something goes wrong

If a server stays on **Not connected yet**, check the steps in
[Add a Node](/homelab/add-node) and [Pairing command](/homelab/pairing-command).
Your StackKit keeps working without Homelab.
