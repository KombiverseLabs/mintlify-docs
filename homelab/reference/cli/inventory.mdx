## techstack api inventory backups

Read backup health of the authenticated owner's servers, with the cause of the last failed backup.

Answers "why is my backup failing". Per visible server: the Guard-observed freshness of the newest snapshot (`state`, `reason_code`, `last_snapshot_at`), the restore drill, the stack's backup schedule and off-site store, the outcome per day, and the newest finished and the newest failed backup job with the step it stopped in and the error it recorded (`last_failure`). A fresh snapshot never proves a restore works; the restore drill says that. Nothing runs on the node to answer this read.

```bash
techstack api inventory backups [flags]
```

| HTTP | `GET /api/v1/inventory/backups` |
| Changes state | No |
| MCP tool | `get_backup_status` |

## techstack api inventory servers access-context

Get sanitized access context for one owned server.

Returns address metadata, channel state, and freshness-qualified service links only. It never returns endpoint references, access-profile references, route IDs, credentials, tokens, SSH users, ports, keys, commands, or logs. This surface requires inventory operate permission; read permission alone is insufficient.

## techstack api inventory servers list

List sanitized server inventory for the authenticated owner.

Returns only servers owned by the authenticated subject in the trusted tenant context. Tenant and owner overrides are not accepted. Raw metadata, channel endpoints, provider-resource references, credentials, SSH material, tokens, and logs are never returned. The lease projection contains only an opaque identifier and state. Cursor pages share one authorization- and filter-bound collection watermark and exclude later inserts. Each server carries its connection and health state and a freshness-qualified metrics block (cpu, memory and disk percent, uptime seconds); a figure from a stale heartbeat is reported as stale without a value.

```bash
techstack api inventory servers list [flags]
```

## techstack api inventory servers rename

Set or clear the owner-chosen name of one owned server.

Writes servers.display_name, which runtime projections never overwrite. `null` or an empty string clears the rename. Requires the signed techstack.inventory.write entitlement and the FGA server `caller` relation; the write is bound to the authenticated tenant and owner, and a server outside that scope is denied without revealing whether it exists. The canonical inventory `name` reports the chosen name when one is set.

```bash
techstack api inventory servers rename <server-id> [flags]
```

## techstack api inventory updates

Read available operating-system and service updates of the authenticated owner's servers.

Per visible server: the operating-system update facts the Guard reports and every service with a newer version. A service whose `update_mode` is `stackkit_upgrade` is updated with the service `update` action (`run_managed_service_action`): the governed upgrade of its stack's StackKits release, which keeps a restore point, verifies the target live and automatically returns to the previous release when that verification fails. All managed services of one server share that release, so one `update` of any of them updates them all; get_job reads its `update_outcome`. `adopt_required` services must be adopted first. A service whose version was not compared is counted in `not_compared`, never reported as up to date. A StackKits-managed application also carries the verified application release feed facts: `application_update` (a security fix in every setting, else the newest checked version; the `update` action with `version` and `digest` moves only that application and get_job reads its `application_update_outcome`), `bundled` (arrives with a StackKits release), `advisories`, `security_fix`, and `not_verified` / `vulnerable` per server.

```bash
techstack api inventory updates [flags]
```
