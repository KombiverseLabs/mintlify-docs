## homelab api unifier layout recommend

Compute and record a verified workload layout for a planned change.

Plans where the selected goals run for an add-server or add-use-case change. An add-server change is planned on the nodes of its owned StackKit deployment; an add-use-case change is planned over every server of the owner's homelab in the tenant (all owned deployments and connected bare servers), and `target` names where it is carried out: `extend` a deployment (the one in `stack_id` or another one), or `found` a new deployment on a bare server (information only). Verifies the option with the pinned StackKits feasibility check and, when it is feasible, records it as an open recommendation the owner can accept inside the wizard run on the target deployment, reject or snooze. An option that is not verified is returned with state `unverified` and no id. `pins` carries the owner's "Choose another server" choices of an add-use-case change (use case id to server id): the planner re-solves with them on the deployment that declares the chosen servers, and the result is verified like any other; a server outside the owner's deployments in this tenant is refused with `layout_pin_server_unavailable`. Records the proposal but changes no infrastructure.

```bash
homelab api unifier layout recommend [flags]
```

## homelab api unifier put-creation-draft

Keep where the signed-in owner stands in one creation process.

Replaces the owner's draft of one creation process and renews its expiry (seven days after the last write). The body is decoded strictly. Answers that carry a password, passphrase, token, key or other secret in a field named for it are refused with `creation_draft_secret_field`, never stored or stripped; the answer names the field, never its value. The owner's expired drafts are removed with the write.

```bash
homelab api unifier put-creation-draft [flags]
```
