يُقدَّم kombify API على `https://api.kombify.io`. وتوضح هذه الصفحة عائلات المسارات التي يمكنك الاعتماد عليها وكيف تغيّرها kombify.

## فئات الاستقرار

لكل عائلة مسارات فئة واحدة. وتنطبق الفئة على العمليات في مرجع API. والمسار غير المذكور في المرجع ليس جزءاً من API التي تبني عليها.

| الفئة | ما تعنيه لك |
| --- | --- |
| Stable | يمكنك البناء عليها. وهي مجمَّدة منذ إصدار API 1.0: فالتغييرات داخل الإصدار تضيف فقط. |
| Protocol | تتبع الرسائل بروتوكولاً مشتركاً (A2A وAG-UI وA2UI وMCP وعقد Connect). والمسارات وصيغة الأخطاء مجمَّدة مثل Stable؛ أما أشكال الرسائل فتتبع إصدارات البروتوكول نفسه. |
| Preview | موثَّقة، لكن المنتج الذي يقف خلفها قد يتغير. وتُسرد التغييرات في ملاحظات الإصدار دون فترة إهمال. |

| الفئة | عائلات المسارات |
| --- | --- |
| Stable | `/v1/ai`، `/v1/embed`، `/v1/agents`، `/v1/orchestrator`، `/v1/homelab`، `/v1/speechkit`، `/v1/notifications`، `/v1/subdomains`، `/v1/content`، `/v1/connectors`، `/v1/harnesses`، `/v1/ril`، `/v1/decisions`، `/v1/supply-dock`، `/v2/supply-dock` |
| Protocol | `/a2a`، `/ag-ui`، `/a2ui`، `/v1/mcp/knowledge`، `/v1/connect` |

وأي عائلة مسارات موثَّقة أخرى تُعد Preview إلى أن تدرجها هذه الصفحة.

## إدارة الإصدارات

الإصدار الرئيسي هو أول مقطع في المسار، مثل `/v1`. وداخل الإصدار الواحد تكون هذه التغييرات إضافية ويمكن أن تصل في أي وقت: مسار جديد، أو حقل طلب اختياري جديد، أو حقل استجابة جديد، أو قيمة جديدة في قائمة استجابة مفتوحة، أو `reason_code` جديد للرفض. اكتب عميلك بحيث يتجاهل الحقول التي لا يعرفها.

وهذه التغييرات كاسرة ولا تصدر إلا كإصدار رئيسي جديد إلى جانب القديم: تضييق المدخلات المقبولة، أو جعل حقل اختياري إلزامياً، أو تغيير نوع حقل أو معناه، أو تغيير فئة حالة نتيجة قائمة، أو تشديد متطلبات تسجيل الدخول أو الاستحقاق على مستدعٍ قائم دون رفض جديد موثَّق.

ولا تُسمح إزالة مسار أو حقل أو `reason_code` رفض داخل الإصدار إلا عبر تسلسل الإهمال أدناه. ويمكن لإصلاحات الأمان والقانون أن تكسر عقداً قبل انتهاء الفترة؛ وتذكر ملاحظة الإصدار ذلك حينها وتعطي مسار الترحيل.

ونقاط نهاية الصحة والاكتشاف (`/gateway/health`، `/.well-known/*`) بلا إصدار وتتبع القاعدة الإضافية. و`/v1/blog` قيد الإيقاف وليس جزءاً من التجميد.

## الإهمال

لا يُزال مسار أو حقل أو `reason_code` رفض من فئة Stable أو Protocol إلا بعد هذا التسلسل:

1. **الإعلان.** يعلّم مرجع API العملية كمنقضية مع خليفتها (وللحقل أو `reason_code` تذكر ذلك العملية التي تعيده)، وتذكرها ملاحظة الإصدار. ويحدد الإعلان تاريخ إيقاف.
2. **الإشارة.** من الإصدار المعلن فصاعداً، يستجيب المسار المنقضي بترويسات `Deprecation` و`Sunset` وترويسة `Link` تحمل `rel="successor-version"` وتشير إلى البديل. ويُعلَن الحقل أو `reason_code` في المرجع وفي ملاحظة الإصدار.
3. **الفترة.** تمر 180 يوماً على الأقل بين الإعلان وإزالة المسار، و90 يوماً على الأقل للحقل أو `reason_code`. وإذا كان المستدعون ما زالوا يستخدمونه في تاريخ الإيقاف، فيتأجل التاريخ.
4. **الإزالة.** بعد الإزالة يستجيب المسار بـ `410` ويسمّي خليفته لإصدار واحد آخر على الأقل قبل تحرير المسار.

ولا فترة لمسارات Preview؛ لكن إزالتها تظهر في ملاحظات الإصدار رغم ذلك.

## مسارات مستبدلة دون تاريخ إيقاف

استُبدل `GET /v1/agents/workbench-orchestrator/harnesses` بـ `GET /v1/agents/harnesses`. ولم يُعلَن له تاريخ إيقاف، لذا لا تسري أي فترة إهمال. وحين يُعلَن تاريخ، يسري التسلسل أعلاه.
