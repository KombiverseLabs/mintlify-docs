## techstack api stacks create

إنشاء نشر StackKit في Homelab المالك.

ينشئ نشر StackKit داخلياً تحت Homelab الوحيد لمالك B2C المصادَق عليه، من حمولة stack-spec القياسية لـ StackKits المقدَّمة بوصفها `stack_spec`. يحدد المسار القديم `/stacks` وحقل الاستجابة `stack_id` هذا النشر؛ ولا ينشئان منتج Homelab ثانياً ولا يختارانه. يمكن لمثيل TechStack واحد أن يخدم مالكين كثيرين، لكل منهم Homelab خاص به. تظل حمولات `user_config`/kombination القديمة مقبولة عند حد التوافق هذا. ينبغي لعملاء المعالج إرسال `X-Idempotency-Key` ثابت؛ وتُرجع إعادات المحاولة بالمفتاح والحمولة نفسيهما النشر الأصلي والخادم المخطط ومهمة التجهيز.

```bash
techstack api stacks create [flags]
```

<Warning>يتطلب تأكيداً: تنشئ هذه العملية نشر StackKit وتبدأ التجهيز، الذي قد يطلب خوادم مدفوعة. مرّر `--yes` أو أجب عن المطالبة؛ فالتشغيل غير التفاعلي دون `--yes` يتوقف قبل أي طلب برمز الخروج 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/stacks` |
| يغيّر الحالة | نعم |
| أداة MCP | `create_stack` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `--x-idempotency-key` | string | مفتاح ثابت لمحاولة المعالج. الحد الأقصى 256 حرفاً. |
| `--mode` | string | وضع المعالج. إحدى القيم: `easy`، `techie`. |
| `--name` | string | اسم الـ stack. |
| `--options` | object | — |
| `--provider` | string | مزوّد البنية التحتية (التنسيق المباشر). |
| `--services` | string\[\] | أسماء الخدمات (التنسيق المباشر). |
| `--stack-spec` | object | شكل stack-spec.yaml القياسي لـ StackKits الذي يولّده معالج الإنشاء. عند وجوده يكون مصدر الحقيقة للتجهيز، ويُخزَّن بوصفه user_config للـ stack لأغراض التوافق. |
| `--user-config` | object | إعداد منظَّم قديم، بما في ذلك الحمولات الأقدم بأسلوب kombination. ينبغي لعملاء المعالج الجدد إرسال stack_spec. |
| `--user-config-format` | string | إحدى القيم: `json`، `yaml`. |
| `--user-config-raw` | string | سلسلة YAML/JSON خام. |
| `--body` | json | جسم طلب JSON (`application/json`) كقيمة حرفية أو `@path` أو `-` لـ stdin. |

## techstack api stacks managed-runtimes add

إضافة عقدة مُدارة واحدة عبر التحكم الأصلي لدى المزوّد.

ينشئ أو يستأنف مهمة Add-Server حتمية واحدة لنشر StackKit المملوك المحدد. مفتاح `Idempotency-Key` القياسي إلزامي. تُرجع إعادة إرسال المفتاح نفسه مع الطلب القياسي نفسه ارتباطات المهمة وعقد الإيجار وخادم وقت التشغيل وجيل الموارد وعملية المزوّد الأصلية؛ وتفشل إعادة استخدامه بنية مختلفة بالرمز 409.

لا يُحفظ المفتاح الخام ولا يُرجَع أبداً. لا يمكن استئناف استجابة مفقودة أو نتيجة قبول أصلي غير مؤكدة إلا بالمفتاح نفسه. يعني قبول HTTP أن القبول الأصلي دائم وأن المطابقة لدى المزوّد معلّقة؛ ولا يدّعي أبداً أن الـ VM قد جُهّزت بالفعل أو أنها سليمة. يحجز القبول الجديد بشكل ذرّي خانة سعة المستأجر/المالك المصادَق عليه مع جيل عقد الإيجار وعملية المزوّد. وعندما يجد القبول الأصلي المرجعي أن تلك السعة المحدودة ممتلئة، يحفظ نتيجة 403 غير قابلة لإعادة المحاولة، وتُرجع إعادة تشغيل تلك المهمة المرفوضة النتيجة نفسها. تعيد عمليات الإعادة الدقيقة لقبول مُلتزَم به مسبقاً استخدام حجزه القائم. لا يوجد في هذا الإصدار تحرير تلقائي للحجز: فحالة الإخراج من الخدمة النهائية أو المحلية وحدها لا تحرر خانة. لا يفوّض جرد عقود الإيجار وأعلام feature-delivery السعة ولا يرفضانها أبداً. يتطلب القبول الجديد المستضاف أيضاً استحقاقات وقت التشغيل التجاري والمزوّد الموقَّعة بإصدار v2، إضافة إلى قرار الوضع/الحد الموقَّع `cloud.runtime.credits` `managed_servers`؛ ولا تمنح أعلام الميزات وحدها سعة لدى المزوّد أبداً. يستخدم Self-host OSS سياسة بيان الإصدار الثابتة المحددة عند البناء بدلاً من الاعتماد على استحقاق SaaS.

```bash
techstack api stacks managed-runtimes add <stack-id> [flags]
```

<Warning>يتطلب تأكيداً: تطلب هذه العملية خادماً مُداراً إضافياً لنشر StackKit، وتُحتسب عليها رسوم. مرّر `--yes` أو أجب عن المطالبة؛ فالتشغيل غير التفاعلي دون `--yes` يتوقف قبل أي طلب برمز الخروج 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/stacks/{id}/managed-runtimes` |
| يغيّر الحالة | نعم |
| أداة MCP | `add_managed_runtime_server` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `<stack-id>` | string | **مطلوب.** معرّف الـ stack. |
| `--ionos-datacenter` | string | اسم بديل لمركز بيانات IONOS لـ provider_region؛ ويُتجاهل لدى المزوّدين القياسيين الآخرين. |
| `--node-role` | string | إحدى القيم: `foundation`، `worker`، `storage`. الافتراضي `"worker"`. |

## techstack api stacks repair

Repair one degraded component of a completed rollout on its existing server.

A rollout whose stack core applied completes degraded when an
independent component could not finish; the component is recorded in
the stack's `degraded_components` and repaired automatically. This
operation starts that repair now. `public_tls` installs the managed
kombify.me origin certificate (ADR-0047) on the stack's server; its
hostnames come from the degraded rollout, never from the request.
Answers 409 `component_repair_not_needed` when nothing is degraded.

```bash
techstack api stacks repair <stack-id> [flags]
```

| | |
| --- | --- |
| HTTP | `POST /api/v1/stacks/{id}/repair` |
| Changes state | Yes |
| MCP tool | `repair_stack_component` |

| Argument | Type | Description |
| --- | --- | --- |
| `<stack-id>` | string | **Required.** Stack ID. |
| `--component` | string | **Required.** One of `public_tls`. |
| `--body` | json | JSON request body (`application/json`) as a literal, `@path` or `-` for stdin. |

استئناف انتظار متأخر لعقدة مُدارة على الـ VM القائمة المحددة الخاصة بها.

استرداد مصادَق عليه وغير متغير النتيجة (idempotent) لمهمة محفوظة في الحالة `waiting_enrollment` أو `waiting_provider_provision` أو `waiting_canonical_guard` تجاوز موعد `next_resume_at` الخاص بها فترة السماح المحدودة. يتحقق الخادم من نشر StackKit المملوك والمهمة المصدر وسبب الانتظار وعقد الإيجار الدقيق ودور الأساس النشط والعقدة القياسية كعملية واحدة. وهو ينهي بشكل ذرّي الانتظار المصدر المحدد، وينشئ أو يعيد بناء عملية نشر بديلة حتمية واحدة مرتبطة بعقد الإيجار والعقدة نفسيهما، ويعيد تشغيل تلك المهمة في الاستدعاءات اللاحقة. قبل الدخول إلى المعالج، يحصل عمّال الطابور بشكل ذرّي على مطالبة التنفيذ التوافقية الدائمة `tenant/stack`؛ وهذا يسلسل المهام المختلفة لنشر StackKit نفسه عبر نسخ Techstack المتماثلة. تبقى المطالبة دائمة في الحالة `running` حتى يخرج المعالج، بما في ذلك أثناء الإلغاء. لا تستدعي نقطة النهاية هذه أبداً إنشاء VM لدى المزوّد ولا تختار VM أحدث. البديل الذي يُعثر عليه دائماً في الحالة `running` بعد انهيار يبقى مغلقاً عند الفشل، ويُبلَّغ عنه بوصفه المهمة نفسها، ولا يُكرَّر تلقائياً أبداً؛ وتبقى مطابقة إجراءات وقت التشغيل شأناً منفصلاً للمشغّل.

```bash
techstack api stacks resume-enrollment <stack-id> [flags]
```

## techstack api stacks stackkit run

Queue an owned node's typed Advanced or backup operation.

Uses the same tenant- and owner-scoped dispatcher as the operator UI. The node executes through its authenticated channel, current release pin, native Advanced catalog and issued operation capability. Techstack never executes Terramate, apply, rollback, backup or restore itself. A mutation requires owner_approved; service locks and active server maintenance are checked before enqueue. Direct backup_run and backup_configure remain Basement-only; managed kits keep their schedule and sealed target-renewal authority. backup_configure derives the node's target and plan from existing custody and accepts no credential fields. advanced_change_set requires candidate_spec; rollback requires an exact rollback_target_ref; restore_drill may reuse a snapshot_anchor_id. ai_provider lets Private AI offer an external OpenAI-compatible provider: the kombify Wallet seals the item wallet_item_id (the provider's API key) to the node, which must be listed as a host target of that item, the node binds it to ai_provider_base_url, and a drift reconcile applies the setting. ai_provider_disable removes it. Restore activation requires exactly one Idempotency-Key header, while other operations have no replay guarantee. Acceptance is not execution success; read the returned job and its scoped result to observe effects.

```bash
techstack api stacks stackkit run <stack-id> [flags]
```

<Warning>Requires confirmation: This operation can change the node deployment, replace its services or restore its data; approve the selected operation and exact target before dispatch. Pass `--yes` or answer the prompt; a non-interactive run without `--yes` stops before any request with exit code 9.</Warning>

| --- | --- |
| HTTP | `POST /api/v1/stacks/{id}/stackkit/operations` |
| Changes state | Yes |
| MCP tool | `run_stackkit_operation` |

| `<stack-id>` | string | **Required.** Stack ID. |
