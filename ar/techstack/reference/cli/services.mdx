## techstack api services execute-application-adoption

نفّذ خطة المصدر المحددة التي خضعت للمراجعة بموافقة صريحة من المالك.

يعيد التحقق من الملخّص المحتفَظ به وهوية المصدر والمراجعة والإصدار. لا تثبت العضوية إلا بإيصال حفظ مصادَق عليه من CLI المثبّت على إصدار محدد. تُحفَظ الحسابات والإعدادات والبيانات الدائمة؛ ولا تُنشأ بيئة تشغيل جديدة. لا يدعم النقل إلى عقدة أخرى أو التبنّي العام.

```bash
techstack api services execute-application-adoption [flags]
```

| | |
| --- | --- |
| HTTP | `POST /api/v1/services/{serviceId}/adoption-plans/{planId}/execute` |
| يغيّر الحالة | نعم |
| أداة MCP | `execute_application_adoption` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `--service-id` | string | **مطلوب.** معرّف تشغيل الخدمة المعتمد. |
| `--plan-id` | string | **مطلوب.** |
| `--expected-inventory-revision` | integer | **مطلوب.** |
| `--mode` | string | إحدى القيم: `adopt_in_place`. |
| `--owner-approved` | boolean | الافتراضي `false`. |
| `--plan-digest` | string | — |
| `--body` | json | جسم طلب JSON بصيغة `application/json`، كقيمة حرفية أو `@path` أو `-` للقراءة من stdin. |

## techstack api services run-action

وضع إجراء خدمة StackKits أذن به المالك في الطابور.

يشتق سلطة الـ stack والخادم والوكيل والـ kit والخدمة من جرد قياسي حديث. تتقارب عمليات إعادة الإرسال الدقيقة عبر إيصال مهمة دائم؛ ولا يُحفظ مفتاح Idempotency-Key الخام أبداً. يلي كل تعديلٍ تشغيلُ StackKits verify قبل تغيير الحالة المقيسة. ترفض الإجراءات التي ينفذها الوكيل بالرمز 409 `maintenance_active` أثناء إعادة تشغيل الخادم أو تحديثه.

```bash
techstack api services run-action <service-id> [flags]
```

| --- | --- |
| HTTP | `POST /api/v1/registry/services/{serviceId}/actions` |
| يغيّر الحالة | نعم |
| أداة MCP | `run_managed_service_action` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |

## techstack api services setup-application-connector

أكّد وجود موصل Home Assistant مُعلَن ومملوك على عقدته، أو ألغِه.

يلزم إثبات حديث لملكية الخلفية وصلاحية operate إيجابية وجرد حالي مطابق تمامًا وموافقة المالك. لا يُنقل عبر Guard إلى CLI المنشور المثبّت على إصدار محدد إلا بيانات الارتباط المحددة حصريًا؛ وتظل صلاحيتا signedApply وإعداد المالك المحليتان إلزاميتين. تُحفَظ النية الدائمة قبل الإرسال؛ وإذا كانت نتيجة التأكيد مجهولة، تُراجَع العملية الأصلية للقراءة فقط. يفتقر الإصدار الحالي v0.51.8 إلى الكتالوج الداعم ويعيد SourcePreview غير قابلة للإرسال للتنفيذ. تبقى بيانات الاعتماد في حفظ العقدة.

```bash
techstack api services setup-application-connector [flags]
```

<Warning>يتطلب تأكيدًا: تُصدر هذه العملية بيانات اعتماد موصل Home Assistant الذي تملكه العقدة والخاضع للمراجعة، أو تلغيها، لهذه الخدمة المحددة. مرّر `--yes` أو أجب عن السؤال؛ يتوقف التشغيل غير التفاعلي دون `--yes` قبل أي طلب برمز الخروج 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/services/{serviceId}/connector` |
| يغيّر الحالة | نعم |
| أداة MCP | `setup_application_connector` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `--service-id` | string | **مطلوب.** معرّف تشغيل الخدمة المعتمد. |
| `--action` | string | **مطلوب.** إحدى القيم: `ensure`, `revoke`. |
| `--expected-inventory-revision` | integer | **مطلوب.** |
| `--lifespan-days` | integer | **مطلوب.** |
| `--owner-approved` | boolean | **مطلوب.** إحدى القيم: `true`. |
| `--body` | json | جسم طلب JSON بصيغة `application/json`، كقيمة حرفية أو `@path` أو `-` للقراءة من stdin. |
