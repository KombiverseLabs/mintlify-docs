## techstack api servers detach

إبطال وفصل خادم BYO واحد محدد يشغّله العميل.

يحتفظ بإيصال الخادم القياسي النهائي ولا يجري أي استدعاء لـ API المزوّد.

```bash
techstack api servers detach <server-id> [flags]
```

<Warning>يتطلب تأكيداً: تبطل هذه العملية بيانات اعتماد الخادم وتزيله من الإدارة دون المساس بالجهاز. مرّر `--yes` أو أجب عن المطالبة؛ فالتشغيل غير التفاعلي دون `--yes` يتوقف قبل أي طلب برمز الخروج 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/servers/{serverId}/detach` |
| يغيّر الحالة | نعم |
| أداة MCP | `detach_self_owned_server` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `<server-id>` | string | **مطلوب.** معرّف وقت تشغيل الخادم القياسي. |
| `--confirm-server-id` | string | **مطلوب.** يجب أن يساوي تماماً معامل المسار serverId. |
| `--body` | json | جسم طلب JSON (`application/json`) كقيمة حرفية أو `@path` أو `-` لـ stdin. |

## techstack api servers maintenance run

ضع خطة تحديث نظام التشغيل أو تحديثه أو إعادة تشغيل خادم مملوك في قائمة الانتظار.

يلزم استحقاق `techstack.servers.maintenance` الموقّع من Edge، وملكية الخادم داخل المستأجر، والصلاحية الدائمة الحالية المرتبطة بالخادم لاستدعاءات MCP الأصلية المفوّضة. لا تتطلب هذه الإجراءات الاعتيادية الثلاثة تسجيل MFA جديدًا أو إقرار owner_approved مستقلاً. يُفك ترميز الجسم بصرامة: مفاتيح صغيرة مطابقة تمامًا، بلا تكرار أو حقول مجهولة. تُرجع إعادة الطلب باستخدام Idempotency-Key نفسه الإيصال المحفوظ قبل التحقق من الهدف. يمكن أن تنشط لكل خادم مهمة واحدة لإعادة التشغيل أو تحديث النظام، ومهمة مستقلة لخطة تحديث؛ تفشل المهمة التي تتجاوز موعدها بالرمز `deadline_exceeded` وتحرّر خانتها. لا يُعرض الإجراء في `allowed_actions` إلا إذا أعلن وكيل الخادم `stackkit.host-maintenance.v1`، كما تتطلب إعادة التشغيل أن يبلّغ الخادم عن `host_boot_id`. الرفض مستند client-error-envelope/v1؛ إحدى قيم `reason_code` في 409 هي control_plane_host أو substrate_node أو protected_demo_server أو service_locked أو maintenance_active أو node_operation_active أو plan_stale أو agent_capability_missing أو boot_id_unknown أو agent_not_connected أو heartbeat_stale أو inventory_revision_stale أو idempotency_key_reused؛ وتحمل 403 القيمة entitlement_required أو maintenance_origin_authority_denied.

```bash
techstack api servers maintenance run <server-id> [flags]
```

| --- | --- |
| HTTP | `POST /api/v1/servers/{serverId}/actions` |
| يغيّر الحالة | نعم |
| أداة MCP | `run_server_maintenance_action` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `<server-id>` | string | **مطلوب.** معرّف وقت تشغيل الخادم القياسي. |
| `--action` | string | **مطلوب.** إحدى القيم: `os_update_plan`، `os_update`، `reboot`. |
| `--expected-inventory-revision` | integer | **مطلوب.** |
| `--expected-plan-digest` | string | لـ os_update فقط: قيمة plan_digest لخطة os_update_plan مكتملة لهذا الخادم لا يزيد عمرها عن 15 دقيقة. |
| `--owner-approved` | boolean | حقل قديم اختياري؛ لا يمنح صلاحية الصيانة. |

## techstack api servers network rebind

أعِد ربط الخادم المنقول بالشبكة الموجودة عليه الآن.

يشغّل `stackkit network rebind` على الخادم عبر kombify Guard الخاص به: تعيد العقدة اكتشاف عنوان LAN، وتعيد إصدار سجل حفظ LAN DNS الموقّع، وتعيد توليد مساحة العمل وتطبيقها. لا يحمل الطلب جسمًا. يلزم المالك ومنحة operate من Inventory واستحقاق `techstack.servers.maintenance` وGuard متصل، وإلا تُرجع 409 `server_network_not_ready`. إذا كانت إعادة الربط في الانتظار أو قيد التشغيل، يُرجع طلبها القائم بدلًا من إدراج طلب آخر.

```bash
techstack api servers network rebind <server-id> [flags]
```

<Warning>يتطلب تأكيدًا: تعيد هذه العملية اكتشاف عنوان الخادم على شبكته الحالية، وتعيد إصدار سجل DNS المحلي الموقّع وتطبيق مساحة عمله. مرّر `--yes` أو أجب عن السؤال؛ يتوقف التشغيل غير التفاعلي دون `--yes` قبل أي طلب برمز الخروج 9.</Warning>

## techstack api servers reach set

انشر الخادم على عنوان kombify.me أو أوقف نشره.

لا يُنشر شيء افتراضيًا: لا يملك الخادم المقترن مسارًا عامًا، ولا ينقل المرحّل حركة مرور. يفعّله المالك لكل خادم باسم `service` صريح و`target_port`، ويمكنه سحبه في أي وقت؛ ويكون المصدر دائمًا عنوان loopback لمضيف Guard، لا جهازًا آخر. يصادق المرحّل على Guard لا على الزائر، لذا يجب أن تحمي الخدمة التي تجيب على ذلك المنفذ نفسها. يتطلب التفعيل المالك واستحقاق `techstack.servers.maintenance` وتسجيل دخول حديثًا متعدد العوامل، بسبب `server_reach_step_up_required`؛ أما السحب فلا يخضع لهذا الشرط. تتضمن الاستجابة قسم reach من نموذج قراءة الخادم؛ ثم ينشئ المُوفّق المسار أو يسحبه.

```bash
techstack api servers reach set <server-id> [flags]
```

<Warning>يتطلب تأكيدًا: تنشر هذه العملية خدمة للخادم على عنوان kombify.me عام يستطيع أي شخص على الإنترنت فتحه. مرّر `--yes` أو أجب عن السؤال؛ يتوقف التشغيل غير التفاعلي دون `--yes` قبل أي طلب برمز الخروج 9.</Warning>

## techstack api servers security repairs request

أصلح ضوابط أمن المضيف المسمّاة والمنحرفة.

يطلب إصلاحًا محدودًا لضوابط تُظهر أدلة أمن مضيف حديثة أنها منحرفة وقابلة للإصلاح التلقائي. يلزم مالك الخادم واستحقاق `techstack.servers.maintenance` الموقّع من Edge وتسجيل دخول حديث متعدد العوامل، لا يتجاوز عمره 300 ثانية. يصل الإصلاح كأمر Guard ذي نوع محدد ومسجّل، يشغّل `stackkit host security repair --apply` للضوابط المسمّاة وحدها؛ ويرفض StackKits، قبل أي تغيير، تغييرًا يقطع مسار الإدارة أو يمنع المالك من الدخول. الحدود: إصلاح واحد لكل خادم في المرة، 409 `repair_in_progress`؛ وفترة تهدئة لكل ضابط، 429 `repair_cooldown`؛ وميزانية محاولات يومية لكل ضابط، 429 `repair_attempts_exhausted`؛ وقاطع بعد إخفاقات متتالية، 429 `repair_circuit_open`. تحمل استجابات 429 قيمة `retry_after`. يُرفض الضابط المتوافق، 409 `control_not_drifted`، أو المشمول باستثناء معتمد، `control_has_exception`، أو اليدوي، `control_not_repairable`، أو المنتظر لمفتاح SSH معتمد، `needs_authorized_key`، أو غير المرصود. يُفك ترميز الجسم بصرامة.

```bash
techstack api servers security repairs request <server-id> [flags]
```

<Warning>يتطلب تأكيدًا: تعيد هذه العملية ضوابط أمن المضيف المسمّاة، مثل الجدار الناري وssh والحماية من التخمين والتحديثات التلقائية، عبر kombify Guard على الخادم. مرّر `--yes` أو أجب عن السؤال؛ يتوقف التشغيل غير التفاعلي دون `--yes` قبل أي طلب برمز الخروج 9.</Warning>

## techstack api servers summary

قراءة ملخص وجود الخوادم للمالك المصادَق عليه.

يُرجع فقط عدداً وعلامة وجود ضمن نطاق سياسة المستأجر والمالك نفسه الخاص بقائمة الجرد القياسية. يوجد استعلام tenant الاختياري للتوافق مع Gateway ويجب أن يطابق تماماً المستأجر في الهوية المصادَق عليها؛ ويُرفض عدم التطابق قبل أي قراءة من المخزن. ولا تُرجَع أي معرّفات للخوادم أو المستأجرين أو الكيانات.

```bash
techstack api servers summary [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/servers/summary` |
| يغيّر الحالة | لا |
| أداة MCP | لا شيء |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `--tenant` | string | — |

## techstack api servers transitions

عرض الخط الزمني المحفوظ لحالة الخادم.

```bash
techstack api servers transitions <server-id> [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/servers/{serverId}/transitions` |
| يغيّر الحالة | لا |
| أداة MCP | `list_server_runtime_transitions` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `<server-id>` | string | **مطلوب.** معرّف وقت تشغيل الخادم القياسي. |
