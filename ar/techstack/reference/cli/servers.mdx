## techstack api servers detach

## techstack api servers maintenance cancel

Cancel an owned maintenance job before execution starts.

Uses the same tenant, entitlement, server and requesting-owner scope as the job read. Cancellation and execution claim use the same queued-state compare-and-set. Repeating a successful cancellation returns its receipt; a claimed or finished job returns maintenance_not_cancellable. Cancelling never claims to stop a command that has already reached the server.

```bash
techstack api servers maintenance cancel <server-id> <job-id> [flags]
```

| HTTP | `POST /api/v1/servers/{serverId}/actions/{jobId}/cancel` |

| `<job-id>` | string | **Required.** |

## techstack api servers maintenance impact

Preview service and stack impact before confirming OS maintenance.

Requires the signed maintenance entitlement and ownership of the server. Lists canonical service placement and stack membership, with reasons and inventory freshness and completeness. An empty services array means no affected services only when inventory.status is current. An incomplete, stale or unavailable inventory cannot authorize maintenance. The digest binds the server, operation and material dependency snapshot; ordinary observation timestamps do not invalidate unchanged impact. Responses are private and must not be cached.

```bash
techstack api servers maintenance impact <server-id> [flags]
```

| --- | --- |
| HTTP | `GET /api/v1/servers/{serverId}/maintenance-impact` |
| Changes state | No |

| --- | --- | --- |
| `<server-id>` | string | **Required.** Canonical server runtime ID. |
| `--action` | string | **Required.** One of `os_update`, `reboot`. |

## techstack api servers maintenance run

ضع خطة تحديث نظام التشغيل أو تحديثه أو إعادة تشغيل خادم مملوك في قائمة الانتظار.

Requires the Edge-signed `techstack.servers.maintenance` entitlement, ownership of the server in the tenant, and current server-bound standing authority for delegated native MCP calls. These three ordinary actions require no fresh MFA or separate owner_approved assertion. Reboot and os_update require expected_impact_digest from the preview the user confirmed. Impact is compared atomically at admission and again at execution claim; changed or incomplete evidence sends no command and requires a refreshed preview and renewed confirmation with a new request key. The body is decoded strictly: exact lowercase keys, no duplicates, no unknown fields. A replay with the same Idempotency-Key returns the stored receipt before target validation. One reboot or OS update and, separately, one update plan may be active per server; a job not finished by its deadline fails with `deadline_exceeded` and frees its slot. The action is offered in `allowed_actions` only when the server agent advertises `stackkit.host-maintenance.v1`, and `reboot` only when the server also reports `host_boot_id`. Refusals are client-error-envelope/v1 documents; 409 `reason_code` is one of control_plane_host, substrate_node, protected_demo_server, service_locked, maintenance_active, node_operation_active, plan_stale, agent_capability_missing, boot_id_unknown, agent_not_connected, heartbeat_stale, inventory_revision_stale, idempotency_key_reused, impact_confirmation_required, impact_changed or impact_unavailable; 403 carries entitlement_required or maintenance_origin_authority_denied.

```bash
techstack api servers maintenance run <server-id> [flags]
```

| --- | --- |
| HTTP | `POST /api/v1/servers/{serverId}/actions` |
| يغيّر الحالة | نعم |

| `--expected-impact-digest` | string | Required for os_update and reboot, forbidden for os_update_plan. snapshot_digest of the current impact preview confirmed for this exact server and action. Changing it under an existing Idempotency-Key is a conflict; a renewed confirmation uses a new key. |

## techstack api servers reach set

لا يُنشر شيء افتراضيًا: لا يملك الخادم المقترن مسارًا عامًا، ولا ينقل المرحّل حركة مرور. يفعّله المالك لكل خادم باسم `service` صريح و`target_port`، ويمكنه سحبه في أي وقت؛ ويكون المصدر دائمًا عنوان loopback لمضيف Guard، لا جهازًا آخر. يصادق المرحّل على Guard لا على الزائر، لذا يجب أن تحمي الخدمة التي تجيب على ذلك المنفذ نفسها. يتطلب التفعيل المالك واستحقاق `techstack.servers.maintenance` وتسجيل دخول حديثًا متعدد العوامل، بسبب `server_reach_step_up_required`؛ أما السحب فلا يخضع لهذا الشرط. تتضمن الاستجابة قسم reach من نموذج قراءة الخادم؛ ثم ينشئ المُوفّق المسار أو يسحبه.

techstack api servers reach set <server-id> [flags]

## techstack api servers security verify

اطلب من kombify Guard رصدًا حديثًا لأمن المضيف.

يسجّل طلب رصد حديث لخط أساس المضيف. يجيب Guard في اتصاله الدوري التالي، خلال نحو دقيقة، بتقرير جديد؛ ولا يتغير شيء على المضيف. يُحدَّث نموذج قراءة `security` للخادم بهذا التقرير فقط، لا بهذا الطلب مطلقًا. يُرجع خادم مستأجر أو مالك آخر 404، والخادم الذي بلا Guard يعيد 409 `guard_not_connected`.

```bash
techstack api servers security verify <server-id> [flags]
```

| | |
| --- | --- |
| HTTP | `POST /api/v1/servers/{serverId}/security/verify` |
| يغيّر الحالة | نعم |
| أداة MCP | لا توجد |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `<server-id>` | string | **مطلوب.** معرّف تشغيل الخادم المعتمد. |

## techstack api servers summary

قراءة ملخص وجود الخوادم للمالك المصادَق عليه.

يُرجع فقط عدداً وعلامة وجود ضمن نطاق سياسة المستأجر والمالك نفسه الخاص بقائمة الجرد القياسية. يوجد استعلام tenant الاختياري للتوافق مع Gateway ويجب أن يطابق تماماً المستأجر في الهوية المصادَق عليها؛ ويُرفض عدم التطابق قبل أي قراءة من المخزن. ولا تُرجَع أي معرّفات للخوادم أو المستأجرين أو الكيانات.

```bash
techstack api servers summary [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/servers/summary` |
| يغيّر الحالة | لا |
| أداة MCP | لا شيء |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `--tenant` | string | — |

## techstack api servers transitions

عرض الخط الزمني المحفوظ لحالة الخادم.

```bash
techstack api servers transitions <server-id> [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/servers/{serverId}/transitions` |
| يغيّر الحالة | لا |
| أداة MCP | `list_server_runtime_transitions` |

| الوسيط | النوع | الوصف |
| --- | --- | --- |
| `<server-id>` | string | **مطلوب.** معرّف وقت تشغيل الخادم القياسي. |
