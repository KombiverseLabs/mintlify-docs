يتضمن Basement Kit المُصدَر دورة نسخ احتياطي محلية بـ Kopia يتحكم بها المالك. شغّلها فقط من مساحة عمل StackKits المطبَّقة التي تنوي حماية بياناتها.

اجعل تمرين الاستعادة جزءاً من الإعداد، لا مهمة لاحقة.

## تمرّن على الاسترداد قبل استيراد بيانات مهمة

1. طبّق Basement Kit وتحقق منه.
2. تأكد من أن جذري البيانات الأساسية والنسخ الاحتياطي منفصلان.
3. اضبط المستودع وأنشئ لقطة بالأوامر أدناه.
4. استعد تلك اللقطة إلى منطقة مؤقتة معزولة وراجع النتيجة.
5. تحقق من الخدمات مجدداً بعد أي تفعيل. التحقق بعد الاسترداد لا يقل أهمية عن اللقطة.

كرر التمرين بعد أي تغيير جوهري في التخزين أو الـ workload أو الإصدار.

## ضبط المستودع وفحصه

```bash
stackkit backup configure --json
stackkit backup status --json
```

تُشتق أصول المستودع ومجموعة المصادر والاستثناءات والحيازة المحلية من الخطة المحلولة. لا توجّه الأمر إلى وحدة تخزين عشوائية ولا تتجاوز حيازة المالك.

### ما الذي تغطيه اللقطة

يحدد `backupPolicy.coverage` في الخطة أصناف البيانات التي تأخذها اللقطة. هناك ثلاث مجموعات متداخلة، والـ stack الذي لا اشتراك خلفه يُحلّ إلى `content`:

| التغطية | ما الذي تختاره |
| --- | --- |
| `config` | إعدادات الـ stack والمواد السرية وحالة المنصة وإعدادات serverless |
| `content` | ما سبق إضافة إلى قواعد البيانات ومحتوى المستخدم والمستندات والسلاسل الزمنية للقياس عن بُعد |
| `media` | ما سبق إضافة إلى أصول الصور والوسائط الكبيرة |

الوسائط تُختار ولا تُورَّث. تهيمن مكتبات الصور والفيديو على حجم المستودع، فلن تسحب البذرة الأولى مكتبة منها بصمت: اختر `media` عندما تريدها.

يعرض ناتج الحالة أعلاه وحدات التخزين والاستثناءات الدقيقة التي اختارها الإعداد المطبَّق، وهذا هو الجواب عن سؤال "ماذا ستحتوي اللقطة التالية". مجموعة التغطية هي ما طلبته الخطة؛ وناتج الحالة هو ما حُلَّ إليه إعداد مطبَّق واحد.

## إنشاء لقطة متكافئة (idempotent)

```bash
stackkit backup run --operation-id before-upgrade-2026-08-11 --json
```

احتفظ بمرساة اللقطة المُعنوَنة بالمحتوى المُعادة مع أدلة التحقق لديك. إعادة استخدام معرّف العملية نفسه تُعيد العملية الموجودة بدلاً من إنشاء نسخة مكررة عن غير قصد.

## الاستعادة إلى منطقة مؤقتة معزولة

```bash
stackkit backup restore sha256:<snapshot-anchor-id> \
  --owner-approve \
  --operation-id restore-check-2026-08-11 \
  --json
```

يتحقق هذا من اللقطة ويستخرجها إلى منطقة مؤقتة يملكها CUE. ولا يستبدل البيانات الحية. راجع معرّف نتيجة الاستعادة المُعاد قبل المتابعة.

## تفعيل الاستعادة المتحقَّق منها

```bash
stackkit backup restore activate sha256:<restore-result-id> \
  --owner-approve \
  --operation-id restore-activation-2026-08-11 \
  --json
```

ينشئ التفعيل اللقطة الأمنية المطلوبة، ويبدّل مجموعة وحدات التخزين المملوكة للخطة بدقة، ويعيد تشغيل بيئة التشغيل، ويتحقق من ربط المالك والخدمات.

إذا انقطع التفعيل، فاسترد العملية المحددة صراحةً:

```bash
stackkit backup restore recover restore-activation-2026-08-11 \
  --owner-approve \
  --rollback \
  --json
```

<Warning>
  النسخ الاحتياطي الناجح ليس دليلاً على الاسترداد. تمرّن على الاستعادة المرحلية ببيانات غير حرجة قبل الاعتماد على الـ stack لملفات لا تُعوَّض.
</Warning>
