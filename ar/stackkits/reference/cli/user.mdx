دعوة مستخدمي الأسرة وإدارتهم في PocketID المحلي.

أنشئ مستخدمي Homelab في مجموعة الأسرة في PocketID واعرضهم وأزلهم.

يطبع add عنوان URL لإعداد passkey لمرة واحدة. يواصل TinyAuth قبول مجموعات المالكين والمسؤولين والأسرة المرتبطة بالفعل بعميل OIDC. لا يمكن إنشاء هويات المالك والمسؤول أو إزالتها هنا.

```bash
stackkit user [flags]
```

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--json` | bool | — | أخرج JSON بصيغة stackkit.command-result/v1 |

**أمثلة**

```bash
# Invite a household member; share the printed one-time URL only with them
stackkit user add alex --email alex@example.com --owner-approve

# List household users
stackkit user list

# Remove a household user
stackkit user remove alex --owner-approve
```

الأوامر الفرعية: [`stackkit user activate`](#stackkit-user-activate)، [`stackkit user add`](#stackkit-user-add)، [`stackkit user files`](#stackkit-user-files)، [`stackkit user list`](#stackkit-user-list)، [`stackkit user owner`](#stackkit-user-owner)، [`stackkit user remove`](#stackkit-user-remove)

## stackkit user add

ادعُ مستخدمًا من الأسرة بعنوان URL لإعداد passkey لمرة واحدة.

```bash
stackkit user add <username> [flags]
```

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--display-name` | string | — | اسم عرض اختياري |
| `--email` | string | — | **مطلوب.** البريد الإلكتروني لفرد الأسرة |
| `--owner-approve` | bool | — | وافق صراحةً على إنشاء مستخدم الأسرة هذا |

موروثة من `stackkit user`:

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--json` | bool | — | أخرج JSON بصيغة stackkit.command-result/v1 |

**أمثلة**

```bash
# Invite a household member and print their one-time passkey setup URL
stackkit user add alex --email alex@example.com --owner-approve

# Set a display name and return the invitation as JSON
stackkit user add sam --email sam@example.com --display-name "Sam Doe" --owner-approve --json
```

## stackkit user files

استئناف حسابات المنزل المحلية لتطبيق Files وتسليمها.

يحتفظ Cloudreve CE بحساب محلي للتطبيق خلف TinyAuth. تجعل هذه الأوامر ذلك الحساب متوافقًا مع هوية منزل معتمدة في PocketID، ولا تكشف كلمة المرور الموجودة في حيازة المالك إلا عند طلب صريح.

```bash
stackkit user files [flags]
```

موروث من `stackkit user`:

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--json` | bool | — | إصدار JSON بصيغة stackkit.command-result/v1 |

الأوامر الفرعية: [`stackkit user files credential`](#stackkit-user-files-credential)، [`stackkit user files ensure`](#stackkit-user-files-ensure)

### stackkit user files credential

طباعة كلمة مرور منزل واحدة لـ Files في حيازة المالك.

التحقق من هوية المنزل المعتمدة في PocketID وحساب Cloudreve غير الإداري المرتبط بها، ثم طباعة كلمة المرور القائمة من الحيازة المحلية الموقّعة للمالك. يحتوي الناتج على مادة سرية؛ فلا تستخدمه إلا في طرفية خاصة أو أنبوب مقصود.

```bash
stackkit user files credential <username> [flags]
```

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | الموافقة الصريحة على كشف كلمة مرور Files هذه |

موروث من `stackkit user`:

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--json` | bool | — | إصدار JSON بصيغة stackkit.command-result/v1 |

### stackkit user owner migrate-domain

تجهيز ترحيل الهوية من home إلى lab.home بموافقة المالك.

الحفاظ على المالك وCA وأسرار الخدمات والمستخدمين الحاليين أثناء ترحيل نية Basement وحيازة وقت التشغيل من home إلى lab.home. احتفظ بملف CLI للإصدار السابق والأدوات المعبأة ومرآة المزوّد قبل استخدام CLI هدف معزول لهذا الأمر. يفوّض `--quiesce-runtime` الأمر لالتقاط هويات حاويات Core المصدر الدقيقة، وجعل رد نداء الهوية متوافقًا بينما يتوفر PocketID، ثم إيقاف تلك الحاويات وحدها وإزالتها بسلاسة دون حذف وحدات التخزين أو الشبكات أو الصور. استخدم CLI السابق لـ generate وapply وverify، ثم استخدم CLI الهدف لـ upgrade `--to` &lt;exact-release&gt;. تغطي نقطة تحقق الترقية الإصدار السابق المرحّل على lab.home؛ ولا ينشئ هذا الأمر نقطة تحقق للتراجع إلى النطاق الأصلي. ينتظر جسر v0.47.4 التأهيل على مضيف حقيقي. بعد الطرح، سجّل DNS للعملاء ومفاتيح مرور جديدة على id.lab.home.

```bash
stackkit user owner migrate-domain [flags]
```

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | الموافقة الصريحة على ترحيل النطاق وتسجيل مفاتيح مرور جديدة |
| `--quiesce-runtime` | bool | — | إيقاف حاويات Core المصدر الموثّقة وإزالتها بسلاسة دون حذف الموارد الدائمة |
| `--spec` | string | `stack-spec.yaml` | StackSpec نسبةً إلى مساحة العمل المطلوب ترحيلها |

موروث من `stackkit user`:

| الخيار | النوع | الافتراضي | الوصف |
| --- | --- | --- | --- |
| `--json` | bool | — | إصدار JSON بصيغة stackkit.command-result/v1 |
