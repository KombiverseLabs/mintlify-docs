يوفّر Gitea حالة الاستخدام [Development](/ar/guides/stackkits/use-cases/development). يشغّل حمل عمل التطوير مع Gitea خادم Git خاصًا في حاوية بلا صلاحيات الجذر (rootless) مع SQLite على عقدة واحدة مختارة. التسجيل العام معطّل والمستودعات الجديدة تُفرض خاصة. ولا يكشف SSH ولا يثبّت مشغّل CI ولا يفعّل Actions؛ أما سير العمل للمستخدمين الإضافيين ورموز API فتبقى عمليات Gitea الأصلية. يسرد [كتالوج حالات الاستخدام](/ar/stackkits/reference/use-case-catalog) المكوّنات التي يعلنها الإصدار المنشور.

## اختيار حمل عمل التطوير صراحةً

من مساحة عمل مالك فارغة، اختر Gitea وأنشئ حفظ المالك المحلي له:

```bash
stackkit init basement-kit --platform standalone-compose \
  --use-case dev --use-case-alternative dev=gitea \
  --use-case-alternative basement-core=standalone \
  --module-compute-profile stackkits-basement-core-runtime=standard \
  --module-compute-profile stackkits-gitea-runtime=standard \
  --owner-source local --owner-email owner@example.com --non-interactive
```

قبل التوليد، ادمج الحقول التالية في أقسام `capabilities` و`data` و`routes` الموجودة في [StackSpec](/ar/guides/stackkits/configure-stack-spec) لديك. حافظ على بقية مدخلاتها. يستخدم هذا المقتطف الموقع الأولي `home` وسياسة الوصول `home-private`؛ كيّف تلك المراجع ونطاق المنزل وجذور تخزين المضيف مع مضيفك الفعلي.

```yaml
capabilities:
  enable: [internal-pki]
data:
  bindings:
    dev:
      classes: [personal]
      primarySiteRef: home
routes:
  dev:
    serviceRef: dev
    moduleRef: stackkits-gitea-runtime
    exposure: local
    protocol: https
    port: 443
    targetPort: 3000
    host: dev.home.test
    path: /
    accessPolicyRef: home-private
```

يتطلب Gitea مسار HTTPS وربط بيانات صريحين هذين للحصول على عناوين استنساخ أصلية قابلة للاستخدام. تحقق من النتيجة وولّدها:

```bash
stackkit validate
stackkit generate --local-node main --local-site home
```

ثم اتبع دورة التسليم المعتادة: تحقق، وافحص الخطة، وطبّق وتحقق كما هو موثّق في [المراجعة والتطبيق والتحقق](/ar/guides/stackkits/review-plan-and-apply). يجب أن يفي جرد المضيف المرصود بملفات تعريف الوحدات المختارة؛ وإعدادات المثال ليست دليلًا على العتاد.

## توفير الاسم والوثوق بالمسار

يحتاج Git عبر HTTPS الأصلي إلى أمرين يجب أن يستوفيهما مضيفك مسبقًا:

- يجب أن يُحلّ اسم مضيف المسار (يستخدم المثال `dev.home.test`) إلى ذلك المضيف من كل عميل تنوي الاستنساخ منه.
- يجب أن تثق عملاء Git بشهادة المرجع الداخلي (CA) للمضيف. ومن دون ثقة العميل يفشل الاستنساخ عبر HTTPS قبل المصادقة.

## كشف كلمة مرور المالك وتسجيل الدخول

يرحّل أول بدء تشغيل قاعدة بيانات SQLite وينشئ المسؤول `owner` قبل خدمة الحركة؛ ويأتي بريد المالك من هوية المالك المحلية لديك، ويُحفظ مرجع `owner-password` في حفظ الأسرار المحلي القائم. اقرأ كلمة المرور في طرفية خاصة:

```bash
stackkit secrets reveal --workload dev --slot owner-password
```

يقبل الأمر فقط الخانات المعلنة في StackSpec الحالي الذي جرى التحقق منه، ويكتب القيمة إلى stdout ولا يكتبها أبدًا في سجلات النشر، ولا ينشئ كلمة مرور ولا يعيد ضبطها. وأي مسؤول قائم غير مطابق أو قاعدة بيانات مستخدمين بلا مالك يُفشل التسليم دون استبدال الحسابات أو إعادة ضبط كلمات المرور.

سجّل الدخول بصفتك `owner`، وأنشئ مستودعًا خاصًا، واستخدم عنوان استنساخه عبر HTTPS مع تخزين بيانات اعتماد Git الأصلي لديك. يصادق Git مباشرةً لدى Gitea: لا توجد بوابة مصادقة أمامية في المتصفح تعترض طلبات Git. والجاهزية التي تبلّغ فقط عن إمكانية الوصول إلى عملية HTTP وSQLite لا تثبت أنك استنسخت أو دفعت أو استرددت أي شيء — اختبر دفعًا فعليًا من عميل تنوي استخدامه.

## حدود التخزين والاسترداد

| المخصص | مسار الحاوية | المحتويات |
| --- | --- | --- |
| `gitea/data` | `/var/lib/gitea` | قاعدة بيانات SQLite والمستودعات وكائنات LFS وبيانات التطبيق |
| `gitea/config` | `/etc/gitea` | `app.ini` ومفاتيح التطبيق والإعدادات المحفوظة |

تنتمي وحدتا التخزين المسمّاتان إلى عقد البيانات والنسخ الاحتياطي لحمل العمل. يقوم الاسترداد الصحيح بإيقاف كاتب التطبيق الوحيد مؤقتًا والتقاط الوحدتين وتفعيلهما معًا مع إيقاف الكتابة — ونسخة حية من ملف SQLite وحده ليست ذلك العقد. اتبع [النسخ الاحتياطي والاستعادة](/ar/guides/stackkits/back-up-and-restore) لدورة حياة مساحة العمل. يستخدم Gitea بصلاحيات الجذر وGitea بلا صلاحيات الجذر تخطيطين مختلفين، لذا فإن تبديل الصورة ليس ترحيلًا للتخزين.

## حدود معروفة

- لا يُكشف SSH؛ وHTTPS الأصلي هو مسار الوصول الموثّق إلى Git.
- لا يُثبَّت Gitea Actions ولا مشغّلات CI؛ وليس لتكامل المشغّلات مسار موثّق بعد.
- يحتفظ إعادة إنشاء الحاوية القسرية بوصول المالك وبيانات المستودعات الخاصة الوصفية وإعدادات التطبيق، لكن تجهيز مضيف Linux الكامل وتوزيع DNS/CA الحقيقي على الشبكة المحلية ودورة نسخ احتياطي/استعادة كاملة هي مستويات أدلة منفصلة ولم تثبت هنا.
