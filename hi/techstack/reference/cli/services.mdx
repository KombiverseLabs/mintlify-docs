## techstack api services execute-application-adoption

स्पष्ट Owner मंज़ूरी के साथ ठीक समीक्षा किया गया सोर्स प्लान चलाएँ।

संरक्षित डाइजेस्ट, सोर्स पहचान, रिविज़न और रिलीज़ फिर सत्यापित करता है। केवल प्रमाणित पिन की गई CLI की कस्टडी रसीद सदस्यता स्थापित करती है। खाते, कॉन्फ़िगरेशन और स्थायी डेटा सुरक्षित रहते हैं; कोई नया रनटाइम नहीं बनता। दूसरे Node पर ले जाना और सामान्यीकृत अपनाना समर्थित नहीं हैं।

```bash
techstack api services execute-application-adoption [flags]
```

| | |
| --- | --- |
| HTTP | `POST /api/v1/services/{serviceId}/adoption-plans/{planId}/execute` |
| स्टेट बदलता है | हाँ |
| MCP टूल | `execute_application_adoption` |

| आर्ग्युमेंट | प्रकार | विवरण |
| --- | --- | --- |
| `--service-id` | string | **आवश्यक।** कैनोनिकल सेवा रनटाइम ID। |
| `--plan-id` | string | **आवश्यक।** |
| `--expected-inventory-revision` | integer | **आवश्यक।** |
| `--mode` | string | इनमें से एक: `adopt_in_place`. |
| `--owner-approved` | boolean | डिफ़ॉल्ट `false`. |
| `--plan-digest` | string | — |
| `--body` | json | JSON रिक्वेस्ट बॉडी (`application/json`) लिटरल के रूप में, `@path` के रूप में, या stdin के लिए `-`। |

## techstack api services run-action

ओनर द्वारा अधिकृत StackKits सेवा एक्शन कतार में डालें।

ताज़ा कैनोनिकल इन्वेंटरी से स्टैक, सर्वर, एजेंट, kit और सेवा अथॉरिटी निकालता है। सटीक रीप्ले एक टिकाऊ जॉब रसीद के ज़रिए एक ही परिणाम पर पहुँचते हैं; रॉ Idempotency-Key कभी सहेजी नहीं जाती। हर बदलाव के बाद, मापी गई स्टेट बदलने से पहले StackKits verify चलता है। जब सर्वर रीबूट या अपडेट हो रहा हो, तब एजेंट द्वारा निष्पादित एक्शन 409 `maintenance_active` के साथ अस्वीकार होते हैं।

```bash
techstack api services run-action <service-id> [flags]
```

| | |
| --- | --- |
| HTTP | `POST /api/v1/registry/services/{serviceId}/actions` |
| स्टेट बदलता है | हाँ |
| MCP टूल | `run_managed_service_action` |

| आर्ग्युमेंट | प्रकार | विवरण |
| --- | --- | --- |
| `<service-id>` | string | **आवश्यक।** कैनोनिकल सेवा रनटाइम ID। |
| `--body` | json | **आवश्यक।** JSON रिक्वेस्ट बॉडी (`application/json`) लिटरल के रूप में, `@path` के रूप में, या stdin के लिए `-`। |

## techstack api services setup-application-connector

अपने नोड पर एक घोषित अपने Home Assistant कनेक्टर को सुनिश्चित करें या रद्द करें।

ताज़ा बैकएंड स्वामित्व, सकारात्मक operate प्राधिकरण, ठीक वर्तमान इन्वेंटरी और Owner मंज़ूरी चाहिए। केवल निर्धारित सहसंबंध मेटाडेटा Guard से प्रकाशित पिन की गई CLI तक पहुँचाता है; उसकी स्थानीय signedApply और Owner सेटअप प्राधिकरण आवश्यक रहते हैं। भेजने से पहले टिकाऊ इंटेंट सहेजता है; अज्ञात पुष्टि पर केवल मूल ऑपरेशन का केवल-पठन मिलान होता है। वर्तमान v0.51.8 में सहायक कैटलॉग नहीं है और गैर-निष्पादन योग्य SourcePreview लौटता है। क्रेडेंशियल नोड की कस्टडी में रहते हैं।

```bash
techstack api services setup-application-connector [flags]
```

<Warning>पुष्टि आवश्यक है: यह ऑपरेशन इसी सेवा के लिए समीक्षा किए गए नोड-स्वामित्व वाले Home Assistant कनेक्टर क्रेडेंशियल जारी या रद्द करता है। `--yes` दें या प्रॉम्प्ट का उत्तर दें; `--yes` के बिना गैर-इंटरैक्टिव रन किसी भी रिक्वेस्ट से पहले एग्ज़िट कोड 9 के साथ रुक जाता है।</Warning>

| --- | --- |
| HTTP | `POST /api/v1/services/{serviceId}/connector` |
| स्टेट बदलता है | हाँ |
| MCP टूल | `setup_application_connector` |

| आर्ग्युमेंट | प्रकार | विवरण |
| --- | --- | --- |
| `--service-id` | string | **आवश्यक।** कैनोनिकल सेवा रनटाइम ID। |
| `--action` | string | **आवश्यक।** इनमें से एक: `ensure`, `revoke`. |
| `--expected-inventory-revision` | integer | **आवश्यक।** |
| `--lifespan-days` | integer | **आवश्यक।** |
| `--owner-approved` | boolean | **आवश्यक।** इनमें से एक: `true`. |
| `--body` | json | JSON रिक्वेस्ट बॉडी (`application/json`) लिटरल के रूप में, `@path` के रूप में, या stdin के लिए `-`। |
