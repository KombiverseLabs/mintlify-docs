स्थानीय PocketID में घरेलू उपयोगकर्ताओं को आमंत्रित करें और प्रबंधित करें।

PocketID household समूह में Homelab उपयोगकर्ता बनाएँ, सूचीबद्ध करें और हटाएँ।

Add एक बार उपयोग होने वाला पासकी सेटअप URL प्रिंट करता है। TinyAuth उन ओनर, एडमिन और household समूहों को प्रवेश देता रहता है जो OIDC क्लाइंट पर पहले से बंधे हैं। ओनर और एडमिन पहचान यहाँ बनाई या हटाई नहीं जा सकतीं।

```bash
stackkit user [flags]
```

| Flag | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `--json` | bool | — | stackkit.command-result/v1 JSON जारी करें |

**उदाहरण**

```bash
# Invite a household member; share the printed one-time URL only with them
stackkit user add alex --email alex@example.com --owner-approve

# List household users
stackkit user list

# Remove a household user
stackkit user remove alex --owner-approve
```

Subcommands: [`stackkit user activate`](#stackkit-user-activate), [`stackkit user add`](#stackkit-user-add), [`stackkit user apps`](#stackkit-user-apps), [`stackkit user files`](#stackkit-user-files), [`stackkit user list`](#stackkit-user-list), [`stackkit user owner`](#stackkit-user-owner), [`stackkit user remove`](#stackkit-user-remove)

## stackkit user add

एक बार उपयोग होने वाले पासकी सेटअप URL के साथ घरेलू उपयोगकर्ता को आमंत्रित करें।

```bash
stackkit user add <username> [flags]
```

| Flag | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `--app` | stringArray | — | Node app this member may sign into (repeatable); without it the member can use every app |
| `--display-name` | string | — | वैकल्पिक डिस्प्ले नाम |
| `--email` | string | — | **आवश्यक।** घर के सदस्य का ईमेल |
| `--owner-approve` | bool | — | इस घरेलू उपयोगकर्ता को बनाने को स्पष्ट रूप से स्वीकृत करें |

`stackkit user` से विरासत में मिले:

| Flag | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `--json` | bool | — | stackkit.command-result/v1 JSON जारी करें |

**उदाहरण**

```bash
# Invite a household member and print their one-time passkey setup URL
stackkit user add alex --email alex@example.com --owner-approve

# Set a display name and return the invitation as JSON
stackkit user add sam --email sam@example.com --display-name "Sam Doe" --owner-approve --json
```

## stackkit user apps

Set which node apps a household user may sign into.

```bash
stackkit user apps <username> [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--all` | bool | — | Allow every app |
| `--app` | stringArray | — | App the member may sign into (repeatable) |
| `--none` | bool | — | Allow no app |
| `--owner-approve` | bool | — | Explicitly approve changing this member's apps |

Inherited from `stackkit user`:

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--json` | bool | — | Emit stackkit.command-result/v1 JSON |

**Examples**

```bash
# Allow Photos and Files only
stackkit user apps alex --app photos --app files --owner-approve

# Allow every app again
stackkit user apps alex --all --owner-approve
```

## stackkit user files


स्वीकृत PocketID घरेलू पहचान और उसके गैर-एडमिन Cloudreve अकाउंट को सत्यापित करें, फिर हस्ताक्षरित स्थानीय-ओनर कस्टडी से मौजूदा पासवर्ड प्रिंट करें। आउटपुट में सीक्रेट सामग्री होती है; इसे केवल निजी टर्मिनल या जानबूझकर बनाई गई पाइप में उपयोग करें।


| Flag | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | यह Files पासवर्ड दिखाने की स्पष्ट स्वीकृति दें |

### stackkit user owner migrate-domain

ओनर द्वारा स्वीकृत home से lab.home पहचान माइग्रेशन तैयार करें।

Basement के आशय और रनटाइम कस्टडी को home से lab.home पर माइग्रेट करते हुए मौजूदा ओनर, CA, सेवा सीक्रेट और उपयोगकर्ता सुरक्षित रखें। इस कमांड के लिए अलग लक्ष्य CLI उपयोग करने से पहले पिछली रिलीज़ की CLI, पैकेज किए गए टूल और provider mirror सुरक्षित रखें। `--quiesce-runtime` कमांड को सटीक स्रोत Core कंटेनर पहचान कैप्चर करने, PocketID उपलब्ध रहते हुए पहचान callback को अभिसरित करने, फिर केवल उन्हीं कंटेनर को शालीनता से रोकने और हटाने की अनुमति देता है, और कोई वॉल्यूम, नेटवर्क या इमेज नहीं हटाता। generate, apply और verify के लिए पिछली CLI उपयोग करें, फिर upgrade `--to` &lt;exact-release&gt; के लिए लक्ष्य CLI उपयोग करें। अपग्रेड चेकपॉइंट lab.home पर माइग्रेट हुई पिछली रिलीज़ को कवर करता है; यह कमांड मूल डोमेन का rollback चेकपॉइंट नहीं बनाता। v0.47.4 ब्रिज वास्तविक होस्ट योग्यता की प्रतीक्षा में है। रोलआउट के बाद id.lab.home पर क्लाइंट DNS और नई passkey एनरोल करें।

```bash
stackkit user owner migrate-domain [flags]
```

| Flag | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | डोमेन माइग्रेशन और नई passkey एनरोलमेंट की स्पष्ट स्वीकृति दें |
| `--quiesce-runtime` | bool | — | प्रमाणित स्रोत Core कंटेनर को शालीनता से रोकें और हटाएँ, स्थायी संसाधन हटाए बिना |
| `--spec` | string | `stack-spec.yaml` | माइग्रेट किया जाने वाला वर्कस्पेस-सापेक्ष StackSpec |

`stackkit user` से मिला:

| Flag | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `--json` | bool | — | stackkit.command-result/v1 JSON जारी करें |

### stackkit user owner reconcile

Enable legacy TinyAuth PKCE only against the verified existing Owner binding.

Requires explicit Owner approval and an idle native lifecycle. Verifies every existing Owner, client, callback and group binding before enabling PKCE, then verifies again. Keeps Owner keys, users, groups, client secret, enrollment links, Plan and release pin. Other identity drift fails closed. On a managed server invoke through authorized Techstack server access; this performs no Advanced apply or provider execution.

```bash
stackkit user owner reconcile [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | Explicitly approve PKCE-only convergence of the existing verified identity binding |

Inherited from `stackkit user`:

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--json` | bool | — | Emit stackkit.command-result/v1 JSON |
