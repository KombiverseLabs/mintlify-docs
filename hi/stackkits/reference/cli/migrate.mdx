StackSpec v1 को वर्गीकृत करें और उसकी माइग्रेशन रिपोर्ट जारी करें।

एक StackSpec को बिना हानि के वर्गीकृत करें और सीमित v1-से-v2 माइग्रेशन एडाप्टर चलाएँ। परिणाम में हमेशा पूरी माइग्रेशन रिपोर्ट होती है और, केवल निर्धारक होने पर, सिर्फ़ आर्किटेक्चर वाला माइग्रेशन प्रक्षेपण।

महत्वपूर्ण: `--complete-with` के बिना प्रक्षेपण CUE-मान्य StackSpec v2 नहीं है, ResolvedPlan नहीं है, और जनरेशन या डिप्लॉयमेंट को अधिकृत नहीं करता। पहले रिपोर्ट की गई मैन्युअल कार्रवाइयाँ पूरी करें और पूरा StackSpec v2 CUE रिज़ॉल्यूशन से गुज़ारें।

`--complete-with` एक पूरा स्पष्ट StackSpec v2 स्वीकार करता है, कभी आंशिक ओवरले नहीं। यह निर्धारक लेगेसी Site, नोड और हार्डवेयर बाइंडिंग का मिलान करता है, फिर एम्बेडेड शासित Architecture v2 प्राधिकार उपयोग करता है। पूरे हुए परिणाम में स्पष्ट कैनोनिकल उम्मीदवार और उसका ResolvedPlan हैश होता है। जनरेटर की पात्रता CUE वैधता से अलग रिपोर्ट होती है और ResolvedPlan की तैयारी का अनुसरण करती है।

`--spec-output` पूरे हुए सटीक कैनोनिकल StackSpec v2 को निर्धारक JSON के रूप में लिखता है। यह केवल `--complete-with` के साथ मान्य है, कभी इन-प्लेस पुनर्लेखन पर डिफ़ॉल्ट नहीं होता और मौजूदा कैनोनिकल लक्ष्य को बदलने से मना करता है; कैनोनिकल प्रतिस्थापन के लिए स्पष्ट CAS-अधिकृत StackSpec ऑथरिंग प्रवाह चाहिए।

shadow-resolution के लिए तैयार परिणाम सफलतापूर्वक समाप्त होता है। अवरुद्ध परिणाम भी मशीन-पठनीय आउटपुट के रूप में जारी होता है, फिर कमांड विफलता के साथ समाप्त होती है। Context केवल लेगेसी स्थान और Pi हार्डवेयर को मैप करता है; यह कभी Kit नहीं चुनता।

```bash
stackkit migrate [v1-spec-file] [flags]
```

| Flag | प्रकार | डिफ़ॉल्ट | विवरण |
| --- | --- | --- | --- |
| `--complete-with` | string | — | एम्बेडेड प्राधिकार के साथ मिलान और रिज़ॉल्व करने के लिए पूरा स्पष्ट StackSpec v2 उम्मीदवार (कभी आंशिक ओवरले नहीं) |
| `--force` | bool | — | मौजूदा माइग्रेशन परिणाम आउटपुट को परमाणु रूप से बदलें; कैनोनिकल StackSpec आउटपुट के लिए नया पथ चाहिए |
| `--format` | string | `json` | मशीन-पठनीय आउटपुट फ़ॉर्मैट: json या yaml |
| `--output, -o` | string | — | माइग्रेशन परिणाम को stdout के बजाय वर्किंग डायरेक्टरी के नीचे लिखें |
| `--spec-output` | string | — | पूरे हुए कैनोनिकल StackSpec v2 को निर्धारक JSON के रूप में वर्किंग डायरेक्टरी के नीचे लिखें (`--complete-with` आवश्यक) |
| `--target-kit` | string | — | प्राधिकार द्वारा समर्थित स्पष्ट लक्ष्य KitProfile (कभी context से अनुमानित नहीं) |

**उदाहरण**

```bash
# Classify a StackSpec v1 and print its migration report
stackkit migrate stack-spec.yaml

# Report the migration toward an explicit target Kit
stackkit migrate legacy.yaml --target-kit cloud-kit

# Reconcile with a full StackSpec v2 and write the completed canonical spec
stackkit migrate legacy.yaml --target-kit basement-kit --complete-with explicit-v2.yaml --spec-output stack-spec.v2.json

# Print the report as YAML
stackkit migrate legacy.yaml --format yaml

# Write the report to a file beneath the working directory
stackkit migrate legacy.yaml --output .stackkit/migration-result.json
```
