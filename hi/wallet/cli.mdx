<Note>
kombify Wallet अभी जारी नहीं हुआ है, और कमांड लाइन भी अभी वितरित नहीं की जा रही। यह पेज बताता है कि यह कैसे काम करती है। इंस्टॉल के चरण यहाँ तब जोड़े जाएँगे जब यह उपलब्ध होगी।
</Note>

`kombify-wallet` आपके टर्मिनल में Wallet ले आता है। ब्राउज़र की तरह, यह मान को आपके डिवाइस से निकलने से पहले उसी डिवाइस पर एन्क्रिप्ट करता है। यह मान केवल स्टैंडर्ड इनपुट या छिपे हुए प्रॉम्प्ट से पढ़ता है, कभी आर्ग्युमेंट से नहीं, इसलिए वे आपकी शेल हिस्ट्री और प्रोसेस सूची में नहीं आते।

## साइन इन करें

```bash
kombify-wallet login
```

कमांड एक लिंक और एक कोड छापती है। लिंक खोलें, Auth0 के ज़रिए अपने kombify खाते में साइन इन करें और कोड की पुष्टि करें। कमांड अपना साइन-इन ऐसी फ़ाइल में रखती है जिसे केवल आप पढ़ सकते हैं।

`kombify-wallet status` दिखाता है कि कौन साइन इन है, और `kombify-wallet logout` साइन-इन हटाकर उसे रद्द कर देता है। ऐसे ऑटोमेशन के लिए जिसके पास पहले से kombify एक्सेस टोकन है, `KOMBIFY_WALLET_TOKEN` सेट करें। यह सहेजे गए साइन-इन पर प्राथमिकता रखता है।

## आइटम सहेजें और पढ़ें

```bash
kombify-wallet set DATABASE_URL --type variable
kombify-wallet list
kombify-wallet get DATABASE_URL
kombify-wallet get DATABASE_URL --reveal
```

`set` मान को छिपे हुए प्रॉम्प्ट से पूछता है, या पाइप से पढ़ता है। अगर नाम उस दायरे में पहले से मौजूद है, तो `set` नया संस्करण जोड़ता है। `--type` `variable`, `configuration` या `generic_secret` होता है। `--scope` `account` (डिफ़ॉल्ट), `project:<project>` या `environment:<project>/<environment>` होता है।

`list` आपके आइटम उनकी ID के साथ दिखाता है। `get` किसी आइटम का ब्योरा दिखाता है, और केवल `get --reveal` मान छापता है। कमांड `kombify-wallet revoke <item>` और `kombify-wallet delete <item> --yes` वैसे ही काम करती हैं जैसे [सेटिंग्स](/hi/wallet/secrets-and-variables) में। जब कोई नाम कई आइटम से मेल खाए, तो `--type` या `--scope` जोड़ें।

## अपने वेरिएबल के साथ कमांड चलाएँ

```bash
kombify-wallet run --project shop --environment production -- ./deploy.sh
```

`run` उस दायरे के लिए आपके वेरिएबल हल करता है और उन्हें कमांड के एनवायरनमेंट में जोड़ देता है। एनवायरनमेंट प्रोजेक्ट पर भारी पड़ता है, और प्रोजेक्ट खाते पर। मान केवल मेमोरी में डिक्रिप्ट होते हैं, और कभी छापे या लिखे नहीं जाते।

- `--only NAME,NAME` वेरिएबल को उन्हीं नामों तक सीमित करता है।
- जो वेरिएबल आपके एनवायरनमेंट में पहले से सेट है, वह बदला नहीं जाता, जब तक आप `--override` न जोड़ें।
- कमांड को `KOMBIFY_WALLET_TOKEN` नहीं मिलता, इसलिए उसके शुरू किए किसी भी प्रोसेस से आपके दूसरे आइटम नहीं खोले जा सकते।
- एग्ज़िट कोड कमांड का अपना कोड होता है।

## Doppler से आयात करें

```bash
doppler secrets download --no-file --format json | kombify-wallet import doppler --format json --scope project:shop
```

हर प्रविष्टि उस दायरे में एक वेरिएबल बन जाती है, या उसी नाम के मौजूदा वेरिएबल का नया संस्करण। आयात Doppler की अपनी मेटाडेटा प्रविष्टियों, ऐसे नामों जो मान्य वेरिएबल नाम नहीं हैं, खाली मानों और टेक्स्ट न होने वाले मानों को छोड़ देता है। यह नाम और नतीजे छापता है, मान कभी नहीं।

## SSH प्रमाणपत्र पर हस्ताक्षर करें

```bash
kombify-wallet ssh-sign my-ca ~/.ssh/id_ed25519.pub --principals deploy --ttl 8h
```

`--host` होस्ट प्रमाणपत्र पर हस्ताक्षर करता है। `--source-address` और `--extensions` उपयोगकर्ता प्रमाणपत्र के वे फ़ील्ड तय करते हैं। देखें [SSH प्रमाणपत्र](/hi/wallet/ssh-certificates)।
