एक उपयोग केस में जोड़ता है: Git सर्वर, वर्कस्पेस और एक्सेस रूट खुद जोड़े बिना

अलग वैकल्पिक चुनाव है।

## रिपॉज़िटरी, आज

- Git केवल HTTPS पर काम करता है। SSH उजागर नहीं है, और कोई CI रनर इंस्टॉल नहीं होता।
- हर क्लाइंट को Git होस्ट के लिए DNS नाम चाहिए और उसे उस होस्ट के आंतरिक CA प्रमाणपत्र पर भरोसा करना होगा।
- रिकवरी के लिए दोनों Gitea वॉल्यूम चाहिए, जिन्हें लिखना रोककर कैप्चर किया गया हो।

## रिमोट डेस्कटॉप और वर्कस्पेस, योजनाबद्ध

- **रिमोट डेस्कटॉप** ब्राउज़र-आधारित है: [Apache Guacamole](https://guacamole.apache.org/) मौजूदा उम्मीदवार है, और कोई डेस्कटॉप क्लाइंट इंस्टॉल किए बिना किसी भी ब्राउज़र से सेशन खुलता है। यह किसी स्पष्ट, पहले से समर्थित डेस्कटॉप लक्ष्य से जुड़ता है; यह खुद कोई OS डेस्कटॉप प्रोविज़न नहीं करता।
- **डेवलपमेंट वर्कस्पेस** (घोषित टूलचेन के साथ प्रोजेक्ट खोलना, संपादित करना और फिर शुरू करना) के लिए रनटाइम का स्पष्ट चुनाव चाहिए और अभी इसे स्वीकार नहीं किया गया है।
- दोनों मूल्यांकन के अधीन हैं। कोई भी आज रिपॉज़िटरी के काम को नहीं बदलता, और एक चुनने के लिए दूसरा ज़रूरी नहीं: केवल-Git ओनर को डेस्कटॉप नहीं चाहिए, और केवल-डेस्कटॉप ओनर को Git सर्वर नहीं चाहिए।

## टूल प्राप्त करें

- **Git क्लाइंट**: जनरेट किए गए HTTPS रूट के विरुद्ध अपना मौजूदा नेटिव Git क्लाइंट या IDE इंटीग्रेशन उपयोग करें।
- **tea, Gitea CLI**: टर्मिनल से स्क्रिप्टेड रिपॉज़िटरी, इश्यू और पुल-रिक्वेस्ट ऑपरेशन के लिए [gitea.com/gitea/tea](https://gitea.com/gitea/tea) देखें।
- **Guacamole**: शिप होने के बाद कोई क्लाइंट इंस्टॉल नहीं करना — यह पूरी तरह आपके ब्राउज़र में चलता है।

## इसे सेटअप करें

खाली ओनर वर्कस्पेस से [Gitea](/hi/stackkits/apps/gitea) पेज का पालन करें। भरोसा करने से पहले असली क्लाइंट से टेस्ट रिपॉज़िटरी में push करें।
