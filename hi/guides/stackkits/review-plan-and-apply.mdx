कॉन्फ़िगरेशन से सत्यापन तक उसी वर्कस्पेस और रिलीज़ की गई CLI का उपयोग करें। जनरेट की गई फ़ाइलें प्रमाण-वाहक आउटपुट हैं; StackSpec ही संपादन योग्य इनपुट रहता है।

## 1. सत्यापित करें और जनरेट करें

```bash
stackkit validate
stackkit generate
```

जनरेशन हल किया गया प्लान, जनरेशन मैनिफ़ेस्ट, रसीद और शासित आर्टिफ़ैक्ट कॉन्फ़िगर किए गए आउटपुट रूट के नीचे लिखता है।

## 2. प्लान की जाँच करें

```bash
stackkit plan --json
```

लागू करने से पहले पुष्टि करें:

- प्लान और स्पेक हैश मौजूद हैं
- `readiness.generation.status` `ready` है
- `readiness.apply.status` `ready` है
- चुने गए वर्कलोड, साइट, नोड और एडैप्टर आपके इरादे से मेल खाते हैं
- हर जनरेट किए गए आर्टिफ़ैक्ट का एक ओनर और अपेक्षित पथ है

`plan` बिना एक्ज़ीक्यूटर चलाए नेटिव v2 क्लोज़र की जाँच करता है। तैयार प्लान आवश्यक है, पर यह प्रमाण नहीं कि होस्ट पहले ही बदल चुका है।

## 3. स्पष्ट रूप से लागू करें

```bash
stackkit apply
```

स्थानीय अनुमोदन प्रॉम्प्ट की समीक्षा करें। `apply` वही चरण है जो होस्ट को बदलता है।
टूलचेन इंस्टॉलर यह चरण आप पर छोड़ता है; `base.stackkit.cc` पर Basement बूटस्ट्रैप
शुरुआती apply पहले ही कर देता है। उस बूटस्ट्रैप के बाद
apply केवल जानबूझकर किए गए कॉन्फ़िगरेशन बदलाव के लिए दोबारा करें।

## 4. नतीजा सत्यापित करें

```bash
stackkit verify --http --json
stackkit drift detect --json
stackkit logs list --json
```

JSON आउटपुट को वर्कस्पेस के साथ रखें। यह देखे गए नतीजे को स्क्रीनशॉट या संपादित Compose फ़ाइल से नहीं, बल्कि स्थानीय लाइफ़साइकल से जोड़ता है।

<Warning>
  जब हल किया गया प्लान apply ब्लॉकर बताए, तो रुक जाएँ। सीधे Docker, Compose या जनरेट की गई फ़ाइलों के संपादन से उसे बायपास न करें; StackSpec या लक्ष्य होस्ट ठीक करें और फिर से जनरेट करें।
</Warning>
