StackKits separates application choice from execution ownership. Standalone Compose is the native default. Komodo is an operations platform without an app store. Marketplace is planned as an optional use case on Coolify; Coolify is an application of that use case, not a native runtime target.

Inspect the matrix embedded in your installed release:

```bash
stackkit app compatibility --json
```

## Choose an adapter

| Adapter | Current status | Use it when |
| --- | --- | --- |
| `standalone-compose` | Native default | Use the installed release's declared workload path and check its lifecycle receipt. |
| [Coolify](/stackkits/apps/coolify) | Planned Marketplace application | Installable as Marketplace only after the published catalog carries the use case and its lifecycle is verified. |
| [Komodo](/stackkits/apps/komodo) | Draft operations-platform path | Choose explicitly only within the workload scope proven by a receipt at the current pin. |

The published [application delivery compatibility](/stackkits/reference/application-delivery-compatibility) matrix describes declared adapter contracts. Historical compatibility rows are not evidence of support at the current pin. Check the lifecycle receipt for your application and release before treating a platform path as supported; deployment capability alone does not establish backup or restore.

For a standalone Basement Kit, start with `standalone-compose` unless you intentionally operate one of the application platforms:

```json
{
  "workloads": {
    "files": {
      "alternative": "cloudreve",
      "runtimeAdapterRef": "standalone-compose",
      "placement": {
        "siteRefs": ["home"],
        "nodeRefs": ["main"]
      }
    }
  }
}
```

## Keep one owner per workload

- Do not route the same workload through Coolify and standalone Compose at the same time.
- Do not add Docker labels or generated routes by hand.
- An explicit Komodo path needs a current-pin receipt; it is not the default or an app store.
- Validate the changed intent and inspect the resolved plan before applying a different adapter.

See [Platform services](/stackkits/apps/overview) for the platform integrations and [Configure a StackSpec](/guides/stackkits/configure-stack-spec) for the complete editing workflow.
