StackKits keeps application choice separate from application delivery. A workload such as Files chooses its application alternative, while `runtimeAdapterRef` chooses how that one workload is delivered.

Inspect the matrix embedded in your installed release:

```bash
stackkit app compatibility --json
```

## Choose an adapter

| Adapter | Current status | Use it when |
| --- | --- | --- |
| `standalone-compose` | Supported | You need the local workload path with declared backup and restore capability and no separate application platform. |
| [Coolify](/stackkits/apps/coolify) | Supported | You already operate the generated application platform and accept that workload backup and restore is outside this adapter. |
| [Komodo](/stackkits/apps/komodo) | Beta | You deliberately accept the beta adapter maturity and validate it in your own workspace. |

Maturity describes the catalog contract, not observed health on your host. The generated [application delivery compatibility](/stackkits/reference/application-delivery-compatibility) matrix lists deployment, route, TLS, backup and restore capabilities for each workload and adapter in the published release. Check the row for your selected application; a platform's deployment support alone does not establish its recovery capability. Do not infer public support for a component the matrix does not list.

For a standalone Basement Kit, start with `standalone-compose` unless you intentionally operate one of the application platforms:

```json
{
  "workloads": {
    "files": {
      "alternative": "cloudreve",
      "runtimeAdapterRef": "standalone-compose",
      "placement": {
        "siteRefs": ["home"],
        "nodeRefs": ["main"]
      }
    }
  }
}
```

## Keep one owner per workload

- Do not route the same workload through Coolify and standalone Compose at the same time.
- Do not add Docker labels or generated routes by hand.
- Treat Komodo as a beta choice in this release, not as the default alternative.
- Validate the changed intent and inspect the resolved plan before applying a different adapter.

See [Platform services](/stackkits/apps/overview) for the platform integrations and [Configure a StackSpec](/guides/stackkits/configure-stack-spec) for the complete editing workflow.
