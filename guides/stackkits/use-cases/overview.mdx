A use case is something your household relies on, such as a photo library or a password vault. Each one runs as a workload on a kit you already verified, and one application provides it. Your kit brings sign-in, routing, the Node Hub and backups; a use case adds the application on top.

No use case is selected by the initial StackSpec. You choose the ones you want.

## Documented use cases

| Use case | What you get | Application | Workload |
| --- | --- | --- | --- |
| [Photos](/guides/stackkits/use-cases/photos) | A family library for photos and videos, with backup from your phone | [Immich](/stackkits/apps/immich) | `photos` |
| [Files](/guides/stackkits/use-cases/files) | Storage and sharing for your files | [Cloudreve](/stackkits/apps/cloudreve) | `files` |
| [Passwords](/guides/stackkits/use-cases/passwords) | A password vault that works with Bitwarden clients | [Vaultwarden](/stackkits/apps/vaultwarden) | `vault` |
| [Media](/guides/stackkits/use-cases/media) | Streaming for the films, music and videos you own | [Jellyfin](/stackkits/apps/jellyfin) | `media` |
| [Personal AI](/guides/stackkits/use-cases/personal-ai) | A chat interface for language models that run on your host | Ollama and Open WebUI | `ai` |
| [Development](/guides/stackkits/use-cases/development) | Private Git repositories for your projects | [Gitea](/stackkits/apps/gitea) | `dev` |

Each use-case page opens with the lifecycle evidence for the current release. The [use-case catalog](/stackkits/reference/use-case-catalog) lists every use case the release declares, including the ones without a guide yet.

## Add a use case

1. Start from a verified kit. The [Quickstart](/stackkits/quickstart) sets up a Basement Kit.
2. Plan storage and recovery on the use-case page.
3. Select the workload in your [StackSpec](/guides/stackkits/configure-stack-spec), then follow [Add a workload](/stackkits/reference/day-2-operations#add-a-workload-to-an-existing-workspace) to establish secret custody, generate, apply and verify.
4. Finish the setup on the application page and try one real task, such as uploading a photo.
5. Practice a restore before the use case holds data you cannot replace. See [Back up and restore](/guides/stackkits/back-up-and-restore).

Files is a good first use case, because its standalone selection needs no secret reference.
