A use case is something your household relies on, such as a photo library or a password vault. Each one runs as a workload on a kit you already verified, and one or more applications provide it. Your kit brings sign-in, routing, the Node Hub and backups; a use case adds the application on top.

No use case is selected by the initial StackSpec. You choose the ones you want.

## The eleven main use cases

| Use case | What you get | Default app (alternatives) | Status | Guide |
| --- | --- | --- | --- | --- |
| Photos | A family library for photos and videos, with backup from your phone | [Immich](/stackkits/apps/immich) | Available, lifecycle-verified | [Photos](/guides/stackkits/use-cases/photos) |
| Documents & Files | Storage and sharing for your files, plus an optional searchable document archive | [Cloudreve](/stackkits/apps/cloudreve) (files) + Paperless-ngx (documents add-on) | Files: available, lifecycle-verified · Documents: available, not yet lifecycle-verified | [Documents & Files](/guides/stackkits/use-cases/documents-and-files) |
| Vault | A password vault, with planned service-secret and Bitcoin extensions | [Vaultwarden](/stackkits/apps/vaultwarden) (passwords) | Passwords: available, lifecycle-verified · Extensions: planned | [Vault](/guides/stackkits/use-cases/vault) |
| Media | Streaming for the films, music and videos you own | [Jellyfin](/stackkits/apps/jellyfin) | Available, lifecycle-verified | [Media](/guides/stackkits/use-cases/media) |
| Smart Home | Home automation centered on a fresh or connected Home Assistant instance | Home Assistant | Available, lifecycle-verified | [Use-case catalog](/stackkits/reference/use-case-catalog#smart-home) |
| Dev | Private Git repositories, with remote desktop and a workspace runtime planned | [Gitea](/stackkits/apps/gitea) (repositories) | Repositories: available, not yet lifecycle-verified · Remote desktop: in development · Workspace: planned | [Dev](/guides/stackkits/use-cases/development) |
| Mail | A mail server declared for the release, ahead of a client-first setup guide | Stalwart | In development | [Use-case catalog](/stackkits/reference/use-case-catalog#private-mail) |
| Game | Self-hosted game servers, starting with Pterodactyl | Pterodactyl | Available, not yet lifecycle-verified (new in v0.41.0) | [Use-case catalog](/stackkits/reference/use-case-catalog#game-server) |
| Network | DNS and connectivity between the devices, servers and networks you choose | — | Planned | [Use-case catalog](/stackkits/reference/use-case-catalog) |
| Automation | Reviewed routines that handle repetitive cross-application work | — | Planned | [Use-case catalog](/stackkits/reference/use-case-catalog) |
| AI | A chat interface for language models that run on your host | Ollama and Open WebUI | Available, not yet lifecycle-verified | [AI](/guides/stackkits/use-cases/personal-ai) |

"Available, lifecycle-verified" means the current release has a public Depot producer receipt: install through restore passed on the tested operating system, and the run's support grade is published on [stackkit.cc/compatibility](https://stackkit.cc/compatibility). "Available, not yet lifecycle-verified" means you can select it in the catalog today, but no lifecycle receipt covers it yet. "In development" means the release declares it but it is not installable yet. "Planned" means it is a target design with no release yet and no committed date.

Rows without a dedicated guide link to their entry in the [use-case catalog](/stackkits/reference/use-case-catalog), which lists every use case the current release declares, generated from the published manifest. It has no maturity field of its own; read status from this page. [OS compatibility](/stackkits/reference/os-compatibility) has the lifecycle evidence behind "lifecycle-verified".

## How a use case is added

1. Start from a verified kit. The [Quickstart](/stackkits/quickstart) sets up a Basement Kit.
2. Plan storage and recovery on the use-case page.
3. Select the workload in your [StackSpec](/guides/stackkits/configure-stack-spec), then follow [Add a workload](/stackkits/reference/day-2-operations#add-a-workload-to-an-existing-workspace) to establish secret custody, generate, apply and verify.
4. Finish the setup on the application page and try one real task, such as uploading a photo.
5. Practice a restore before the use case holds data you cannot replace. See [Back up and restore](/guides/stackkits/back-up-and-restore).

Documents & Files is a good first use case, because Cloudreve's standalone selection needs no secret reference.
