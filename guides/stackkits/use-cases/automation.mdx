<Info>
StackKits v0.54.3 declares Automation as the optional `automation` use case with the `workpaths` alternative. Its `stackkits-workpaths-runtime` module has executable, apply-ready contracts for low, standard and high compute profiles. This describes what the release can author; it is not installation or recovery evidence for your host.
</Info>

## What the release includes

Workpaths is the application choice for workflow automation. The separate `automation-notifications` add-on selects `ntfy-live` through `stackkits-ntfy-live-runtime`, which declares a standard compute profile. The notification module is experimental in this release. Selecting Automation does not select every optional add-on.

The [application catalog](/stackkits/reference/application-catalog#automation) lists the exact choices and modules. The generated [use-case catalog](/stackkits/reference/use-case-catalog) is the release-backed inventory. n8n, Activepieces, Node-RED and Windmill are not executable Automation alternatives in this release.

## Select and review the workload

Start with the [Quickstart](/stackkits/quickstart) for the baseline. In an existing workspace, follow [Configure the StackSpec](/guides/stackkits/configure-stack-spec) to enable `automation` and select `workpaths`. Review the resulting module, compute profile, credential requirements and application delivery in the generated plan before [applying](/guides/stackkits/review-plan-and-apply).

Use the route and setup instructions produced by your installed release. Do not infer a public URL, provider connection, preset routine or permission from the catalog entry alone. A workflow needs its own explicit access to any service it uses.

## Check the result

Run the verification offered by your installed CLI, then open the generated application route. Check the [OS compatibility](/stackkits/reference/os-compatibility) and [application delivery compatibility](/stackkits/reference/application-delivery-compatibility) evidence for your target. A successful application start alone does not prove that a particular workflow or external integration works.

## Protect your workflows

Keep credentials in the custody selected for your installation. Follow [Back up and restore](/guides/stackkits/back-up-and-restore) and check which workload data your generated backup plan actually includes before relying on it.

If Automation is absent from a release older than v0.54.3, check that version's catalog instead of assuming these choices exist. For a failed plan, apply or verification, see [Troubleshooting](/guides/stackkits/troubleshooting).
