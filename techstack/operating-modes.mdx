Techstack extends an existing StackKits environment. It does not replace the
standalone path.

## In plain words

There are several ways to run a stack. You can use StackKits alone, add the
Techstack app on your own network, connect to kombify, or let kombify prepare a
server. Each step is optional, and you can stay on the simplest one.

## What you need first

- Standalone: a server you operate and the StackKits CLI. No account.
- Local orchestration: the [Windows Alpha](/techstack/install-windows). No
  account.
- Connected or managed: a kombify account, and for managed placement an
  account that has it enabled.

## Standalone StackKits

The public StackKits CLI initializes, validates, generates, applies, and
verifies a stack without Techstack, an account, or a hosted kombify endpoint.
This is the default path for a local homelab or an existing VPS you operate.

## Local orchestration

The Techstack product contract adds a visual operator experience, runtime
inventory, and coordinated Day-2 operations around the same released StackKits
CLI. This mode keeps the stack and its owner authority local.

<Note>
The [Windows Alpha](/techstack/install-windows) is now a public, unsigned
download. It supports account-free local operation; Cloud sync remains a
separate connected path.
</Note>

## Connected operation

A connected runtime may project account context and remote status into the
operator experience. Connection is optional: local owner identity, local
credentials, and the ability to operate the stack remain with the local
environment.

When a service needs a public HTTPS name, [kombify.me](/kombify-me/overview)
is the connected-ingress path. A public origin gets a `*.kombify.me` address;
a private HTTP target uses the Techstack node agent. StackKits still runs
without it.

## Managed placement

In managed operation, Techstack owns provider selection, resource leases,
provider credentials, lifecycle receipts, and terminal cleanup. These paths
require explicit admission and remain preview scope; the public documentation
does not claim general availability.

## Advanced Mode

Advanced Mode is a bounded Techstack-to-StackKits seam. Techstack can issue a
short-lived capability for an approved advanced operation, while the pinned
StackKits CLI validates and executes it. Techstack does not become a second
renderer or bypass StackKits validation.

## If something goes wrong

If a mode is not available to you, fall back to the one before it. Standalone
StackKits always works without the others. See
[availability](/techstack/availability) for what is public today, and
[Add a Node](/techstack/add-node) if a server will not connect.
