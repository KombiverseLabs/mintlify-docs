Techstack Alpha is an early, local-first Windows client for operating servers
in your home network. It can run without a hosted kombify account. StackKits on
the server still bootstraps its required local Owner/Admin identity.

<Warning>
This is an unsigned Alpha release for real-user feedback, not a stable or
production-readiness claim. Windows may display a SmartScreen warning. Verify
the GitHub release origin and checksum before deciding whether to continue.
</Warning>

## Verify the installer checksum

Choose one version on the
[official releases page](https://github.com/kombifyio/TechStack/releases).
For example, [v0.42.15](https://github.com/kombifyio/TechStack/releases/tag/v0.42.15)
publishes both `kombify-Techstack-Setup.exe` and `SHA256SUMS.txt`. Download
both from that same release into one folder. Do not combine a previous
installer with a checksum downloaded from `latest` after it has changed.

1. Open PowerShell in that folder and run
   `Get-FileHash -LiteralPath .\kombify-Techstack-Setup.exe -Algorithm SHA256`.
2. Open `SHA256SUMS.txt` and find the single row ending in
   `kombify-Techstack-Setup.exe`. Compare its 64-character hash with the
   PowerShell result. Uppercase and lowercase letters represent the same hash.
3. Continue only if every character matches. Stop if the row is absent,
   ambiguous or different, and download both files again from the same
   official release before retrying.

A matching hash checks that the file matches the selected release; it does
not make an unsigned Alpha installer signed.

## Use Techstack locally

1. Start Techstack and choose **Use locally**. A hosted kombify account is not
   required for this mode.
2. For a fresh Ubuntu server, choose **Give me a one-liner**, select
   **Basement Kit**, and complete the local Owner/Admin bootstrap fields.
3. Copy the generated pairing command and run it once on the Ubuntu server.
   Keep the Windows client running and reachable on the local subnet while the
   server downloads its agent and sends the first Guard heartbeat.
4. Wait until Techstack changes the server from **Not connected yet** to the
   connected state, then continue with the StackKit rollout.
5. For a server that already runs Basement Kit, choose **Connect my server**
   instead and enter its local SSH details.

<Note>
The Windows Alpha bundles a pinned Basement Kit catalog, its Windows validator,
and the Linux rollout payload; the release notes name the exact StackKits
version each build carries. The installer also creates a Windows Firewall
exception for TCP `5264` limited to the local subnet so the generated command
can reach the client even when Windows classifies the home network as Public.
</Note>

<Note>
Cloud sync and connected operation require a separate account later. They are
not prerequisites for the local Alpha path.
</Note>

## Update the Windows client

1. Note your installed client version and read the target release notes,
   including the StackKits version it bundles. Keep recovery material and
   backups for the servers you operate.
2. Close Techstack. Download the installer and checksums from the same
   selected public release, then repeat the checksum comparison above.
3. Run the verified installer, start Techstack, and compare its displayed
   version with the release you selected. Check your server connections
   before making another rollout.

## Returning to an earlier version

Installing an older Windows client does not by itself restore a server's
data or reverse a StackKits rollout. This guide has no release-backed
client-data downgrade procedure. Keep the previous release and its matching
checksums, but obtain recovery guidance before running it against data
written by a newer client. For a StackKits change, use the
[upgrade recovery guidance](/stackkits/reference/day-2-operations#recover-an-interrupted-upgrade)
and the server's verified recovery evidence.
