## techstack api substrates appliances create

Admit a Home Assistant OS guest on the owner's own hypervisor.

Reserves a guest on a bound substrate (the owner's own Proxmox host, customer custody, local billing, nothing billed by kombify) and submits its creation; the guest is not yet assessed as running (`application_status` is `authenticated_check_pending`). Only the `haos` profile and a placement on this substrate are accepted. The substrate binding must be enabled and its Guard inventory current, and the stack must be owned by the caller. Replaying the same intent with the same Idempotency-Key returns the same guest; a changed intent or a different key for the same stack and node answers 409 `appliance_not_admitted`.

```bash
techstack api substrates appliances create <server-id> [flags]
```

## techstack api substrates binding set

Enable or disable guest placement on one substrate.

Binds the substrate to the Guard's current authenticated inventory (node, guest-id range, image pins) and turns guest placement on or off. Optimistic concurrency: `revision` must equal the current binding revision (0 when none exists) and the answer carries the next one. Refused with 409 while the substrate has no current inventory, no node-local configuration, a revision mismatch, or non-decommissioned guests that still hold custody.

```bash
techstack api substrates binding set <server-id> [flags]
```
