## techstack api jobs get

Get the current state of one owned job.

This is the canonical polling surface for the UI, API clients, MCP
tools, and agents. `waiting_enrollment` exposes a non-terminal wait;
access to the target remains unavailable until the job resumes and
reaches a terminal success state.

```bash
techstack api jobs get <id> [flags]
```

| --- | --- |
| HTTP | `GET /api/v1/jobs/{id}` |
| Changes state | No |
| MCP tool | `get_job` |

| `<id>` | string | **Required.** Resource ID. |

## techstack api jobs list

List jobs owned by the authenticated user.

Returns the same owner-scoped job state used by the operator UI and
automation clients. A job with `state: waiting` remains active and the
current orchestrator process schedules its next check; it is not a
failed provider action. If that schedule becomes stale after a process
restart, use the exact-target `resumeStackEnrollment` operation.

```bash
techstack api jobs list [flags]
```

| | |
| --- | --- |
| HTTP | `GET /api/v1/jobs` |
| Changes state | No |
| MCP tool | `list_jobs` |

| `--state` | string | One of `pending`, `running`, `waiting`, `completed`, `failed`, `canceled`. |
