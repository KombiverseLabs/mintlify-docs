## techstack api registry services delete

Delete an archived service copy from the Registry.

Removes the registry row of a service copy that a finished move left in the archived state. Any other status is refused with 409; no workload or server is touched. The canonical inventory store currently answers 503 `service_control_server_fence_unavailable`.

```bash
techstack api registry services delete <service-id> [flags]
```

<Warning>Requires confirmation: This operation removes the archived service copy from the Registry; the record cannot be restored. Pass `--yes` or answer the prompt; a non-interactive run without `--yes` stops before any request with exit code 9.</Warning>

## techstack api registry services import

Record an unmanaged service that already runs on an owned server.

Adds an observed (unmanaged) service row for a server of an owned stack. The row is keyed by stack, server and service name, so repeating the call updates the same row. Nothing is deployed or probed. Either `name` or `service_id` is required and is normalized to a lower-case key. A stack the caller does not own is refused with 403 and an unknown stack or server with 404.

```bash
techstack api registry services import [flags]
```

## techstack api registry services import-home-assistant

Link an existing Home Assistant instance read-only.

Probes a Home Assistant instance from a local executor with the long-lived access token held in the Wallet item `token_wallet_item_id` (a kombify Wallet item assigned to Techstack, or a built-in wallet API key or OAuth token item whose URL names this instance; resolved inside Techstack, never answered) and records a read-only observed service. This contract accepts no token. The token is used for this probe only and is never stored in the registry row. Self-hosted installs only (503 `lan_executor_unavailable` otherwise). The call is idempotent: an already linked instance returns `existing: true` without a new probe.

```bash
techstack api registry services import-home-assistant [flags]
```

## techstack api registry services migrate

Start moving a service to another server of the same stack.

Marks the source service as migrating, creates the target copy pending verification and starts a migration job. The target server must belong to the same stack and differ from the source, and the service must be movable. Today every call answers 501 `Runtime service migration is unavailable` (`migration_available` is false in the registry) until a runtime executor exists; the canonical inventory store additionally answers 503 `service_control_server_fence_unavailable`.

```bash
techstack api registry services migrate [flags]
```

## techstack api registry services verify

Finish a service move by accepting the target copy.

Accepts a service copy that is pending verification as running and archives the migrating source copy. Answers 409 when the service is not pending verification. Today every call answers 501 until a runtime executor exists, and the canonical inventory store answers 503 `service_control_server_fence_unavailable`.

```bash
techstack api registry services verify [flags]
```
