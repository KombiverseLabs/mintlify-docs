## techstack api servers detach

Revoke and detach one exact customer-operated BYO server.

Retains the terminal canonical server receipt and performs no provider API call.

```bash
techstack api servers detach <server-id> [flags]
```

<Warning>Requires confirmation: This operation revokes the server's credentials and removes it from management without touching the machine. Pass `--yes` or answer the prompt; a non-interactive run without `--yes` stops before any request with exit code 9.</Warning>

## techstack api servers maintenance get

Read one maintenance job of an owned server.

Scoped like the POST: the Edge-signed `techstack.servers.maintenance` entitlement, the tenant, ownership of the server, and a job that belongs to this server and was requested by the caller. Anything else is 404. Maintenance jobs have their own ledger and are not served by `/api/v1/jobs/&#123;id&#125;`. There is no log endpoint: the job carries its outcome, and a failure carries its stable code with user guidance.

```bash
techstack api servers maintenance get <server-id> <job-id> [flags]
```

## techstack api servers maintenance run

Queue an owner-approved OS update plan, OS update or reboot.

Requires the Edge-signed `techstack.servers.maintenance` entitlement, ownership of the server in the tenant, and for `reboot` and `os_update` a multi-factor sign-in at most 300 seconds old from the verified edge envelope. The body is decoded strictly: exact lowercase keys, no duplicates, no unknown fields. A replay with the same Idempotency-Key returns the stored receipt before target validation. One reboot or OS update and, separately, one update plan may be active per server; a job not finished by its deadline fails with `deadline_exceeded` and frees its slot. The action is offered in `allowed_actions` only when the server agent advertises `stackkit.host-maintenance.v1`, and `reboot` only when the server also reports `host_boot_id`. Refusals are client-error-envelope/v1 documents; 409 `reason_code` is one of control_plane_host, substrate_node, protected_demo_server, service_locked, maintenance_active, node_operation_active, plan_stale, agent_capability_missing, boot_id_unknown, agent_not_connected, heartbeat_stale, inventory_revision_stale or idempotency_key_reused; 403 carries entitlement_required or server_maintenance_step_up_required.

```bash
techstack api servers maintenance run <server-id> [flags]
```

<Warning>Requires confirmation: This operation reboots, updates or plans an update of the server's operating system as requested. Pass `--yes` or answer the prompt; a non-interactive run without `--yes` stops before any request with exit code 9.</Warning>

| | |
| --- | --- |
| HTTP | `POST /api/v1/servers/{serverId}/actions` |
| Changes state | Yes |
| MCP tool | `run_server_maintenance_action` |

| Argument | Type | Description |
| --- | --- | --- |
| `<server-id>` | string | **Required.** Canonical server runtime ID. |
| `--action` | string | **Required.** One of `os_update_plan`, `os_update`, `reboot`. |
| `--expected-inventory-revision` | integer | **Required.** |
| `--expected-plan-digest` | string | os_update only: the plan_digest of a completed os_update_plan for this server that is at most 15 minutes old. |
| `--owner-approved` | boolean | Required true for os_update and reboot. |
| `--body` | json | JSON request body (`application/json`) as a literal, `@path` or `-` for stdin. |
