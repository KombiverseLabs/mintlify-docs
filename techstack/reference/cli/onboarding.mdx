## techstack api onboarding apply

Apply one action to the caller's onboarding journey.

Applies one closed action (complete, skip, dismiss, resume or coach_seen) to the authenticated owner's progress in a journey and answers the resolved journey, state, step availability and revision. Steps that spend money complete only from server facts: a reported completion of such a step is refused with 403 `onboarding_derived_only`. A repeated action is a no-op, and a stale `If-Match` revision answers 412.

```bash
techstack api onboarding apply <journey-id> [flags]
```

| | |
| --- | --- |
| HTTP | `PUT /api/v1/onboarding/{journeyId}` |
| Changes state | Yes |
| MCP tool | `apply_onboarding_action` |

| Argument | Type | Description |
| --- | --- | --- |
| `<journey-id>` | string | **Required.** Journey id, for example `techstack.platform`. |
| `--if-match` | string | Optional compare-and-swap revision read from the journey state, for example `"3"`. |
| `--action` | string | **Required.** One of `complete`, `skip`, `dismiss`, `resume`, `coach_seen`. |
| `--source` | string | Who asserts the completion; empty means reported for complete and manual for skip. One of `reported`, `manual`. |
| `--step-id` | string | Required for complete, skip and coach_seen, for example `techstack.add_server`. |
| `--body` | json | JSON request body (`application/json`) as a literal, `@path` or `-` for stdin. |

## techstack api onboarding reset

Restart the caller's onboarding journey.

Clears the authenticated owner's completed and seen steps in a journey and reactivates it so the tour is shown again. Only the owner's own progress changes; no infrastructure is touched. Answers the resolved journey like the action route.

```bash
techstack api onboarding reset <journey-id> [flags]
```
