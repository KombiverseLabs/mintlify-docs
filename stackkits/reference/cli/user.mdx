Invite and manage household users in local PocketID.

Create, list, and remove Homelab users in the PocketID household group.

Add prints a one-time passkey setup URL. TinyAuth continues to admit the owners, admins, and household groups already bound on the OIDC client. Owner and admin identities cannot be created or removed here.

```bash
stackkit user [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--json` | bool | — | Emit stackkit.command-result/v1 JSON |

**Examples**

```bash
# Invite a household member; share the printed one-time URL only with them
stackkit user add alex --email alex@example.com --owner-approve

# List household users
stackkit user list

# Remove a household user
stackkit user remove alex --owner-approve
```

## stackkit user activate

Reissue passkey enrollment for an existing household member.

Reissue a one-time passkey registration link for a household member who has no passkey yet. With `--reset` the Owner resets the passkey of a member who lost every usable passkey: the link is issued although Pocket ID still lists the lost ones, which the member then removes in their account settings. The Owner recovers their own account with the recovery code (stackkit break-glass redeem).

```bash
stackkit user activate <username> [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | Explicitly approve reissuing household passkey enrollment |
| `--reset` | bool | — | Reset the passkey of a member who lost every usable passkey |

### stackkit user owner migrate-domain

Prepare the owner-approved identity domain migration (home to lab.home, or lab.home to a public id.&lt;name&gt;).

Preserve the existing owner, CA, service secrets and users while migrating Basement intent and runtime custody from home to lab.home. Preserve the prior-release CLI, packaged tools and provider mirror before using an isolated target CLI for this command. `--quiesce-runtime` authorizes the command to capture the exact source Core container identities, converge the identity callback while PocketID is available, then gracefully stop and remove only those containers without deleting volumes, networks or images. Use the prior CLI for generate, apply and verify, then use the target CLI for upgrade `--to` &lt;exact-release&gt;. The upgrade checkpoint covers the migrated prior release on lab.home; this command creates no original-domain rollback checkpoint. The v0.47.4 bridge awaits real-host qualification. After rollout, enroll client DNS and new passkeys at id.lab.home.

```bash
stackkit user owner migrate-domain [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | Explicitly approve domain migration and new passkey enrollment |
| `--quiesce-runtime` | bool | — | Gracefully stop and remove the authenticated source Core containers without deleting persistent resources |
| `--spec` | string | `stack-spec.yaml` | Workspace-relative StackSpec to migrate |
| `--to` | string | `lab.home` | Target identity domain: lab.home for the retired home default, or a public name (a kombify.me name or an own domain, giving https://id.&lt;name&gt;) for a local-only install |

## stackkit user remove

Remove a household user and everything they hold on this Authority.

Remove one household member with the local removal chain: every device of the member is revoked (with its credentials, VPN add-on peer, sessions and app credentials), the member's account joins the revoked accounts of the Owner-signed Home trust and can never enroll again, and then the PocketID user is deleted, which ends the member's passkeys and PocketID sessions. The output lists each revocation-registry artifact and what the chain did for it.

```bash
stackkit user remove <username> [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--owner-approve` | bool | — | Explicitly approve removing this household user |
