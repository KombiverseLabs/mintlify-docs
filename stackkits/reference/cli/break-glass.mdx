Owner recovery: recovery set, recovery key and recovery code.

Owner recovery at the Authority.

The recovery set (the break-glass bundle) holds the Authority's identity custody: Owner key, CA keys, Pocket ID keys and database, step-ca database, device registry and device credential issuer key. It is encrypted to the Owner's recovery key, which is shown once at setup and never stored here. The separate recovery code registers a new Owner passkey once: at this console at once (redeem), or from an enrolled Owner device after 24 hours with notices to every Owner device.

Restoring the set onto a replacement Authority keeps the identity origin, so existing passkeys keep working.

```bash
stackkit break-glass [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--dir` | string | — | Override the bundle directory (default: /var/lib/stackkit/recovery) |

## stackkit break-glass redeem

Redeem the recovery code at this console for a new Owner passkey.

Redeem the recovery code at the Authority's console. It yields a Pocket ID link, valid for 20 minutes, that registers a new passkey for the Owner account; the code is then used up (replace it with 'stackkit break-glass code'). A pending Owner device recovery ends. The code is read from `--code-file` or standard input, never from an argument.

## stackkit break-glass restore

Restore a recovery set onto a replacement Authority.

Restore a recovery set onto a replacement Authority. Run it in the workspace directory of the new host before generate and apply: it verifies the whole set with the recovery key, fills fresh Docker volumes for the Pocket ID and step-ca databases, and installs the identity custody. The identity origin stays the same (the Pocket ID host is the passkey relying party), so existing passkeys keep working. The key is read from `--key-file` or standard input, never from an argument.

```bash
stackkit break-glass restore [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--from` | string | — | Path of the recovery set (break-glass-&lt;node&gt;.age) |
| `--json` | bool | — | Print a JSON result |
| `--key-file` | string | — | Read the recovery key from this file instead of standard input |
| `--owner-approve` | bool | — | Authorize installing the restored identity custody |

Inherited from `stackkit break-glass`:

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--dir` | string | — | Override the bundle directory (default: /var/lib/stackkit/recovery) |

**Examples**

```bash
# Restore, then roll the Authority out again from the same StackSpec
stackkit break-glass restore --from break-glass-main.age --owner-approve

```

## stackkit break-glass setup

Create the recovery key and code, show both once and write the first recovery set.

Create the Owner's recovery key and recovery code on the Authority, print both exactly once, and write the first recovery set.

Store the recovery key offline and apart from the recovery set: whoever holds both holds the Authority's identity. StackKits keeps only the public half of the key, so it can write new sets but never read one. kombify never receives the key. `--rotate` replaces an existing key and code; it asks for the Owner's passkey step-up on an enrolled Owner device in the Hub first.

```bash
stackkit break-glass setup [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--backup-target` | bool | — | Also upload the set to the S3 backup target bound with 'stackkit backup target import' |
| `--json` | bool | — | Print a JSON result that contains the recovery key and code |
| `--owner-approve` | bool | — | Authorize creating (or with `--rotate` replacing) the recovery key and code |
| `--rotate` | bool | — | Replace an existing recovery key and code |
| `--target` | string | — | Also copy the set into this directory of the Owner's backup target (mounted disk, NAS) |

Inherited from `stackkit break-glass`:

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--dir` | string | — | Override the bundle directory (default: /var/lib/stackkit/recovery) |

**Examples**

```bash
# First setup, with a copy of the set on a mounted backup disk
stackkit break-glass setup --owner-approve --target /mnt/backup

# Machine-readable, for the setup flow that shows key and code once
stackkit break-glass setup --owner-approve --backup-target --json
```

## stackkit break-glass write

Write a new recovery set of the Authority's identity custody.

Write a new recovery set: the local copy in the bundle directory and, when given, a copy in a backup target directory and an upload to the bound S3 backup target (object StackKitsRecoverySet/&lt;site&gt;/&lt;node&gt;.age below its prefix). Pocket ID and step-ca are paused for the few seconds the databases are read, so the set is crash-consistent. Write a new set after identity changes such as new members or devices.

```bash
stackkit break-glass write [flags]
```
