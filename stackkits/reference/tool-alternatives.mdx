StackKits never lock you into a single tool. For each capability there is a **smart default** (what you get if you change nothing) and **alternatives** you can select in `stack-spec.yaml`. Defaults are resolved from your context (local vs cloud), compute tier, and domain — you can always override them.

<Note>
  This page is the canonical, implementation-backed catalog. Basement Kit and Cloud Kit ship the **platform services** below; **add-ons** layer optional capabilities on top of any kit — Basement, Cloud, or Modern Homelab.
</Note>

## Platform services

These run in every Basement Kit and Cloud Kit deployment, selected by the resolver per context and compute tier.

| Capability | Smart default | Alternatives you can select |
|------------|---------------|-----------------------------|
| **Reverse proxy & TLS** | Traefik v3 | — (standard edge for all kits) |
| **App platform (PaaS)** | Coolify | Komodo *(supported)*, Dokploy *(draft)*, Dockge *(experimental)* |
| **Container management UI** | — *(covered by the app platform)* | Portainer *(high tier)*, Dockge |
| **Forward-auth gateway** | TinyAuth | Authelia *(via `authelia` add-on)* |
| **Identity / SSO (OIDC)** | PocketID | — |
| **Internal PKI** | step-ca | — |
| **Uptime monitoring** | Uptime Kuma | — |
| **Server metrics** | Netdata | Beszel, Glances *(low tier)* |
| **Log viewer** | Dozzle | — |
| **Full metrics stack** | Prometheus + Grafana *(high tier)* | `monitoring` add-on (VictoriaMetrics + Grafana + Loki + Alloy) |
| **Password manager** | Vaultwarden | — |
| **Media server** | Jellyfin | — |
| **Photos** | Immich | — |

<Note>
  The app platform is **context-resolved** — the release default does not hard-pin a PaaS. The resolver enables **Coolify** by default; **Komodo** is a supported drop-in switch, **Dokploy** is in draft, and **Dockge** is an experimental lightweight option. Switch with an explicit override in your spec.
</Note>

```yaml stack-spec.yaml
stackkit: basement-kit

# Override a smart default — e.g. use Komodo instead of Coolify
services:
  platform:
    provider: komodo   # coolify | komodo | dokploy | dockge
```

## Container management alternatives

Day-to-day container operations are normally covered by your app platform (Coolify by default) or by [Dockge](https://docs.kombify.io/stackkits/apps/dockge) as the lightweight Compose-focused path. If you want a dedicated, full-featured management UI instead, Portainer is the documented alternative.

### Portainer

Portainer is a full-featured Docker management UI for inspecting and managing containers, images, volumes, and networks, served at `portainer.<domain>`. The resolver enables it on the **high compute tier**; on smaller setups Dockge is the lighter Compose-focused alternative.

```yaml stack-spec.yaml
stackkit: basement-kit

services:
  portainer:
    enabled: true
```

<Tip>
  Portainer locks new-admin creation a few minutes after start. If first-run setup times out, restart the container (`docker restart portainer`) and complete setup promptly.
</Tip>

<Note>
  Portainer (full management), Dockge (Compose-focused), and your PaaS platform overlap — pick one management path per host to avoid conflicting owners for the same workloads.
</Note>

## Monitoring alternatives

[Uptime Kuma](https://docs.kombify.io/stackkits/apps/uptime-kuma) is the default **uptime monitor** (checks and status pages), and the `monitoring` add-on delivers the full observability stack. For **per-node server metrics**, Netdata is the default and Beszel is the lightweight alternative.

### Netdata

Netdata provides real-time, high-resolution system metrics (CPU, RAM, disk, network, per-container) for each node, served at `netdata.<domain>`. It is the **default** server-metrics service on standard and high compute tiers — no configuration needed. On low-resource nodes the resolver uses lighter tools (Beszel or Glances) instead.

<Tip>
  Charts empty or a node missing? Verify the Netdata container is running (`docker logs netdata`) and that the host has access to `/proc` and `/sys`.
</Tip>

### Beszel

Beszel is a lightweight server-monitoring tool with historical data and alerts — an **alternative** to Netdata, ideal for low-resource nodes (e.g. a Raspberry Pi) where a full metrics agent is too heavy. The Beszel hub is served at `monitor.<domain>`; register each node's Beszel agent so its metrics report to the hub, then set CPU, memory, and disk alert thresholds.

```yaml stack-spec.yaml
stackkit: basement-kit

services:
  beszel:
    enabled: true
```

<Tip>
  On `pi` and low compute tiers the resolver already prefers lightweight metrics. If a node is missing from the hub, confirm its Beszel agent is running and can reach `monitor.<domain>` (`docker logs beszel`).
</Tip>

## Add-ons (optional capabilities)

Add-ons are composable modules you stack on any kit. Each declares its compatible StackKits and is enabled in the `addons:` list.

| Capability | Add-on | What it deploys |
|------------|--------|-----------------|
| **Observability** | `monitoring` | VictoriaMetrics + Grafana + Loki + Alloy |
| **Backup** | `backup` | Kopia encrypted backups, DB hooks, 3-2-1 targets |
| **Backup fan-in** | `backup-repo-server` | Kopia Repository Server (multi-host / multi-tenant) |
| **Media** | `media` | Jellyfin + *arr stack |
| **Photos** | `photos` | Immich photo & video management |
| **Password vault** | `vault` | Vaultwarden (Bitwarden-compatible) |
| **Smart home** | `smart-home` | Home Assistant + MQTT + Zigbee2MQTT |
| **AI / LLM** | `ai-workloads` | Ollama + Open WebUI (local inference) |
| **Dev platform** | `dev-platform` | Gitea + Woodpecker CI |
| **Calendar / CardDAV** | `calendar` | Radicale + Bloben web UI |
| **Mail** | `mail` | Stalwart all-in-one (IMAP/JMAP/SMTP + CalDAV) |
| **File sharing** | `file-sharing` | Self-hosted file sharing and sync |
| **Remote desktop** | `remote-desktop` | Apache Guacamole (browser-based) |
| **Game server** | `gameserver` | Self-hosted game server |
| **Advanced auth** | `authelia` | Advanced auth server (replaces TinyAuth) |
| **Mesh VPN** | `vpn-overlay` | Mesh VPN overlay |
| **External access** | `tunnel` | Bypass CGNAT/DS-Lite to expose local services |
| **High availability** | `ha` | HA overlay: `warm-standby` tier (continuous backup + automated restore to a standby node) or `quorum` tier (live control-plane failover) |

<Note>
  The `ha` add-on tiers are node-gated as a **technical prerequisite, not a paywall**: `warm-standby` needs at least 2 nodes (downtime = restore time), `quorum` needs at least 3 (odd-numbered) manager nodes for quorum-based failover with near-zero downtime.
</Note>

```yaml stack-spec.yaml
stackkit: basement-kit

addons:
  - monitoring       # full observability stack
  - backup           # encrypted 3-2-1 backups
  - media            # Jellyfin + *arr
```

## How defaults are chosen

The resolver picks each tool from three inputs, in order of precedence:

<Steps>
  <Step title="Explicit override">
    Anything you set in `stack-spec.yaml` wins.
  </Step>
  <Step title="Context (local / cloud / pi)">
    Cloud contexts favor public-DNS + Let's Encrypt defaults; `pi` / low-resource contexts drop heavier services (e.g. Glances instead of Netdata, no Prometheus).
  </Step>
  <Step title="Compute tier (low / standard / high)">
    Higher tiers enable more by default — e.g. Portainer, Prometheus, and Grafana are added on the high tier.
  </Step>
</Steps>
