The released StackKits catalog includes Uptime Kuma for local service monitoring. Use it together with the CLI verification result, not as a substitute for it.

```bash
stackkit verify --json
stackkit status --json
```

After a successful rollout, open the Uptime Kuma address generated for your stack and add checks only for routes you are authorized to monitor. For protected routes, configure an intentional health endpoint or expect the configured authentication response instead of assuming every monitor must return HTTP 200.

StackKits publishes local observation and verification evidence. It does not require or imply a hosted monitoring service.

See [Uptime Kuma](/stackkits/apps/uptime-kuma) for the application-specific first steps.
