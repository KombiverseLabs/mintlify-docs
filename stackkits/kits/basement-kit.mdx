Basement Kit is the current local profile in the public `v0.23.0` release. Use it for a homelab on hardware you already control, with one home site and a local owner.

## What it provides

- a CUE-validated StackSpec and local `stackkit` lifecycle
- local owner custody with PocketID and TinyAuth
- a Node Hub at the generated `base.<domain>` address
- the released core runtime plus optional workloads selected by your validated configuration

The authoring default domain is `home.test`. Make sure clients use a DNS path you control before treating a generated route as reachable; StackKits does not silently modify every client or router.

## Start a Basement Kit

```bash
mkdir my-homelab
cd my-homelab

stackkit init basement-kit --owner-source=local
stackkit validate
stackkit generate
stackkit plan --json
stackkit apply
stackkit verify --http --json
```

Run the commands from the StackKits workspace. Do not modify generated rollout files; change the StackSpec and re-run validation instead.

## Compute sizing

Native `stackkit/v2alpha2` sizes each module independently. Select a workload alternative per use case and an explicit compute profile per selected module; undeclared profiles fail closed and `standard` is never filled in silently. For constrained hardware such as an SBC or a low-RAM mini-PC, select the standalone core-lite runtime with its `low` profile:

```bash
stackkit init basement-kit --owner-source=local --hardware-profile pi \
  --use-case photos \
  --use-case-alternative basement-core=standalone-lite \
  --use-case-alternative photos=immich \
  --module-compute-profile stackkits-basement-core-lite-runtime=low \
  --module-compute-profile stackkits-immich-runtime=standard
```

Core Lite `low` means standalone Compose without Coolify. It does not force Photos or Media to the same profile: a low core with a standard Immich profile is a valid mixed selection, and Immich Lite (Immich without machine learning) is a separate workload alternative rather than an implicit consequence of selecting Core Lite. Jellyfin (Media) declares module-local `standard` and `high` profiles.

The legacy kit-wide `install.computeTier` graphs remain available with `--api-version stackkit/v2alpha1 --compute-tier <tier>`:

| Tier | Module graph | Minimum host |
| --- | --- | --- |
| `low` | Standalone Compose with the core-lite runtime, no Coolify, Immich without machine learning, no Media | 2 CPU cores, 2 GB RAM, 10 GB disk |
| `standard` | Coolify PaaS plus Immich with machine learning | 2 CPU cores, 4 GB RAM, 20 GB disk |
| `high` | `standard` plus the `telemetry-collection` capability | 2 CPU cores, 4 GB RAM, 20 GB disk |

Host preflight and compiler admission use the selected profiles' capacity floors. Apply attests the local CPU, RAM, and disk inventory first and blocks with `inventory-fact-unverified` or `runtime-capacity-unsatisfied` when facts are missing or the host is undersized. See [StackSpec](/stackkits/reference/spec-format) for the full profile and admission semantics.

## When to use another kit

Choose [Cloud Kit](/stackkits/kits/cloud-kit) when the single environment is an existing VPS or cloud host with a domain you operate. StackKits does not provision that host.
