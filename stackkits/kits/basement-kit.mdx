Basement Kit is the released local profile of the current public StackKits release. Use it for a homelab on hardware you already control, with one home site and a local owner.

## In plain words

A Basement Kit turns one computer in your home into a small private server. It installs the programs that protect and organize your services, and you can add things like files, photos or media later. Nothing leaves your home network unless you decide to publish it. If you are new to this, read [Before you start](/guides/stackkits/before-you-start) first.

## What you need first

- A computer you control that can stay on, running a system listed in [OS compatibility](/stackkits/reference/os-compatibility).
- Access to a terminal on it.
- Your home network, with phones and laptops that can resolve the local names (see [Day to day](/guides/stackkits/daily-use)).
- A private place for the access details in `.stackkit/access.json`.
- No kombify account and no rented server.

## What it provides

The smallest useful Basement Kit is one home site with one local node. It brings:

- a CUE-validated StackSpec and local `stackkit` lifecycle
- local owner custody with PocketID and TinyAuth
- routing through Traefik
- a Node Hub at the generated `base.<domain>` address
- local backup policy with owner-bound restore

The authoring default domain is `home.test`. Make sure clients use a DNS path you control before treating a generated route as reachable; StackKits does not silently modify every client or router.

The baseline stays standalone. The StackKits website helps you choose and bootstrap a path, but it does not operate the host.

## Complete the baseline

1. Bootstrap the kit with the [Quickstart](/stackkits/quickstart).
2. Finish first-run protection in the [Node Hub](/guides/stackkits/node-hub): create the local PocketID owner and confirm that TinyAuth protects the expected routes.
3. Configure the local backup repository and practice a restore. See [Back up and restore](/guides/stackkits/back-up-and-restore).

Change the StackSpec and re-validate rather than editing generated files.

After each step you should see the following:

1. The Quickstart leaves a workspace folder with your configuration and an access record.
2. The Node Hub opens, you can sign in as the local owner, and protected routes ask you to sign in.
3. You have a backup and know that a restore works.

## What is stored where

Your configuration, logs and access details stay in the workspace folder on the home computer. Owner identity lives in PocketID on that computer. Backups are a separate copy that you configure. Keep the folder private and do not share `.stackkit/access.json`.

## If something goes wrong

- An address does not open on a phone or laptop: the device probably cannot resolve your local names. See [Troubleshooting](/guides/stackkits/troubleshooting).
- Setup stops with an error: read it with `stackkit logs latest --json` before you run the installer again.
- You are not sure the setup is healthy: see the checks in [Day to day](/guides/stackkits/daily-use).

## Add use cases

Add workloads only after the baseline verifies. [Documents & Files](/guides/stackkits/use-cases/documents-and-files) is a good first use case, because Cloudreve's standalone selection needs no secret reference. [Use cases](/guides/stackkits/use-cases/overview) lists all documented ones.

## When to use another kit

Choose [Cloud Kit](/stackkits/kits/cloud-kit) when the single environment is an existing VPS or cloud host with a domain you operate. StackKits does not provision that host.
