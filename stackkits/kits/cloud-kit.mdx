Cloud Kit is included in the current public release. It uses the same standalone authoring lifecycle as Basement Kit, but is intended for one existing cloud host with public DNS and TLS under your control.

<Note>
  The release includes the Cloud Kit definition and installer. Treat configuration bootstrap and release-specific live-runtime evidence as separate claims.
</Note>

## Before you start

Prepare these outside StackKits:

- an already-available host you are authorized to operate
- a domain and DNS records you control
- a host and network posture appropriate for public services

StackKits validates and applies its own system definition to that host. It does not provision a server, select a provider, or keep provider credentials.

## Start a Cloud Kit

Bootstrap the released workspace on Linux or macOS. The Cloud installer
supports the same three guided modes (`auto`, `guided`, `expert`) via
`STACKKIT_INSTALL_MODE`. Non-TTY runs always use `auto`:

```bash
# auto: defaults everywhere, straight to a running Cloud homelab
curl -sSL https://cloud.stackkit.cc | DOMAIN=example.com sh

# guided: workspace, admin email, owner, one apply confirmation
STACKKIT_INSTALL_MODE=guided \
DOMAIN=example.com \
CLOUDFLARE_API_TOKEN=... \
CLOUDFLARE_EMAIL=you@example.com \
curl -sSL https://cloud.stackkit.cc | sh

cd ~/my-cloud-homelab
```

Cloudflare DNS credentials for a custom public domain stay
environment-driven (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_EMAIL`). To target an
existing external PaaS, set the `STACKKIT_PLATFORM_*` /
`COOLIFY_*` / `KOMODO_*` overrides.

Or initialize it with an already installed CLI:

```bash
mkdir my-cloud-stack
cd my-cloud-stack

stackkit init cloud-kit \
  --domain example.com \
  --owner-source=local \
  --platform=coolify \
  --use-case=photos,files,vault
stackkit validate
stackkit generate
stackkit plan --json
stackkit apply
stackkit verify --http --json
```

Use a domain you own in place of `example.com`. Keep the StackSpec and verification output with the workspace, and change only the StackSpec before regenerating artifacts. The `--use-case`, `--platform`, and `--enable` flags mirror the guided/expert selections and let you script the same authoring choices.
