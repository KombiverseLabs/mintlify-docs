Cloud Kit is included in the current public release. It uses the same standalone authoring lifecycle as Basement Kit, but is intended for one existing cloud host with public DNS and TLS under your control.

<Note>
  The release includes the Cloud Kit definition and installer. Treat configuration bootstrap and release-specific live-runtime evidence as separate claims.
</Note>

## Before you start

Prepare these outside StackKits:

- an already-available host you are authorized to operate
- a domain and DNS records you control
- a host and network posture appropriate for public services

StackKits validates and applies its own system definition to that host. It does not provision a server, select a provider, or keep provider credentials.

## Start a Cloud Kit

Bootstrap the released workspace on Linux or macOS:

```bash
curl -sSL https://cloud.stackkit.cc | DOMAIN=example.com sh
cd ~/my-cloud-homelab
```

Or initialize it with an already installed CLI:

```bash
mkdir my-cloud-stack
cd my-cloud-stack

stackkit init cloud-kit --domain example.com --owner-source=local
stackkit validate
stackkit generate
stackkit plan --json
stackkit apply
stackkit verify --http --json
```

Use a domain you own in place of `example.com`. Keep the StackSpec and verification output with the workspace, and change only the StackSpec before regenerating artifacts.

Re-running the Cloud installer on a workspace that already carries deployment intent skips initialization and resumes `stackkit apply` from the apply journal instead of failing.

## Compute sizing

Native `stackkit/v2alpha2` sizes each selected module with an explicit `--module-compute-profile`; undeclared profiles fail closed. On the legacy `stackkit/v2alpha1` adapter, Cloud Kit declares only the `standard` and `high` kit-wide tier graphs. It does not declare `low`, so `--api-version stackkit/v2alpha1 --compute-tier low` fails closed at init and compile. Legacy `high` adds the `telemetry-collection` capability to the `standard` graph:

```bash
stackkit init cloud-kit --domain example.com --owner-source=local \
  --api-version stackkit/v2alpha1 --compute-tier high
```

Before Apply changes the host, the compiler attests the local CPU, RAM, and disk inventory against the selected profiles' capacity floors. Missing facts block Apply with `inventory-fact-unverified`; an undersized host blocks it with `runtime-capacity-unsatisfied`. See [Compute sizing on Basement Kit](/stackkits/kits/basement-kit#compute-sizing) for the profile model.
