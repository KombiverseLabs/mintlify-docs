Cloud Kit is included in the current public release (v0.35.x) as a preview. No automated lifecycle run covers a public VPS yet, so [OS compatibility](/stackkits/reference/os-compatibility) lists it as `unverified`. It uses the same standalone authoring lifecycle as Basement Kit, but is intended for one existing cloud host with public DNS and TLS under your control.

<Note>
  The release includes the Cloud Kit definition and installer. Treat configuration bootstrap and release-specific live-runtime evidence as separate claims.
</Note>

## In plain words

Cloud Kit is for a server that you rent and already operate, such as a virtual private server, and that you want to reach by a name under your own domain. It is the right kit when your homelab should live on that server instead of on a computer at home. If you have never set up a server, read [Before you start](/guides/stackkits/before-you-start) first; the Basement Kit is the gentler start.

## Before you start

Prepare these outside StackKits:

- an already-available host you are authorized to operate
- a domain and DNS records you control
- a host and network posture appropriate for public services

What you need first, in short:

1. Command-line access to the host, with permission to run the installer.
2. The domain name, and access to its DNS settings.
3. A decision about which ports and services may be reachable from the internet.
4. A private place for the access details that setup creates.

StackKits validates and applies its own system definition to that host. It does not provision a server, select a provider, or keep provider credentials.

## Start a Cloud Kit

Bootstrap the released workspace on Linux or macOS:

```bash
curl -sSL https://cloud.stackkit.cc | DOMAIN=example.com sh
cd ~/my-cloud-homelab
```

Use a domain you own in place of `example.com`. Keep the StackSpec and verification output with the workspace, and change only the StackSpec before regenerating artifacts.

After each part you should see the following:

1. The command creates the workspace folder `~/my-cloud-homelab` and puts you in it.
2. The StackSpec in that folder names your domain. Review it before you change the host.
3. Verification output tells you whether the rollout matches the plan. Use the same steps as in the [CLI walkthrough](/guides/stackkits/cli-walkthrough) and [Review a plan and apply](/guides/stackkits/review-plan-and-apply).
4. Open the Node Hub address from the output and finish protection as described in the [Node Hub guide](/guides/stackkits/node-hub).

If you already have the CLI, [choose a kit](/guides/stackkits/choosing-a-kit) and [configure the StackSpec](/guides/stackkits/configure-stack-spec).

## What is stored where

The configuration (StackSpec), verification output and access details stay in the workspace folder on your host, so keep that folder private. Your domain and DNS records stay with you and your provider, and StackKits does not keep provider credentials. Plan backups with [Back up and restore](/guides/stackkits/back-up-and-restore).

## If something goes wrong

- A name does not open: check that the DNS records for your domain point to the host, then compare the address with the one in the Node Hub. See [Troubleshooting](/guides/stackkits/troubleshooting).
- The installer stops with an error: read the log with `stackkit logs latest --json`, and check [OS compatibility](/stackkits/reference/os-compatibility) for your host. Remember that Cloud Kit is a preview.
- For everyday use after setup, see [Day to day](/guides/stackkits/daily-use).
