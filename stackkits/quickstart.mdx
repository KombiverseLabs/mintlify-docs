The fastest StackKits path is the Install Engine: one short command on the host that should become your homelab. If you want more control, install the CLI only and run the steps yourself.

## Fastest path

Run the Basement Kit one-liner on a Linux or macOS host with root/sudo access. Without a version pin, this installs the current stable latest release (`v0.5.0`):

```bash
curl -sSL https://base.stackkit.cc | sh
```

This installs the `stackkit` CLI, installs the Basement Kit definitions, prepares Docker and OpenTofu, initializes the stack, generates deployment artifacts, applies the stack, and prints the service URLs.

## Pinned beta path

Use a pinned prerelease when you are testing the current beta (`v0.5.1-beta.2`):

```bash
export STACKKIT_RELEASE_VERSION=v0.5.1-beta.2
curl -sSL https://base.stackkit.cc | sh
```

Prerelease pins are explicit by design. Unpinned installers stay on stable latest until the beta evidence and public mirror CI are clean enough for stable promotion.

## Per-kit one-liners

Use a kit-specific one-liner when you already know the StackKit:

```bash
curl -sSL https://base.stackkit.cc | sh      # Basement Kit stable latest
curl -sSL https://cloud.stackkit.cc | sh     # Cloud Kit
```

| StackKit | Use case | Status |
|----------|----------|--------|
| `basement-kit` | Local single-environment homelab | Stable |
| `cloud-kit` | Cloud single-environment on your VPS | Preview, graduating |
| `modern-homelab` | Hybrid local + cloud setup (bridge contract) | Preview / Early Access, via the CLI |

Need failover? [High Availability](https://docs.kombify.io/stackkits/addons/high-availability) is an add-on you layer onto any kit, not a separate kit.

## CLI-only path

Use the CLI-only installer when you want to make the technical choices yourself:

<Steps>
  <Step title="Install the CLI">
    ```bash
    curl -sSL install.stackkit.cc | sh
    ```
  </Step>

  <Step title="Initialize a StackKit">
    ```bash
    mkdir my-homelab
    cd my-homelab
    stackkit init basement-kit
    ```

    <Note>
      `stackkit init base-kit` still works as a deprecated alias — it resolves to `basement-kit` and prints a deprecation warning. Use `basement-kit` in new specs and scripts.
    </Note>
  </Step>

  <Step title="Prepare and generate">
    ```bash
    stackkit prepare
    stackkit generate
    ```
  </Step>

  <Step title="Preview and apply">
    ```bash
    stackkit plan
    stackkit apply
    ```
  </Step>

  <Step title="Check status">
    ```bash
    stackkit status
    ```
  </Step>
</Steps>

## What you get

The Basement Kit default provisions a homelab foundation with StackKits standards, add-ons, baselines, auth/routing defaults, generated infrastructure artifacts, and a service URL summary.
