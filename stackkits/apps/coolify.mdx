Coolify is an optional application platform integration and a supported workload adapter for the Files, Photos, and Vault contracts. Since v0.24.63, the default Basement and Cloud core does not install Coolify. Enable it with an explicit workload selection; existing explicit Coolify selections keep their authority.

| Role | Current release behavior |
| --- | --- |
| Core platform | Not installed by the default core since v0.24.63; requires explicit selection |
| Workload adapter | Supported for `files`, `photos`, and `vault` |
| Route and TLS evidence | Supported |
| Workload backup and restore | Not supplied by the Coolify adapter |

Coolify consumes the same workload, identity, routing, data, and evidence contracts as the standalone Compose default. It adds only its platform-specific bootstrap and execution behavior. Each workload has exactly one execution owner and one routing owner, so an installed Coolify must not also manage a workload assigned to standalone Compose.

## Use it safely

1. Select the `coolify` adapter explicitly in the workload intent; the default for new selections is `standalone-compose`.
2. Complete and verify the StackKits rollout before opening the application platform.
3. Open the generated Coolify URL from the Node Hub or the StackKits output.
4. Use one application delivery path per workload; do not create competing generated routes by hand.
5. Keep application credentials and recovery material under the local owner's control.
6. Use the StackKits backup path only where the selected adapter declares backup-and-restore support.

## Verify

- The generated Coolify route opens at the address reported by the rollout.
- StackKits verification reports the application platform and its configured routes as healthy.
- The StackKits workspace remains the source of configuration intent.

For the beta alternative, see [Komodo](/stackkits/apps/komodo). For the complete adapter matrix, see [Application delivery](/guides/stackkits/application-delivery).
