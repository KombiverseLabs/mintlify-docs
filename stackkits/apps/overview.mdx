This catalog separates what the native v0.16.0 StackSpec selects today from additional module contracts that merely ship in the release. A file in the release archive is not proof that the initial StackSpec enables it.

## Current core runtime

- [PocketID](/stackkits/apps/pocketid) — local owner identity
- [TinyAuth](/stackkits/apps/tinyauth) — forward-auth entrypoint
- [Traefik](/stackkits/apps/traefik) — routing implementation in the generated core
- [Coolify](/stackkits/apps/coolify) — selected-provider platform in the current core

## Optional native v2 workloads

- [Cloudreve](/stackkits/apps/cloudreve) — released `files` alternative
- [Immich](/stackkits/apps/immich) — released `photos` alternative
- [Vaultwarden](/stackkits/apps/vaultwarden) — released `vault` alternative

None of these workloads is enabled by the initial Basement or Cloud StackSpec. Files has a validated public configuration example. Photos and Vault require owner-bound secret custody for which v0.16.0 has no safe public post-init authoring command.

## Additional released module contracts

- [Komodo](/stackkits/apps/komodo) — beta workload adapter
- [Homepage](/stackkits/apps/homepage), [Uptime Kuma](/stackkits/apps/uptime-kuma), [Whoami](/stackkits/apps/whoami), and [Dozzle](/stackkits/apps/dozzle) — visibility modules not selected by the initial native v2 StackSpec
- [kombify Point DNS](/stackkits/apps/kombify-point) — local DNS module without a current public native v2 how-to
- [Jellyfin](/stackkits/apps/jellyfin) — media module without a current native v2 workload selector

Use `stackkit app compatibility --json` for the workload adapter matrix. Do not edit generated deployment files or infer enablement from archive presence.
