Immich is the released alternative for the optional native v2 `photos` workload. The initial Basement and Cloud StackSpecs do not enable it.

## Released contract

| Property | Value |
| --- | --- |
| Workload | `photos` |
| Alternative | `immich` |
| Data class | personal |
| Required secret reference | `database-password` |
| Supported standalone adapter | `standalone-compose` |

The released CLI validates and generates this workload contract, including persistent photo and database allocations and a generated Photos route. See the [use-case catalog](/guides/stackkits/use-cases/overview) for the catalog-declared release scope.

The `database-password` slot holds an opaque `secret://` reference; local owner custody holds its password. Choose the workload, placement and adapter in the [StackSpec](/guides/stackkits/configure-stack-spec), then follow [Add a workload](/stackkits/reference/day-2-operations#add-a-workload-to-an-existing-workspace) to validate, establish custody, generate, inspect the plan, apply and verify.

## First use

1. Complete StackKits verification after a rollout that already has valid owner-bound custody.
2. Open the generated Immich address from the Node Hub or rollout output.
3. Create the application owner account and connect clients only after you have confirmed storage capacity and backups.

Photo libraries grow quickly. Keep the storage and backup responsibility with the host you operate, confirm that recovery covers both the originals and the database volumes, and verify the StackKits workspace after any configuration change.

See [Family Photo Vault](/guides/stackkits/use-cases/family-photo-vault) for storage, recovery, and current-release planning guidance.
