Immich provides the [Photos](/guides/stackkits/use-cases/photos) use case. It is the released alternative for the optional native v2 `photos` workload, and the initial Basement and Cloud StackSpecs do not enable it. Plan storage and recovery on the Photos page before you select it.

## What it is

Immich is a photo and video library that runs on your own host. It does what a cloud photo service does: the phone app uploads new pictures, and you browse, search and share them in a web library. A StackKit includes it so your family's photos stay on hardware you control.

## Which kits and use cases include it

When you choose the optional Photos use case, Immich is its default alternative. The released catalog commits it for the Basement Kit and the Cloud Kit on standalone Compose; the Cloud Kit has partial lifecycle evidence, while its complete public-VPS bootstrap remains pending. Coolify and Komodo also declare Photos backup and restore, but their lifecycle rows are not tested. See [Application delivery compatibility](/stackkits/reference/application-delivery-compatibility) for the distinction between declarations and executed evidence.

## Released contract

| Property | Value |
| --- | --- |
| Workload | `photos` |
| Alternative | `immich` |
| Data class | personal |
| Required secret reference | `database-password` |
| Supported standalone adapter | `standalone-compose` |

The released CLI validates and generates this workload contract, including persistent photo and database allocations and a generated Photos route. The [use-case catalog](/stackkits/reference/use-case-catalog) shows the components the release declares.

The `database-password` slot holds an opaque `secret://` reference; local owner custody holds its password. Choose the workload, placement and adapter in the [StackSpec](/guides/stackkits/configure-stack-spec), then follow [Add a workload](/stackkits/reference/day-2-operations#add-a-workload-to-an-existing-workspace) to validate, establish custody, generate, inspect the plan, apply and verify.

## How to open it

Open the generated Photos route printed by the CLI or listed in the [Node Hub](/guides/stackkits/node-hub). The default local domain is `home.test`, and the name must resolve on your device. The same address is what the phone app asks for as its server address.

## First use

1. Complete StackKits verification after a rollout that already has valid owner-bound custody.
2. Open the generated Immich address from the Node Hub or rollout output.
3. Create the application owner account and connect clients only after you have confirmed storage capacity and backups.
4. Connect each phone with [Back up photos from your phone](/guides/stackkits/use-cases/photos/phone-backup).

Verify the StackKits workspace again after any configuration change.

## What is backed up

Recovery needs both the original photos and videos and the Immich database; either part alone is not a complete restore. Photo originals belong to the `media` coverage group, which is chosen, not inherited, so a first snapshot will not quietly include a large library. Run `stackkit backup status --json` to see exactly which volumes the next snapshot contains, and practice a staged restore with [Back up and restore](/guides/stackkits/back-up-and-restore). The [v0.39.7 published compatibility record](https://github.com/kombifyio/StackKits/releases/download/v0.39.7/stackkits-compatibility-evidence-v3.json) records passing Photos backup and restore phases. The [latest projected record, v0.53.10](https://github.com/kombifyio/StackKits/releases/download/v0.53.10/stackkits-compatibility-evidence-v3.json), grades standalone Photos `preview` with `restore-failed`; its last fully verified release is v0.46.8. Neither the historical phase result nor the v0.54.2 backup declaration proves a working restore on the current release.

## What to expect

Photo libraries are often the largest data set in a homelab and keep growing, so size primary and backup storage for photo and video growth. The first upload from a phone can take a while on a large album; a small test album with one spare photo is enough for a first check.

## If something goes wrong

- The address does not open: compare it with the rollout output and confirm that the name resolves from the device. See [Troubleshooting](/guides/stackkits/troubleshooting).
- The phone cannot sign in: use the Immich account you created in the web library; it is not your kombify account.
- A test photo does not arrive: check the chosen album and the app's photo access, then follow [Back up photos from your phone](/guides/stackkits/use-cases/photos/phone-backup).
- Storage fills up: stop adding photos and fix capacity before the next snapshot.
