StackKits sets up a secured, backed-up homelab at home or in the cloud and keeps the whole setup as one blueprint you can read, keep and take anywhere. One command on a computer you already have gets you there; the [quickstart](/stackkits/quickstart) shows it.

StackKits works against a host you already control; it does not require a kombify account or a hosted kombify endpoint.

## The address zone you get

The zone follows the host you install on, so there is no domain to choose
before you start:

| Where you install | Zone the installer selects | What it means |
| --- | --- | --- |
| A home server or mini PC | `*.lab.home` | A private home zone for devices on your own network. The kit runs standalone, with no kombify account. |
| A public VPS or cloud host | `*.kombify.me` | The public zone, because private home addresses are not reachable from a public server. |

A public host needs a reachable origin and an account before it actually serves
public names. `stackkit connect` binds the server to your kombify account; from
then on your apps get `{base}-{app}.kombify.me` names, and you decide per app
whether it stays home-only or is reachable from the internet.

<Note>
  kombify.me is Beta software. Names, headers and error shapes can still
  change, so do not treat it as a general-availability release.
</Note>

See [kombify.me](/kombify-me/overview) for how public names and private relays
work.

## Release-specific documentation

Check the [use-case catalog](/stackkits/reference/use-case-catalog), [OS compatibility](/stackkits/reference/os-compatibility), and [application delivery compatibility](/stackkits/reference/application-delivery-compatibility) for listed components and declared compatibility. Each reference identifies and links the published release it describes. OS compatibility and the Lifecycle test column of application delivery compatibility come from automated lifecycle runs of that release on fresh virtual machines: install, init, generate, apply, verify, backup and restore. The use-case catalog and the declared adapter capabilities are not evidence of deployment or verification on a real host.

Guides and examples that name a version describe that version. Do not assume an older example has been verified against a newer release.

Modern Homelab ships in every release as an alpha definition archive for authoring and validation; it is not an install path.

Choose the kit by the environment you control, not by the number of services you want to run.

The first successful standalone path is on the [Quickstart](/stackkits/quickstart).

## What StackKits does not do

- create or buy a server for you
- hold provider credentials or manage provider resources
- require a hosted control plane for Standard Mode
- replace the local owner and evidence produced by the standalone lifecycle
