StackKits is the standalone, open homelab standard. It provides portable kit definitions, the `stackkit` CLI and MCP connector, and a local lifecycle for validating, generating, applying, and verifying a stack.

StackKits works against a host you already control; it does not require a kombify account or a hosted kombify endpoint.

## Release-specific documentation

The [use-case catalog](/guides/stackkits/use-cases/overview), [OS compatibility](/stackkits/reference/os-compatibility), and [application delivery compatibility](/stackkits/reference/application-delivery-compatibility) references each identify and link the published release they describe. Use that release information when checking available components and declared compatibility; it is not evidence that your host has been deployed or verified.

Guides and examples that name a version describe that version. Do not assume an older example has been verified against a newer release.

Choose the kit by the environment you control, not by the number of services you want to run.

The first successful standalone path is on the [Quickstart](/stackkits/quickstart).

## What StackKits does not do

- create or buy a server for you
- hold provider credentials or manage provider resources
- require a hosted control plane for Standard Mode
- replace the local owner and evidence produced by the standalone lifecycle
